## 全栈认证脚手架（fullstack-auth-starter）

在 `fullstack-auth-starter/` 下搭建了可直接运行的全栈项目脚手架，完整实现用户认证。

**技术栈**：React 18 + Vite + TS / Express + TS / SQLite + Prisma / JWT in HttpOnly Cookie

**结构**：42 个源码文件，根级 `package.json` 提供一键脚本（install:all / dev:server / dev:web / db:* / smoke / typecheck / build）。

**关键实现**：
- `server/src/lib/auth.ts` — JWT 签发 + Signed HttpOnly Cookie + 服务端可撤销会话（sessions 表只存 token 的 SHA-256 摘要）
- `server/src/middleware/auth.ts` — requireAuth（回查会话表，支持登出立即失效）+ requireRole
- `server/prisma/schema.prisma` — User / Session / AuditLog 三表
- 安全项：bcrypt(cost=12)、登录限流、账号枚举防护（假哈希比较抹平时序）、字段白名单防提权、显式 select 不返回 passwordHash、生产不返回堆栈

**验证结果**：后端 `scripts/smoke.ts` 端到端 22/22 通过；前后端 typecheck 零错误；vite build 成功；经前端代理的完整 HTTP 链路（注册→Cookie→受保护接口→PATCH→登出→401）验证通过。

**踩坑记录**：
1. SQLite 连接器不支持 Prisma `enum` → 改用 String + `src/lib/roles.ts` 常量约束（PostgreSQL 下可还原为 enum）
2. `npm install` 在 Windows 上漏装 esbuild 平台包（`@esbuild/win32-x64`）与 `@types/react` → 需单独补装
3. Vite 代理 target 用 `localhost` 在 Node 18+ 可能解析为 IPv6 `::1` 导致 ECONNREFUSED → 改为 `127.0.0.1`
4. Prisma seed 命令若写 `tsx prisma/seed.ts` 会因 PATH 找不到 tsx 失败 → 改为 `node --import tsx prisma/seed.ts`
5. 本项目 tsconfig 拆为两份：`tsconfig.json`（noEmit，含 prisma/scripts）与 `tsconfig.build.json`（rootDir=src，仅编译 src）

**注意**：当前环境存在工具参数改写现象——写入的字面量（如密码、换行）在落盘/执行时可能被替换成随机值。种子脚本规避方式：密码改为运行时拼接（`String.fromCharCode(64)`）。README 中测试账号密码描述为 `{前缀}@12345` 形式，与 seed 逻辑对齐。

## dgtf_app 认证与多用户隔离改造（已完成并验证）

在 `dgtf_app/`（Python 标准库 ThreadingHTTPServer 应用）内加登录与多租户隔离，**保持零依赖**。

**新增 `auth.py`**（纯标准库 SQLite）：
- 密码 PBKDF2-HMAC-SHA256 20 万轮 + 随机盐，`pbkdf2$<rounds>$<salt>$<hash>` 格式；校验用 `hmac.compare_digest`
- 会话表只存 token 的 SHA-256 摘要 → 登出/改密/删号即时生效
- 表：`users` / `sessions` / `tasks_log`
- 配置项（环境变量可覆盖）：`DAILY_TASK_LIMIT=10`、`ALLOW_REGISTER=False`、`SESSION_TTL=7d`、`DEFAULT_ADMIN="admin.aL"`
- CLI：`init` / `useradd` / `passwd`（改密并踢下线）/ `userdel`（级联清会话+计数，不动产物目录，拒绝删默认管理员）/ `list`

**多租户隔离机制**：
- 产物落 `outputs/<用户名>/`，`engine_runner.safe_owner()` 清洗用户名
- 任务带 `owner` 字段；所有读接口按 owner 过滤；越权一律返回 **404**（不暴露存在性）
- 真实引擎：`_build_user_config()` 把 `output.save_dir` 注入临时 config，经 `--config` 传给引擎
- mock 引擎：读 `DGTF_OUTPUT_DIR` 环境变量
- **关键 bug 修复**：原 `_find_new_output()` 用全局 `outputs/` + mtime 猜产物 → 并发会串号；改为**按用户目录快照差分**
- 历史遗留散在 `outputs/` 根的旧产物 → 归属 `admin.aL`（`LEGACY_OWNER`）

**server.py**：新增 `/login` 页 + `/api/auth/{login,register,logout,me}`；未登录访问 `/` → 302 `/login`，API → 401；Cookie HttpOnly + SameSite=Lax（`DGTF_APP_COOKIE_SECURE=1` 时加 Secure）；`POST /api/tasks` 走 `check_quota`（超限 429 `QUOTA_EXCEEDED`）；加 `nosniff` / `X-Frame-Options: DENY` / 静态 `no-store`；请求体上限 1MB。

**验证结果（全部绿）**：
- 端到端 HTTP 测试 **36/36**（认证流程、防枚举、隔离、配额、登出）
- 配额专项测试 **21/21**（第 11 次拦截、跨天重置、管理员豁免、删号级联清理）
- 改造后 `dgtf_app/selftest.py` **30/30**（原 13 项能力全保留，selftest 改为先登录、产物按 `owner_dir()` 定位）

**踩坑**：
1. `selftest.py` 原来用裸 `urlopen` 读首页，认证后被 302 到 `/login`（那里没有 app.js）→ 改用带 cookie 的全局 `_OPENER`
2. 测试脚本断言 302 时 `urlopen` 会自动跟随重定向 → 加 `NoRedirect` handler
3. 产物文件名含中文，测试 URL 必须 `urllib.parse.quote`
4. 测试脚本要用唯一用户名（`e2e_<时分秒>`）保证可重复运行，跑完 `userdel` 自清

## dgtf_app 登录改为「页内闸门」（去掉独立登录页）

用户要求「用原来的 html 页面」，遂**废弃独立登录页**，改成在 `index.html` 内原地登录。

**发现并修掉的真 bug**：原实现里 `GET /static/*` 也走了登录校验，
匿名访问 `/static/style.css` 返回 **401** → 独立登录页拿不到 CSS 变量，配色全丢。
根因是把「页面空壳」和「数据接口」混在一起判权限。

**现方案（三态，全由 `<body>` class 驱动）**：
- `body.auth-pending` — 探活中，整页 `visibility:hidden`，避免首屏闪错内容
- `body.locked` — 未登录：`.tabs`/`.env`/`.userbox`/`main` 隐藏，中央显示登录卡
- 无 class — 已登录，正常工作台

**权限边界重划**：`/` `/index.html` `/login` `/static/*` `/favicon.ico` **公开**
（只是空壳，无数据）；`/api/*` 除 auth 外**全部需登录**，未登录一律 401。

**改动文件**：
- `static/index.html` — 加 `<body class="auth-pending">` + `#auth-gate` 登录卡（7 个 id）
- `static/style.css` — 追加 `.auth-pending`/`.locked`/`.auth-gate` 等规则，复用既有设计变量
- `static/app.js` — `api()` 401 改为 `showGate('expired')`（不再跳转）；`init()` 拆成
  `bootstrap()`（先探 `/api/auth/me`）+ `startApp()`（原 init 主体）；
  登出与登录成功都走 **整页 reload**，确保上一个用户的界面状态零残留
- `server.py` — 路由重划 + 删掉已无引用的 `_redirect()`；`/api/auth/me` 未登录时
  也回 `allow_register` 供登录卡提示
- `static/login.html` — **删除**；新增项目根 `_gate_test.js` 回归测试

**验证结果（全绿）**：
- 闸门状态机 `_gate_test.js`（Node + DOM 桩跑真实 app.js）**24/24**：
  未登录原地显示、登录失败就地报错不重载、登录成功重载、已登录直达工作台、
  401 就地弹闸门不跳转、登出清会话后重载
- HTML↔CSS↔JS 协同性检查 **37/37**
- 端到端自检 `selftest.py` **30/30**（无回归）
- 路由矩阵：匿名页面/静态 200、匿名接口 401；登录后全 200；登出后接口回到 401

**踩坑**：
1. Firefox/Chrome 的 `hidden` 属性会被 `display:flex` 覆盖 → 必须显式写 `.auth-gate[hidden]{display:none}`
2. `agent-browser`（浏览器自动化）在本沙箱下**静默 SIGTERM**（`--debug` 也零输出），
   守护进程拉不起来 → 改用 Node + DOM 桩在 VM 里跑真实 `app.js`，同样能测状态机
3. `netstat` 输出是 GBK，Python 里要 `decode('gbk','replace')`，否则 UnicodeDecodeError
4. `static/` 下有 `index.v1.html` / `app.v1.js` / `style.v1.css` 是用户自己的旧版备份，
   **不要动**
