再想一层：真正的判据是什么？

"可观测锚点"的实质是：**这个回访条件能被检查是否满足**。检查需要：
1. 一个可被引用的对象或状态
2. 一个可被观察的变化（出现/达到/满足/变化）

所以白名单可以设计成两类 pattern：
- 时间/触发词 + 任何具体内容：`(当|若|如果|一旦|在).{1,40}(时|后|前|了)` 或者更宽：`(当|若|如果|一旦|在).{1,40}`
- 状态变化动词：`(出现|完成|解决|得到|满足|达到|超过|变化|更新|补充|积累|形成|产生|暴露|显形|给出|确认|推翻|失效|成立|失败)`
- 引用对象：`[TPSCd]_?\d+|ing|覆盖率|距离|权重|圈|层`

任何一条命中就 pass。

但这样会不会太宽？其实 P1-6 的初衷是"必须有可观测锚点"——如果这三类任一都没命中，那确实大概率是空词或者模糊词。所以只要宽度合适，就 OK。

## 一、背景与目标

v1.21.62 的 P1-6 补丁做了两件事：给 `revisit_condition` 加白名单，让"必须有可观测锚点"。**结果是灾难性的**——编码助手实测全库 1213 条真实条件，**只放行 24 条（2.0%），拦下 1189 条（98.0%）**，其中大量是明显合法的（"T2探针给出边界判据后"、"谓词类型区分完成后"、"相对化屏障被形式化后"）。

更严重的是：被拦下的 deferral 只 `stats["invalid"] += 1` 然后 `continue`，**不进 vp、不进产物、不进池**——98% 的账在用户完全不知情的情况下消失，**直接违反宪法级"失败必须留痕"**。

本提示词做三件事：
1. 把白名单从"少数句式"改成"**三类宽特征任命中其一即放行**"（召回优先）
2. **被拦下的 deferral 必须留痕**（进 `view.errors` + `pool.meta`，产物里可见）
3. 同步更新冒烟断言与 changelog

**总原则**：**宁可放过模糊的，也不能拦住合法的**。判据失败的代价是"账消失"，比"放过一个模糊条件"严重得多。

## 二、改动 1 · 白名单扩充

**位置**：`_BAD_REVISIT` 及其下方的 `_REVISIT_ANCHOR_PATTERNS` / `_valid_revisit`。

**查找**（这段是 v1.21.62 引入的）：

```python
_BAD_REVISIT = ("以后", "适当时机", "待定", "稍后", "再说", "看情况")

# [v1.21.62 P1-6] 白名单：revisit_condition 必须含**可观测锚点**
#   —— 说得出一个具体的事件、观察、或状态变化。
#   黑名单只挡"以后"这类空词，挡不住"当有新材料时"——那也无法判断
#   它是否发生，等于没写。
_REVISIT_ANCHOR_PATTERNS = (
    r"当.{1,30}(出现|发生|完成|解决|给出|成立|失败|超过|达到)",
    r"若.{1,30}(出现|发生|完成|解决|给出|成立|失败|超过|达到)",
    r"第\s*\d+\s*圈后",
    r"覆盖率.{0,10}(超过|达到|>|≥)",
    r"有.{1,20}证据(时|后)",
    r"[A-Za-z0-9]{2,}\s*(出现|变为|大于|小于|达到)",
)


def _valid_revisit(cond: str) -> bool:
    c = (cond or "").strip()
    if len(c) < 4:
        return False
    if any(b in c for b in _BAD_REVISIT):
        return False
    # [v1.21.62 P1-6] 必须有可观测锚点
    if not any(re.search(p, c) for p in _REVISIT_ANCHOR_PATTERNS):
        return False
    return True
```

**替换为**：

```python
_BAD_REVISIT = ("以后", "适当时机", "待定", "稍后", "再说", "看情况")

# [v1.21.62 P1-6 修] 白名单：revisit_condition 必须含**可观测锚点**。
#
# ★ 为什么改：v1.21.62 初版只有 6 条 pattern（全是"当X动词"一族句式），
#   实测 1213 条真实条件只放行 2%，98% 被静默吞掉。被拦下的多是明显
#   合法的可观测锚点（"T2探针给出边界判据后"、"谓词类型区分完成后"、
#   "相对化屏障被形式化后"）。**判据太窄，反而制造了数据丢失**。
#
# ★ 修法：从"少数句式"改成**三类宽特征**，任命中其一即放行：
#   ① 时间/条件词：当/若/如果/一旦/在…时（后/前）/…之后/第N圈/…后
#   ② 状态变化动词：出现/完成/解决/给出/成立/变化/更新/…（约 30 个）
#   ③ 引用对象：T#/P#/S#/C#/d_###/ing/覆盖率/距离/权重
#   再加一层兜底：长度 ≥ 10 字且不含黑名单词 → 视为有具体描述。
#
# ★ 判据顺序：**先黑名单排除，再白名单放行**。黑名单挡"以后"这类纯空词，
#   白名单 + 兜底保证合法条件不被误杀。**召回优先，不追求精确率**。
#
# ★ 保持的原则：不允许"完全说不出什么时候回来"（即纯空词被拦）。
_REVISIT_TIME_HINT = re.compile(
    r"(当|若|如果|一旦|在)[^。]{0,60}(时|后|前|了|的话)"
    r"|第\s*\d+\s*圈"
    r"|[^，。]{2,40}(之后|之前|以后)"
    r"|(下|本|上)\s*\d*\s*圈"
    # 兜底时间尾：含"后/时/前"结尾的短语（"形式化后"、"完成后"等）
    # 前面要求 ≥3 字，避免单字"时/后/前"被误匹配
    r"|[^，。]{3,40}(后|时|前)"
)

_REVISIT_CHANGE_VERB = re.compile(
    r"(出现|发生|完成|解决|给出|成立|失败|超过|达到|变化|更新|"
    r"补充|积累|形成|产生|暴露|显形|确认|推翻|失效|回答|清偿|"
    r"触发|发现|浮现|新增|消失|启动|落地|稳定|支持|反对|通过|"
    r"披露|揭示|证实|证伪|澄清|定位|锁定)"
)

_REVISIT_CITATION = re.compile(
    r"[TPSCd]_?\d+"
    r"|\bing\b"
    r"|覆盖率"
    r"|距离"
    r"|权重"
)


def _valid_revisit(cond: str) -> bool:
    """检查 revisit_condition 是否含**可观测锚点**。

    ★ v1.21.62 P1-6 修：判据放宽成"三类宽特征任一命中即通过" +
      "长度 ≥ 10 且不含黑名单词"兜底。**召回优先**——拦错了代价是
      "账消失"，放过一个模糊条件只是"多挂一笔不太精确的账"。
    """
    c = (cond or "").strip()
    if len(c) < 4:
        return False
    # 黑名单优先：纯空词一律拦
    if any(b in c for b in _BAD_REVISIT):
        return False
    # 三类宽特征任一命中即通过
    if (_REVISIT_TIME_HINT.search(c)
            or _REVISIT_CHANGE_VERB.search(c)
            or _REVISIT_CITATION.search(c)):
        return True
    # 兜底：长度 ≥ 10 字且不含黑名单词 → 视为有具体描述
    if len(c) >= 10:
        return True
    return False
```

## 四、改动 3 · 冒烟断言同步

```
  1189 条被拦下。被拦下的多是明显合法的（"T2探针给出边界判据后"、
  "谓词类型区分完成后"、"相对化屏障被形式化后"）。
  更严重的是被拦下的 deferral 只 `stats["invalid"] += 1` 然后 continue，
  **不进 vp、不进产物、不进池**——98% 的账在用户不知情下消失，
  违反宪法级"失败必须留痕"。

  **修法**（两处）：
  1. **白名单扩充成三类宽特征**（召回优先）：①时间/条件词；②状态变化
     动词；③引用对象（T#/P#/S#/C#/d_###/ing/覆盖率/距离/权重）。
     再加一层兜底：长度 ≥ 10 且不含黑名单词 → 视为有具体描述。
     判据顺序：**先黑名单排除，再白名单放行**。目标召回 ≥ 90%。
  2. **被拦下的必须留痕**：进 `view.errors`（产物【失败记录】段）
     + `pool.meta`（池段），限流 20 条防刷屏；超过 20 条时写一条汇总。

  **验证**：冒烟新增 11 条边界断言（纯空词拦 / 各类合法条件通过 /
  长度兜底通过 / 长度不足拦）；新旧白名单对照跑 1213 条真实条件，
  放行率应 ≥ 90%。
```

---

## 七、一句话

> **P1-6 的初版是"想精确，结果丢数据"。修法是把判据反过来**——**黑名单严、白名单宽、兜底宽松、失败必留痕**。目标不是"精确判断什么算可观测锚点"，是"**确保 90%+ 的合法条件不被误杀，且被拦的一定能在产物里看到**"。
