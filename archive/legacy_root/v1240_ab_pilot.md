# V1.24.0 · V2 接管 vs V1 自动排程 A/B（600k 预算 pilot）

## 协议

- 同一题、同一模型/配置（all_on=false、shape=8、effort=low、max_tokens=600000、serial）；
- V1：scheduler.v2.enabled=true / takeover=false，V1 自动排程；
- V2：scheduler.v2.enabled=true / takeover=true，V2 初始串行排程；
- 每对同题先后/并发错开 3 秒，避免产物同名；无人工挑题。
- 质量用 bench/bench_score.py（practice/research/decision/boundary）+ packed quality。

## 汇总（Q1–Q5）

- 完成率：V2 5/5；V1 0/5（全部在 600k 内没跑完 all；Q3/Q4 连 both 都没跑完）。
- calls：V2 均值 85.0；V1 均值 111.8；V2 −24.0%。
- tokens：V2 均值 531.1k；V1 均值 632.4k；V2 −16.0%。
- 研究覆盖：V2 100 / 100 / 100 / 100 / 50（均值 90%）；V1 80 / 50 / 100 / 100 / 100（均值 86%）。
- 三态：V2 .333 / 1.000 / .833 / .500 / .500（均值 .633）；V1 .400 / .333 / .667 / .500 / .333（均值 .447）。
- 决策 rubric：V2 3/3（Q2 边界题 0）；V1 3/3（Q2 0）；动作条数 V2 3–6、V1 4–6。
- V1 五题全部 paused；V2 五题全部闭合。

V2 在 2M 预算下仍在 ~528k 自然停（实际没花满 2M）；V1 到 882k 仍卡在 both，已超过 V2 全闭合成本的 1.67 倍。V1 这一跑被手动停止，**不是完成跑次**，因此不参与上面的质量均值；它只证明“预算不是 V1 的瓶颈，排程才是”。

## 观察

1. V2 的 3/2/2/1 初始排程在 600k 下能把四层都跑完；V1 自动排程把预算更多花在 0/1，导致 both/all 被截断。
2. V2 不是“少花钱少干活”：Q1–Q4 研究覆盖都是 100%（V1 Q1 80%、Q2 50%），决策 rubric 不低；Q5 V2 覆盖 50%，低于 V1 的 100%。
3. Q1 是 V2 三态不占优、覆盖占优：V2 覆盖 5/5、三态 .333；V1 覆盖 4/5、三态 .400。V1 用更多 token 换到略高三态，但覆盖更低且仍未闭合。
4. Q2 是 boundary 题，两侧 decision 都是 0（设计如此），不能拿它判“谁更会做决策”。
5. Q5 是 V2 覆盖不占优的题：V2 只答 1/2，V1 4/4；但 V2 三态更高（.500 vs .333）、且 V2 闭合、V1 仍 paused。

## 局限

- n=5 对，600k pilot 预算，不是 2M 正式跑；不能做统计显著性。
- V2 只接管“初始串行排程”，层内 prompt/算法仍是 V1；Phase 5 未做。
- 并发启动曾撞过一次同题快照；已改为错开 3 秒；Q5 也按此。
- 质量评分器对 boundary 题的 decision=0 是模板口径，不代表边界分析差。

## 结论（pilot）

在这 5 对、600k、serial 的条件下，V2 初始排程**在成本与闭合上占优**：少 24% calls / 16% tokens，五题全闭合；研究覆盖均值 90% 对 86%，三态均值 .633 对 .447。取舍是 Q1 的覆盖/三态与 Q5 的覆盖（V1 更高），但 V1 五题都没闭合。

因此建议：V2 takeover 进入**推荐 preset**（不是主配置默认），用 2M 正式跑再扩样本；Phase 5 层内重写仍需要每层 A/B，不能由这次 pilot 直接放行。
