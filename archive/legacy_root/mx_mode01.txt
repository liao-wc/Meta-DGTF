# ★ 为什么做这一批：batch01 六题全被 auto_plan 选成 A，所以 batch01 的结论
#   **只能限定在 A 模式内**（"A 模式下哪些场景合适"），不能推广到"元DGTF 适

# ★ 模式不是凭空挑的，按 _MODE_GRAPH 的**结构依赖强度**在梯度上取三个点：
#     serial：全串行，每层只吃前一层的完整结果      → 依赖最强
#     H     ：0→1→both 硬闸（跑完才放行），all 软闸 → 依赖强
#     A     ：四层独立并行，互不等待                → 依赖最弱
#   （D/E/F/G/C 留到第二轮补，先坐实「强度梯度本身有没有效」。）
#
# ★ 题也不是凭空挑的，按**题自身的结构依赖**取两个极端（都有评尺清单）：
#     law 出海GDPR合规：条文拆解型，各合规面相对独立，可并行列
#     biz 制造企业自动化投资：决策权衡型，要先摊两面→研究→对撞→拍板，层间吃紧
#
# ★ 预注册假设（跑之前写下，跑完只准照判据说，不准改判据）：
#     H1  law（依赖弱）→ 弱依赖模式不吃亏：A ≥ H ≥ serial
#     H2  biz（依赖强）→ 强依赖模式占优：serial/H > A
#   判据沿用老规矩：组间差 > 组内极差才许断言。
#   ⚠️ 本批每格只有 1 次观测，**没有组内极差** → 结果只能当方向性线索，
#      一条都不许写成结论；要结论就得补重复观测。
