【问题】v1.23.14 报告 §八 四条边界：① 三条规则无数据支撑；② history_limit 的窗口效应；
  ③ 未真跑；④ 未答「上限给多少最省」。

【改法】
- ★ 先量覆盖率，发现最刺眼那条根本不是没数据：「三态判决一致率」在产物里
  254/368 份都写了，而上一版抽取器只从 packed 抽（压根没写那个正则）
  ⇒ 补抽后 n 从 1 涨到 255。
- ★★ 由此推翻一个拍脑袋阈值：上一版规则「一致率 < 0.5 ⇒ 不降档（质量优先保护）」，
  而实测 p10 = 0.167、中位 = 0.333 ⇒ 0.5 在中位数**之上**，会拦掉 54%，
  实际等于把降档功能**废掉**。改成实测 p10 + 要求 ≥30 份样本。
- 分层：auto.history_limit 语义从「总样本数」改成「每题型上限」（两桶各取 N 条，
  扫描上限 4N，两桶满即停）。原语义下窗口一缩，事实型会被整体挤掉。
- 时间衰减：读数改**加权分位**，权重 0.5**(age/半衰期)，新键
  auto.history_halflife_days（出厂 14 天，0=不衰减）。
- 抽取器补齐：新增抽「三态一致率」与「外部锚点 · 联网」两行；
  ★ 抽不到的字段**不写键**（web_fail=0 与「没有这一行」是两件事）。
- 截断率加层样本门槛 _AUTO_STOP_MIN_N=24；一致率加 _AUTO_TRI_MIN_N=30。

【真跑对照（同题 / 全四层 / 只改上限 + 一次 auto 默认）】
- up2（显式锁 7 项，上限 2/2/2/2，元层被 all_extra_rounds 抬到 3）：
  实际停圈 2/2/2/3、自然 0 / 截断 4、79 calls / 739,219 tokens / 约 38 分钟。
- auto（不传参数）：从历史取上限 4/4/5/7、实际停圈 4/4/5/7、自然 1 / 截断 3、
  193 calls / 2,420,429 tokens、模式 B、联网收 24 条（4 环节、失败 0）。
- ★★ 实际停圈 == 圈数上限（6 组全等）⇒ 停止判据在这类题上几乎不触发：
  「给足上限让它自然停」走不通，**上限就是成本**；最优不是上限最小
  （79 calls 那份是被截断的产物、质量没交代），而是按历史给够用的上限
  —— 即 _AUTO_ROUNDS_BASE 取实测 p50（4/4/5/6）的依据。
- ★ 三处新渲染行在真跑里全部兑现（调度表 / 实际停圈 / 联网行）；
  up2「auto 接管 5 项」vs auto「12 项」= 「显式 ＞ auto」在真跑里可见。
- ★ 真跑立刻改善历史读数：层样本 6→22、联网 96→144、三态 n 255→259；
  截断率 0.333→0.727（印证 6 层样本不足以下结论）。
- ★ 成本口径：单次调用 ≈25 秒；四层×2 圈 ≈38 分钟 / 79 calls / 74 万 tokens。
  据此砍掉 up6/up10（>1.5 小时、边际价值低），并写看门狗在落盘后立即停 runner。
