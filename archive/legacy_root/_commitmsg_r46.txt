fix(dgtf_app): R46 修「导入资料没反应」—— `FileList` 活引用被判据自己清空

用户第二次报「还是导入不了资料啊，也没有显示」。

【真根因】
dgtf_app/static/app.js 的 `#anchor-file` change 处理器原写成：

    const fs = e.target.files;      // ★ 拿到的是 FileList **活引用**
    e.target.value = '';            // ★ 清 value 会**就地清空 fs**
    if (fs && fs.length) importFiles(fs);   // ← 恒为假 ⇒ importFiles 一次都没跑过

页内最小对照实测：
    清空前 af.files.length=2  fs.length=2
    清空后 af.files.length=0  fs.length=0
    fs === af.files ? true

`value=''` 是 R44 为「同一文件能再选一次」加的，副作用当时没被测到 ——
R44/R45 两轮的验收探针都是**直接调 importFiles()**，整条
「点按钮 → 选文件 → change」的真实链路从没被走过。

【修法】
    const fs = e.target.files ? [...e.target.files] : [];   // 先拷成真数组（快照）
    e.target.value = '';
    if (fs.length) importFiles(fs);

【验收】★ 这次走真实路径：CDP `DOM.setFileInputFiles` 往 #anchor-file 塞真文件，
浏览器自己派发 change（程序 dispatchEvent 会被 value='' 清空，测不出真相）。

    判据              | 修复臂                      | 负对照（回退旧写法）
    ------------------|-----------------------------|------------------------
    fetch 请求        | POST /api/library/import    | ★ 一条都没有
    #import-msg       | 完成：成功 3 个             | ""（用户看到的）
    #import-detail    | 3 行 ✓ 明细                 | 空
    #local-list 行数  | 0 → 3                       | 3 → 3（没动）
    #attach-panel     | hidden=false（自动展开）    | hidden=true

  负对照逐条复现用户症状 ⇒ 判别力确认。

【新增守卫】dgtf_app/selftest.py 加 `check_r46_frontend(js)` 四条静态判据：
  1. 找得到 #anchor-file 的 change 处理器（取段锚 `_af.addEventListener('change'`，唯一）
  2. 取 files 必须**先拷成数组**（`[...e.target.files]`）
  3. **不许**在真代码行上出现 `const fs = e.target.files;`（注释行不算 —— 否则判据被自己的文档骗红）
  4. 清 value 仍在，且判据用**快照后的长度**（`if (fs.length)`）
