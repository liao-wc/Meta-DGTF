## 一、候选生成产出率（用户点名五处量化之第五处）

`candidate_yield(cands, prev_texts, thr=0.72)` —— 模块级纯函数、零 LLM：
逐条取与**上圈全部候选描述**的最大相似度，`new_ratio` = 相似度低于 thr 的
条数占比；`collapsed = new_ratio < 0.34`。
读数 `n / n_new / new_ratio / max_sim / collapsed / verdict`。

· ★ **缺输入 ⇒ 全 `None` + `verdict=""`（不表态）** —— 首次跑是「没得比」，
  不是「没长」；硬给 `collapsed` 会造出**假告警**。
· 接线：`DGTF.run` 的 `_drop_banned` 之后、`_dual_judge` **之前**
  （`_dual_judge` 会改写候选集合 ⇒ 读在它之后 = 读加工过的）。
  历史走 `view._prev_cand_descs` 跨圈暂存；命中 `collapsed` 打 `vp` 留痕、**不拦截**。
· 补丁：`_patch_v12333_candyield.py`。

## 二、★ 降本真缺陷：规则命中「省调用」被自己的补丁抵消

**现象**：`auto_plan(llm=...)` 的 B1 规则命中分支，注释写「命中即定案，
**不花这次模式调用**」—— 但为补 `orientation` 又调 `plan_orientation(q, cfg)`，
而它**签名只有 `config`**、内部自己 `new LLM(cfg)`（没有 `llm=` 可注入）
⇒ **真花掉一次调用**。实测规则命中路径 `LLM.call` = **1**（本应 0）。

⇒ 「规则优先省一次调用」的设计意图**被自己的补丁吃掉**，
  净效果 ≈ 没做优化 —— 用户点名诉求「减少 LLM 调用」的直接违背。
  ★ 形态 = 「有接线 ≠ 这跑走得到」的**第三类**：接线全在、行为也对，
    只是**成本账目与代码注释不一致**（没人把「规则命中 ⇒ 0 次调用」当判据跑过）。

**修**（`_patch_v12333_orientrule.py`）：新增模块级纯函数 `orientation_rule()`，
零成本、**与 `_has_decision_context` 同源**（同一个 `_DECISION_CUES`，
避免「打桩判 decision、渲染判 boundary」的双真相）；规则命中时用它，
**只有规则拿不准（空题面）才回落 LLM 版**。

**验收**：规则命中 ⇒ `LLM.call` **0 次**（构造性证明，spy 计数）；
新判据 **㉝** + 变异体 **M52**（方向反）/ **M53**（又偷调 LLM）⇒ 均判红。

## ★ 本轮新增通则

1. **凡「为了省钱」写的分支，必须配一条「省钱真的发生了」的成本判据**
   （构造性证明：spy 计数 == 0）。否则省钱的注释会随后续补丁**静默失效**。
2. **`and/or` 三元陷阱**：`x and A or B` 在 **A 是假值（0 / "" / []）** 时
   与 `A if x else B` **不等**（`True and 0` = 0 ⇒ `0 or 1` = 1）。
   症状：代码完全正确、判据**恒红**。
3. **「判据随实现更新」两种走向要分清**：**放宽**（`==3` → `>=3`，没牙）
   错；**登记**（`==3` → `==4`，仍是硬等式）对。
4. **「缺输入不表态」必须回 `None` 不能回 `0`** —— `0` 会被下游当成
   「测出来就是 0」。
