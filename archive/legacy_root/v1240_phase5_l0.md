## 机制

- **MAP-Elites 档案**：cell = polarity × 关键词桶（12 桶，md5 稳定映射）；每格保留 score 最高的精英，容量 32。
- **novelty**：候选与档案最近邻的 token Jaccard 距离；重复候选 novelty=0。
- **顺序接收**：边接收边更新档案，避免同批候选全部 novelty=1.0 的假多样性。
- **Heaps 饱和**：累计 cell 数对 log(round) 的斜率；连续无接收或 novelty 低则建议停。
- **Thompson 探针**：Beta(1,1) 后验采样选探针，成功/失败更新 alpha/beta。

### 判定：L0-v2 v1 **不通过**

- Q1：bench 覆盖/三态/决策持平，但 calls +12.7%、tokens +14.3%。
- Q2：覆盖 4/4 → **2/6**，三态 1.000 → **.500**；成本只 −5%。
- 两题都不构成 Pareto 改善；Q2 明显质量回退。

### 原因

1. 0 层候选只有 13–15 条，硬 quota=8 直接砍掉 5–7 条；被砍的不一定低质，可能正是 all 层需要的边界候选。
2. MAP-Elites 的 cell 由 polarity × 首关键词桶决定，桶太粗，精英选择与“研究覆盖”目标不对齐。
3. 只做**后置过滤**，没有改变候选生成；过滤只会丢信息，不会产生新信息。

### 下一步（重写 L0-v2 v2，而不是调大 quota）

- 把 MAP-Elites 从“裁剪器”改成“生成导向器”：档案只提供 novelty 方向，下一圈 prompt 注入“未覆盖 cell”，**不删本圈候选**。
- novelty 目标与 research coverage 对齐：按子问题覆盖/三态需要加权，而不是按关键词桶。
- 先做 0 层单层 A/B，通过前不碰 1/both/all。
- 在 v2 通过前，l0_v2_curate 保持 false；方案H 配置仅作实验留档，不推荐。

### 最终判定：L0-v2 **不通过**

- 不是参数没调好，而是“给 0 层加 novelty 方向”不能保证研究层覆盖/三态；
- 0 层是上游，novelty 目标与 research coverage/三态目标没有对齐；
- 继续硬调 quota/prompt 会在小样本上过拟合，不应启动 1/both/all。

## 观察

1. 真实 0 层候选量 28–60，归档后 8 个精英；novelty 首 8 个多在 0.92+，说明当前候选本身差异大，固定 quota=8 在这一步不是过度裁剪。
2. 档案只占 4–8 格 / 32，说明 polarity × 关键词桶对 0 层候选的覆盖很稀；下一步要评估桶设计（关键词太细会碎片化）。
3. 固定 quota=8 是保守起点；真正接入后应按 novelty 阈值 + 动态 quota，而不是每圈硬收 8。
4. Heaps/novelty stop 只能多圈 trace 验证；packed 只有最终圈，当前无法证明停止收益。
