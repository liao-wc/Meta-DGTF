v1.23.13 · 统一自适应调度器：十二项逐项可接管 + 清 auto_plan 双实现技术债

【问题】v1.23.12 之前，「自动」散在 8 处：main 三条纯规则（成本档/事实题联网/
思考强度）、run 两次 LLM（模式+圈数 / 只定模式）、取向路由一处、停止/联网降级/
配额写死在 yaml。三个后果：
  ① 读者答不出「这一次是谁定的 route / 圈数 / 联网」；
  ② 做不到「只让 auto 管一项」—— `--rounds` 默认 "0"、`--route` 默认全四层，
     「没给」与「给了」不可区分；
  ③ 停止/降级阈值是常量，不吃题型与历史。

【改法】
- 新增 auto_dispatch()：十二项一次算完 —— 层集合/成本档/并行模式/圈数/取向路由/
  联网/思考/强度/停止阈值/联网降级/可判定性判定/落地层模板。每项按
  `显式 ＞ 配置 ＞ auto ＞ 默认` 取值，逐项留痕（值/来源/理由）。
- auto 的输入三类，全部零 LLM：_auto_features（纯规则题型特征）、已给的
  cost/effort/rounds（成本质量意图与效率约束）、_auto_history（扫最近 N 份
  *.packed.json：成本中位/被截断率/各层实际停圈/三态一致率/联网入池与失败/
  取向错配）。
- 12 个策略纯函数 _auto_pick_*；规则能定的不调 LLM（事实短题直接 serial）。
- 落点三类都不改判定语义：进 run() 参数 / 写 cfg["runtime"] 由既有
  _apply_runtime 落（唯一写入者）/ 写既有阈值键（spiral.*、web_search.*）。
- 产物头部新增「自动调度（逐项来源）」十二条表格 + 题型特征 + 历史读数。
- CLI：--route/--rounds/--appendix 默认改 None；新增 --landing/--decidability。
- 取向与落地层解耦（上一版 auto 在路由侧按 decision、在模板侧按题面分流）。
- 全关开关 auto.enabled=false ⇒ 十二项退回配置/默认，行为回到上一版。

【技术债】auto_plan() 双实现 + 双 schema（v1.21.71 F8 起挂账）：
- 新增 _assemble_plan() 唯一装配器（三条出口全过它）⇒ schema 只有一种；
  单调用路径因此也带上 route/cost_profile/max_calls（由缺变有）。
- 新增 _normalize_orientation(v, fallback) 唯一实现（原三份）。
- P5.2.b 从「数源码字面」改成行为判据（低置信打桩 ⇒ mode=serial 且取向带出）。

【验收】
- 探针（零 LLM，合成输入 + 合成历史）71 项读数：十二项齐全与留痕 / 逐项显式接管
  10 项各验一次（每项断言「只改这一项」）/ 总开关 / 历史自适应 5 正 3 负 /
  技术债两路同 schema / 产物十二行表。
- 冒烟 exit 0 / 0 ✗ / 208 ✓（守卫 100→101）。

- --phase all PASS 310 / FAIL 5，红名单全部落在基线红名单之内 ⇒ 无新增红。

  AST 登记 added 104→132 两向对账；主文件 17275 → 17984 行 / 纯 CRLF。

【本轮修掉自己三处错】
- ★ 功能级：_apply_auto_dispatch 首版只写「来源是 auto」的项 ⇒ --web off /
  --profile quality / --thinking on / --effort max 全部失效。正确规则：写
  来源 ∈ {auto, 显式}；source 是给留痕用的。由既有接线判据抓到，已补 M8 变异体。
- 补丁脚本混用文本级与行级替换，中间一次 join 静默丢掉所有文本级替换
  （版本号没升、4 处调用全丢），ast.parse 却通过 ⇒ 改为只用行表一处真相源。
- 三条判据查源码字面 ⇒ 重构后误报，全部改成行为断言（P5.2.b / smoke v1.23.4 /
  smoke v1.23.11 联网接线）。
