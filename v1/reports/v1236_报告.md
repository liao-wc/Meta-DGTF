## 二、版次标记的口径（判据与清理工具同一把尺子）

```
TAG = \[v\d[^\]]*\]                      # 方括号短标签：[v1.21.71 F9] / [v122 P6 G6.2]
    | (?<![A-Za-z0-9_-])v\d+(?:\.\d+)*(?![A-Za-z0-9_-])   # 裸 v+数字：v1.21.59 / v1.19 / v59
```

两侧 lookbehind/lookahead 挡掉 `deepseek-v4-pro` 这类假阳性（实测该串会被裸规则误命中）。

★ **上一版定口径时用的是窄口径 `v1\.2\d`**，报出 395 行；实测口径放宽后：
**注释行 441 行**、**批注块 378 个 / 覆盖 1479 行**。
窄口径把规模低估到约 **1/4** —— 因为块内只有首行带标记、其余是续行，
而短标签 `[v122 …]` / `v59` 形态根本没被窄口径覆盖。

## 三、三类处置

| 类 | 形态 | 处置 |
|---|---|---|
| A | 整行注释且含标记 | **连块删**（块 = 连续注释行，最多的一块 18 行） |
| B | 代码 + 同行 `# …` 含标记 | **只删注释部分**，代码保留（`strip()` 掉行尾空白） |
| C | 函数/类 docstring **以**标记开头 | **只剥前导标记**，正文一字不动（`old == tag + new`） |

### 两条保护（都因为「判据在读」）

- **P1** 含 `[AUDIT-<数字>]` 的注释行**不删** —— 冒烟里
  `src.count("# [AUDIT-122] 标 pending_fix：")` 与常量 `_AUDIT122_PENDING_FIX`
  两向对账。这类行内的版次标记**另行抹掉**，所以保护行也不含标记（2 行）。
- **P2** **判据需要的片段一个都不许消失**。做法：从 `smoke_test.py` + `_v122_verify.py`
  收集全部 `"X" in src` / `"X" not in src` / `src.count("X")` 的 X（**156 个**），
  做**最小代价保护** —— 某片段若**全部出现处**都在待删行里，只保住其中**最短的
  那一行**（实保 3 行），而不是整块。删除量因此只从 1479 降到 1476。

  ★ 本项目实踩：`assert "修行层不追求收敛" in src, "缺红线注释"` —— 该短语**只**
  出现在一行带版次标签的**宪法红线注释**里。盲目按标记删会直接打掉红线。

## 九、经验教训

1. ★ **「按行数」会把注释类清理的规模低估到 1/4**。块内只有首行带标记，
   续行才是大头（最大一块 18 行）。**量法必须按「块」**。
2. ★★ **测试套件会把注释当锚点** —— 这是本轮最大的发现。三类耦合：
   `assert "<注释片段>" in src`、`getsource(方法)` 里查注释、**变异体锚点含注释**。
   本项目有 156 个这样的片段。**结论：注释不是「随手可删的东西」，它是契约的一部分。**
   所以「清理」必须配**判据驱动的保护名单**，而不是一刀切。
3. ★ **保护粒度要「最小代价」**：我第一版按「块」保护，2 字泛词（`'文件'`、`'断言'`）
   一下保住 57 个块 —— 等于没清。改成「每个片段最多保一行、且只在它会全部消失时保」
   后，只多保 3 行。**保护的粒度就是清理的成败。**
4. ★ **`not in` 不能漏**：收集判据片段时我先只匹配 `"X" in src`，漏了
   `"X" not in src`，导致 `[v1.21.72 #13]` 那条被判据点名要求的注释被删掉。
5. ★ 本机 **bash 命令偶发被执行两次**（本轮 3 次），一次性补丁脚本**必须幂等**；
   写完立刻**换一条命令回读**（沙箱 overlay 会吞写入，本轮主文件头部被吞过一次）。
6. ★ 判据的锚不能是**会变的东西**（版本号、版本标签）。本轮两处失效都源于此。
