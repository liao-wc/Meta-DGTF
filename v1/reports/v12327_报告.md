## 0. 为什么要合并 v1.23.27 与 v1.23.28

设计报告原本把「接口层（E1/E2/E5/A1）」与「信念层（D1/D2/D3）」拆两版。  
但实测核对依赖后发现**顺序倒置**：

```
E1（引擎算 G）──需要──> H_sem（语义熵，原 v1.23.28 的 D3）
                └──────> BeliefItem.status（原 v1.23.28 的 D1）
E2（子模批选）──需要──> G（E1）
E3（covers）───需要──> AspectUnit.id（A1）+ BeliefItem.id（D1）
```

⇒ v1.23.28 说「依赖前两版的 id 体系」，但 E1 反过来又依赖 v1.23.28 的语义熵。  
**本版把 A1 + D1/D2/D3 作为同一底座一起做，E1/E2/E3/E4/E5 才拿得到真实输入。**

### 2.5 D2 · 迁移规则（Step5 同批）

`belief_transition(item, *, round_no, sources, attack, resolved_by)` **纯函数**，  
优先级 **`resolved` > `revoked` > `stable` > 保持原状**：

| 迁移                  | 条件                                                             |
| ------------------- | -------------------------------------------------------------- |
| → `stable`          | `k=2` 圈（`_BELIEF_STABLE_K`）+ ≥2 独立来源（`_BELIEF_STABLE_SOURCES`） |
| → `revoked`         | `attack ≥ support`                                             |
| `stable` → `active` | 出现新 `attack`                                                   |
| 任意 → `resolved`     | 由 `decidable_channel` 回答（`resolved_by` 非空）                     |

**为什么 resolved 最高**：红线「停止与清算分开」—— 一旦被可判定通道回答，  
「稳不稳 / 被不被质疑」都不再是这条主张的问题。

### 2.6 D3 · 语义熵（`_patch_v12327_step6.py`）

- `_SEM_CLUSTER_THR = 0.70`
- `semantic_entropy_of(texts, corpus, thr, top_n)` → `(h_norm, h_raw, clusters)`
  - `h_norm = h_raw / ln(n)` ∈ [0,1]
  - **`n < 2` 返回 `(None, 0.0, ...)`**（不是 `0.0`）
  - 单链聚类到**簇代表**（保守：宁可高估发散，不高估稳定）
- `Pool.refresh_belief_entropy(corpus, thr)` —— 刷新所有条目

### 2.7 E1 · EIG 可计算化（`_patch_v12327_step7.py` + `step8c` + Step10 修）

`probe_information_gain(probe, belief_items, covered_ids, corpus, thr,
assign_min)` → `(G, detail)`：

```
G = (h_before - h_after) / h_before ∈ [0,1]
```

- 算不出来（未决 < 2 / 全被覆盖 / 空问题）⇒ **返回 `(None, {"why":...})`**，  
  **不是 `0.0`**（0.0 = 「算出来是零增益」，None = 「没有可谈的信息量」）
- `_GAIN_ASSIGN_MIN = 0.15` 软分配下限（不设会得到稠密矩阵 ⇒ 熵降全是噪声）

**★ 两个必须同时修的坑（否则 G 恒为 0）**：

1. **两臂同一把尺子**（Step8c）：`_raw_entropy` 返回**原始**熵、不归一化，  
   分母恒为 `ln(n_before)`。各臂用自己的 `ln(n)` 会把「移除」的效应抵消掉。
2. **命中整簇而非单条**（Step10 实测新抓）：未决 `{B1,B2,B3}`，B1~B2 同簇、  
   B3 独立 ⇒ `h_before` 用「2 簇」分歧度；若只移 B1，剩下 `{B2,B3}`  
   **不再同簇** ⇒ 归一化后 `h_after > h_before` ⇒ G 被 `max(0.0,…)` 夹成 0。  
   实际语义：探针命中一簇 = 「这簇疑问被回答了」，同簇是同一件事的另一种  
   说法，应一并消解。

### 2.8 E2 · 子模批选（Step7 同批）

`select_probe_focus_submodular(pool, candidates, n, corpus, thr, floor)`  
→ `(picked, detail)`：贪心 + 边际下限 `_GAIN_MARGINAL_FLOOR`（默认 0.0）。

- 配置开关 `probe.submodular`（默认 `True`）；**算不出 G 时自动退回** `_legacy`
- `select_probe_focus` 尾部接它；`expected_gain` **双写**引擎 G + 模型自报，  
  并标 `gain_source="engine"/"model"`

**为什么「宁少勿滥」**：`floor` 是「不许零增益补位」，**不是**「不许少」。  
G 的绝对值尺度依赖池大小，硬阈值会随池漂移 ⇒ 默认 0.0。

### 2.11 E5 · 双向判据（Step8 同批）

| 条件                                                       | 判定                      |
| -------------------------------------------------------- | ----------------------- |
| 理由 ≥8 字 **且** 与 `untouched` 某项 `_sim3 ≥ _COVERS_SIM_MIN` | `honest_empty`（**不罚**）  |
| 其余（理由空洞 / 缺失）                                            | `lazy_empty`（**留痕不罚分**） |

**为什么**：旧行为与提示词「推不动就返回空数组」**方向正好相反** ——

- `_GAIN_STOP_FLOOR = 0.02` + 配置键 `probe.stop_floor`

  → `(is_stop, reason)`
  - `seen == 0` ⇒ `(False, "no_candidate")` —— **不是停止**  
    （「模型没给候选」≠「候选都推不动」；混为一谈会让「模型偷懒」被读成

**★ 它与 `min_gain` 是两把尺子**：`min_gain` 管「模型自报值不值得做」，  
`stop_floor` 管「还能不能推得动」。默认 0.02 刻意压低 —— 停止是强动作。

### ★★ 收尾核查抓到的**本版真缺陷**：D1/D2 结构性不可达

> 这是 §5.2「`belief_transitions` 0 条」的**正确解释**——原报告写的
> 「无状态迁移 ⇒ 符合预期」是**错判**，实测证明是「三条迁移根本无法发生」。

**现象**：`belief_items` 17 条全 `active`；`belief_transitions` 恒 0 条。

**根因（实测坐实）**：`upsert_belief` 的**唯一调用点** L4557 被嵌在
「这个 `structural_amp` 是**新的**」守卫里：

```python
if s and not any(_similar(s, x, _DUP_SIM)
                 for x in self.undecidable_channel["structural_amps"]):
    ...append...
    self.upsert_belief(s[:200], ground="layer%s" % layer,
                       round_no=int(layer or 0), sources=["layer%s" % layer])
```

⇒ **跨圈复现同一主张 = 被 `_DUP_SIM` 判定重复 = 跳过登记**。

实测（构造脚本走真实入口 `add_undecidable`，连喂 4 圈）：

| 圈 | `structural_amps` | belief `support` | `rounds_seen` |
|---|---|---|---|
| 1 | 1 条 | `['layer1']` | `[1]` |
| 2 | 1 条 | `['layer1']` | `[1]` |
| 3 | 1 条 | `['layer1']` | `[1]` |
| 4 | 1 条 | `['layer1']` | `[1]` |

⇒ `stable` 要 `support >= 2 且 rounds >= 2` ⇒ **永不成立**。

**四条迁移的可达性总账**：

| 迁移 | 触发条件 | 调用点是否满足 | 可达 |
|---|---|---|---|
| `resolved` | `resolved_by` 非空 | **0 处传** | ✗ |
| `revoked` | `attack` 非空 | **0 处传** | ✗ |
| `stable` | `support>=2 且 rounds>=2` | 守卫挡复现（上表） | ✗ |
| 保持原状 | 默认 | — | ✓ |

⇒ `belief_transitions` **必然恒空**。B（绕过守卫直接调 `upsert_belief`）
实测 `support` 能累积到 4 ⇒ **纯函数本身没问题，坏的是接线**。

**连带的语义错位**：`layer` 实参来自 `layer_no = r + 1`（L11539）与
`r`（L12770）——**是圈号，不是层名**。故 `ground` 被写成 `"layer3"`
（第 3 圈）而非 `"layer1"`（研究层）；`sources` 同理。变量名叫 `layer`
是**误导性命名**（L12098 走默认 0，连圈号都不是）。

**判据为什么没抓到**：smoke L11303-11317 只测 `belief_transition`
**纯函数**（直接喂构造入参）；L11357 直接把 `belief_items` 塞进去
⇒ **没有一条判据走真实登记路径**。

★★ 这是红线「**有接线 ≠ 这跑走得到**」的完美反例现场。
**升级为通则**：*纯函数判据全绿 ≠ 该能力在引擎里可达* ——
新能力必须配一条**「真实入口产出」判据**（跑一次入口、断言产出），
而不是「调用点存在」或「纯函数正确」判据。
