## 二、问题：脏数据是**怎么产生的**

A/B 真跑（`_fullrun_V1250AB.py`）在 `run()` 之后又调了一次 `m._eml_finish(res)`，
而 `run()` **内部本来就调过**（`元DGTF-V1.23.51.py` 的 `run()` 里那处
`packed["playbook"] = self._eml_finish(packed)`）。于是每个跑次学两遍：

| 文件 | 脏成什么样 |
|---|---|
| `episodes.jsonl` | V1250A / V1250B **各 2 条**除 `t` 外完全相同的记录 |
| `nogoods.jsonl` | 同样每跑 2 条 |
| `playbook.jsonl` | 7 个条目的 `used_outcomes` 每个 `run_id` **记了 2 次** ⇒ `weight` 多扣 0.05/次 |
| `dgtf_memory/MEMORY.md` | 证据数 6→8 **是对的**（`t_used` 按 `run_id` 去重） |

**为什么 v1.23.48/49 的 A/B 跑次没脏**：那两版的 `run_id` 没在 `_eml_finish`
之前盖进产物 ⇒ 内部那次调用拿到空 id，被「匿名跑次一律不写库」的闸挡掉，
于是脚本那次看起来"正常"。v1.23.50 修好盖章之后，内部那次变成真写，脚本那次
就成了重复。**证据**：`episodes.jsonl` 里只有 V1250A/V1250B 重复，V1248/V1249 一条都没有。

> 这是「**同一个语义两处调用**」的第 N 次复发：修一处不算修，得让**重复调用本身无害**。

## 三、修法（两处，各司其职）

### 1) 引擎侧：`_eml_finish` 幂等守卫（兜住**所有**调用方）

位置有硬约束：**拿到跨进程锁之后、写 episode 之前**。

```python
try:
    _old_eps = eml_read_jsonl(_dir / _EML_EPISODES) or []
except Exception:
    _old_eps = []
_sig_new = json.dumps({k: v for k, v in _ep.items() if k != "t"},
                      ensure_ascii=False, sort_keys=True)
for _oe in _old_eps:
    if str((_oe or {}).get("run_id") or "") != str(_ep.get("run_id") or ""):
        continue
    _sig_old = json.dumps({k: v for k, v in (_oe or {}).items() if k != "t"},
                          ensure_ascii=False, sort_keys=True)
    if _sig_old == _sig_new:
        _blk["dup_skipped"] = True
        ...
        return _blk
```

两个设计决定，都是为了不把别的场景一起挡掉：

- **为什么要拿锁之后**：两个进程同时收尾时，先读后写必须在锁内，否则两边都读到
  「还没有这条」⇒ 守卫形同虚设。
- **为什么判据是「同 `run_id` 且除 `t` 外逐字相同」而不是「只看 `run_id`」**：
  墙钟预算 `paused` 的跑次也会写一条**半程样本**；续跑跑完时它的
  `cost` / `rounds_cap` / `cut_layers` 都不同 ⇒ **必须能写**，否则完整样本永远进不了库。
  这个分支由冒烟的正对照钉住（同 `run_id` + 不同读数 ⇒ 照写）。

### 2) 调用方侧：`_fullrun_V1250AB.py` 改成**条件补调**

```python
_pb = res.get("playbook")
if not isinstance(_pb, dict) or _pb.get("error"):
    try:
        res["playbook"] = m._eml_finish(res)
    except Exception as e:
        ...
```

★ 引擎守卫**不能替代**这一处：守卫的返回值是一块 `dup_skipped` 的留痕，若调用方
拿它覆盖 `res["playbook"]`，产物里的学习块就被降级成空壳。**正确做法是根本不重调。**

> 同族的 `_fullrun_V1248AB.py` / `_fullrun_V1249AB.py` **没改**：它们的跑次已归档，
> 而且引擎侧守卫现在能兜住它们。改历史脚本会让「当时的脚本长什么样」失真。

### 3) 数据侧：已清账（独立提交 `485a5ff`）

`_fix_eml_dup_20261016.py`（干跑 + `--apply` 两道断言）：

## 七、经验教训

1. **「修好一个锁」会让原本被它挡住的 bug 显形。** v1.23.50 修「`run_id` 盖章」
   是对的，代价是 A/B 脚本的重复调用从「无害」变成「脏数据」。**改一处语义时，
   要问一句「有没有谁一直在依赖旧语义的副作用」。**
2. **幂等守卫的判据不能只看主键（`run_id`）**，否则会把「同一跑次的完整样本」
   当重复丢掉。正确做法是**带上读数指纹**，并用正对照把「照写」这一支也钉住。
3. **判据的位置也是判据的一部分。** E5 第一次假红不是实现错，是它被放在了
   「对照组故意制造同形数据」之后 —— 与「检测缺省要在补默认值之前判」同一条纪律。
4. **逐字节比 > 数条数。** 数条数只能发现「多写了一条」，发现不了「条数没变但
   `weight` 被多扣一档」。
