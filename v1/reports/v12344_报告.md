# 元 DGTF · v1.23.44 验收报告

## 一、问题（实测，非猜）

查真库 `dgtf_memory/playbook.jsonl`（11 条）：

```
status:      active 8 · shadow 3
n_evidence:  {1: 3, 76: 2, 4: 2, 3: 1, 6: 1, 68: 1, 66: 1}
阈值:        _EML_PROMOTE_N = 3   _EML_RETIRE_RECENCY = 0.05（halflife 14d）
```

- **升级 0 的真因**：3 条 `shadow` 卡在 `n_evidence = 1 < 3`（**静态阈值**）⇒ 永远升不上去。
- **遗忘 0 的真因**：`recency = 0.5^(age/14) < 0.05` ⇒ 需 **age > 60 天**；库才建几周 ⇒ 永不触发。

两者都是 SOTA 点名的失败模式：**cold start** + **static thresholds**
（ReasoningBank, arXiv:2509.25140；Memory-Driven Self-Improvement 综述）。

## 二、修法

1. `eml_promote(..., adaptive=False)`：adaptive 且库 < `_EML_COLD_LIB(20)` ⇒ 晋升门槛降到 **1**
   （冷启期先让学到的条目能生效）。
2. `eml_sweep_forget(..., adaptive=False)`：adaptive 时退休门槛随库规模放大（大库才该多清）。
3. 接线：读 `memory.eml_adaptive` 传给两处。
4. 新配置键 `memory.eml_adaptive: false`（引擎 + yaml + app 三处同步）。

★ **默认 false = 关 ⇒ 逐字零行为差**（`adaptive=False` 时 `_eff_n == promote_n`、`_rr == retire_recency`）。
