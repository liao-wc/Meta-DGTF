## 二、A1：锚点只挂在 serial 通道（硬伤）

**改前实测**（`_probe_v75_before.txt`）：

- 全源码 `self._anchor_round(` 只有 **1 处**调用点，在 `_run_layer`（serial 通道）里
- `_before_round` **0 处**
- `_run_one_round_B` 函数体**含** `_print_polarity_snapshot`、**不含** `_anchor_round`

**后果链**：B/C/D-H 七个模式走别的入口 → 锚点从不入池 → `pooled` 恒 0 →
收尾对照拿不到锚点。**那条链上的所有锚点读数全是假的**——不是「没效果」，
是「压根没接上」。

**做法**：抽 `_before_round(entry, pool, layer_no)` 作**统一圈前入口**
（极性快照 + 锚点入池），`_run_layer` 与 `_run_one_round_B` 都调它。
做成一个方法而不是两处各写一份——本项目「同一条逻辑两条通道各写一份」
已发生过 7 次以上，这是第 8 次的防线。

`layer_no` 是 1-based、`_anchor_round` 收 0-based，内部做 -1 转换
（离线实测：`_before_round(entry, pool, 1)` → `_anchor_round(..., 0)`）。

**判据**：`check_v76_anchor_two_channels`。

## 三、A2：`_anchor_calls` 从未被赋值（硬伤）

**改前实测**：`_anchor_calls` 全源码出现 **2 次，都是读**
（`_budget_exhausted` 的 `getattr` + packed 输出），**0 次写**。

**后果**：v1.21.75 宣称的「检索调用纳预算」是**空转** —— 加了个恒为 0 的项；
同时 packed 里 `anchor_calls` 永远写 0，看起来像「没花过钱」。

> 这是**上一轮我自己的错误**：v75 报告里写了「检索调用纳预算」，
> 实际只加了读、没加写。本轮复核把它抓出来了。

**做法 3 条**：

1. `__init__` 显式 `self._anchor_calls: int = 0`
2. `_budget_exhausted` 里**只算 `llm.total_calls`** —— 锚点调用发生在收尾对照
   （打包阶段，不在圈循环内），不该混进这个守卫
3. `_anchor_crosscheck` 里做**独立预算判断**（用尽则跳过并留痕），
   并在**真正发起调用前**自增、回填 packed

**判据**：`check_v76_anchor_calls`。
**离线验收**：`calls=10/budget=10` → 用尽；`calls=10/budget=20/anchor=99` → 未用尽
（锚点不再影响守卫）；预算用尽时 crosscheck 返回 `收尾对照跳过：预算已用尽（10/10）`。

### ★ 清单里有一处判据是错的（已修正并说明）

清单 P1 写「`_anchor_round` 直接调用点：改前 1，改后 **0**」。
**这不可能** —— `_before_round` 内部必须调 `_anchor_round`，全源码至少 1 处。
清单**自己的冒烟判据 1** 写的却是「`_anchor_round` 直接调用点**恰好 1 处**」,
前后矛盾。

按后者实现，并把探针判据改为更有意义的形态：
**「总数恰好 1 处，且它归拢在 `_before_round` 里」**（P1 = `1/0 → 1/1`）。
