# 元 DGTF · v1.23.49 验收报告

> 主题：**跑中快照（心跳落盘 + 孤儿回收）** —— 修「`run()` 只在返回后写盘 ⇒ 宿主回收就全丢」。

## 一、问题（实测，非猜）

今天 12:37 的 A/B 真跑（`_fullrun_V1248AB.py`）被宿主回收：**~24 分钟 / ~¥2 全丢**。
`MetaDGTF.run()` 是 60 分钟级长跑，packed 只在 `return` 前组装、调用方只在返回后
才写盘 ⇒ 中途被强杀 = 连层 0 的五圈都不剩。

## 二、修法（配置式；**默认 true 是本项目「新键默认关」惯例的唯一例外**，用户拍板）

1. **跑中快照**：`run()` 起 **daemon** 心跳线程（`start_run_ckpt`），每 `ckpt_interval`
   （默认 30s）把 `self._results`（各层 `View.to_dict()`）**原子**落盘
   （`tmp` + `os.replace` ⇒ 强杀也不留半份）；跑完/异常落 final（`status=done`/原因）。
2. **孤儿回收**：`recover_orphan_runs()` 把超过 `_RUN_CKPT_STALE`（900s）仍 `running`
   的回填 `interrupted` + `interrupted_why`（**幂等**；新鲜的**不动** —— 判据里做负对照）。
3. **新配置键 2 个**：`runtime.live_checkpoint: true`、`runtime.ckpt_interval: 30.0`
   —— ★ **默认 true 是惯例的唯一例外**：它是纯安全网（daemon 心跳 + 原子落盘），
   不碰任何引擎输出/结论，只决定「崩了能不能找回」；12:37 已用 24 分钟 / ~¥2
   证明「默认关」的代价是**全丢**。要回到零行为差设 `false` 即可（app 面板也能关）。
4. 快照目录：`<repo>/outputs/_run_ckpt/`（`run_ckpt_dir` / `run_ckpt_path`）。

### 2.1 本轮挖出并修掉的**两个真 bug**（都在新代码自己的静默失败区）

判据写完做单独复现时发现 `_ckpt_snapshot` 有两个被 `except: pass` 吞掉的异常：

- `dict(None)`：某层中途还没有 View（**长跑中途是常态**）⇒ TypeError；
- `ENGINE_VERSION`：**未定义**（模块里只有 `__version__`）⇒ NameError。

两处都发生在 `stop_run_ckpt` / 心跳体内部，且都被 `except: pass` **静默吞掉**
⇒ **安全网从未成功落过一次盘**（「能力存在但静默不可达」第 1 形态）。
修法：None 守卫（该层记 `None`，不丢层）+ 改用 `__version__`。
—— 这正是 12:37 全丢的**同一类静默失败**，也是本版判据⑦（端到端真落盘）存在的理由。
