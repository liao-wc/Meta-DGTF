## 1. 核心教训：纯函数判据全绿 ≠ 该能力在引擎里可达

这是本版最重要的一条，也是 v1.23.27 翻车的根因。

v1.23.27 的 D1/D2 判据长这样：

```python
_cur = mod.make_belief_item("x", "g", "active")
if mod.belief_transition(_cur, round_no=1, sources=["p#1"]) != "active":
    bad.append("[D2] 单圈单来源不该升 stable")
```

**完美通过**。但真实入口下（`Pool.add_undecidable` → `upsert_belief`）：

| 能力 | 纯函数判据 | 真实入口 | 结论 |
|---|---|---|---|
| `stable` 迁移 | ✅ | **0 条** | 不可达 |
| `revoked` 迁移 | ✅ | **0 条** | 不可达 |
| `resolved` 迁移 | ✅ | **0 条** | 不可达 |

根因三条：
1. `upsert_belief` 被嵌在「结构名是**新的**」守卫里 ⇒ 复现（同一条主张第二次
   出现）被 `_DUP_SIM` 挡掉 ⇒ `support` 恒 `['layer1']`、`rounds_seen` 恒 `[1]`
   ⇒ `stable` 永不成立。
2. `attack` / `resolved_by` 在调用点 **0 处传参** ⇒ `revoked` / `resolved`
   连输入都没有。
3. `layer` 实参是**圈号**不是层名（`ground="layer3"`）⇒ 变量名误导。

**修正表述**：v1.23.27 报告里写的「`belief_transitions` 0 条 ⇒ 符合预期」是**错判**。
0 条不是「本轮没触发」，是「结构上不可能触发」。

**新通则**（已写入工作记忆的 MEMORY，见 `.workbuddy/memory/`）：新能力必须配
一条「**真实入口产出**」判据 ——
跑一次真实入口、**断言产出**，而不是「调用点存在」或「纯函数正确」。

### 1.1 ★ 更隐蔽的第二类盲区：字段有值 ≠ 读数有信息量

§1 说的是「能力不可达」。本版真跑时又抓到**更难发现的一种**：
能力**可达**、字段**有值**、判据**全绿** —— 但那个值的**信息量为零**。

D3 `semantic_entropy` 就是标本：第一轮修好后真跑产物里 **6/6 条 = 1.0**，
而 `1.0` 是**归一化熵的上界**（= 「这些簇两两都不同」）。
即「每个主张看起来都和别的完全不同」——这在 6 条**本就异质**的文本上必然成立
⇒ 读数**不携带任何区分信息**，与「恒 `None`」在**可用性**上是同一级别的失败，
却因为「有值」而**骗过了所有纯函数判据**。

**两向自查法**（本版立的规矩）：
- 出口存在？ → **产出非空？**
- 字段有值？ → **值的分布有区分度吗？**（全是同一个数 = 可疑）
- 读的是**同一个东西**吗？（`to_dict` 出口 vs 实际赋值点）

★ 这也解释了为什么「读产物」不能省：产物的**值分布**是唯一能证伪
「有值但零信息」的东西，纯函数判据看不见它。

## 2. 三项「效果不如原版」的重新设计

### 2.1 A3 双读数死字段 → 补出口

`touch_rate` / `aspect_carry_rate` 是 `View` 级 `property`，而
`View.to_dict() = asdict(self)` —— **`asdict` 不收集 property** ⇒ 值算出来了、
产物里读不到。

★ 陷阱：`View.to_dict`（`asdict` 自动全量）与 `Pool.to_dict`（手工白名单）是
**同名两种语义**。先前「搜键名字面量查出口」的做法查不出 `asdict` 那条路。

修：`View.to_dict` 在 `asdict` 之外显式补两个键。

### 2.2 D1/D2 三条迁移不可达 → 登记与去重解耦

- `upsert_belief` 移出「新条目」守卫 ⇒ 每圈都登记；
- `sources` 用**层名**（`0`/`1`/`both`/`all`）而非圈号 —— 同一主张被不同层
  独立提炼才算「独立复现」，用圈号会让「同一层反复说」冒充独立；
- `attack` / `resolved_by` 元数据在注入点统一补（`_belief_attack` /
  `_belief_resolved`）。

**修复对照**（`_probe_v12328_belief_fix.py`）：

| 场景 | v1.23.27 | v1.23.28 |
|---|---|---|
| 跨层复现 | stable **0** | stable **1** ✅ |
| 攻击 | revoked **0** | revoked **1** ✅ |
| 清偿 | resolved **0** | resolved **1** ✅ |
| 同层反复说（负对照） | 0 | **0** ✅ |

### 2.3 D3 可观测字段未接线 → 出口前刷新一次（第一轮）

`refresh_belief_entropy` **零调用点** ⇒ 产物 `semantic_entropy` 恒 `null`。
修：`add_undecidable` 出口前刷新（唯一调用点）。实测从 `null` → `0.75`。

★ **但这条在第二轮被推翻** —— 真跑产物核对表明 `0.75` 是「**有值但零信息量**」，
见 §2.4。这是本版最重要的一次自我纠正。

### 2.4 ★★ D3 `semantic_entropy` 恒等上界：三轮迭代

**发现方式**：不看纯函数判据，直接读**真跑产物** ——
`outputs/20261013_144044_*.packed.json` 里 **6/6 条** `h_norm = 1.0`，
`semantic_clusters` 全是 `[[0],[1],[2],[3],[4],[5]]`。

**根因（R1 出厂实现）**：`_txt = [本条目 text] + 全池 structural_amps`
⇒ 这个主张的文本与一批**异质**文本混在一起对比 ⇒ 簇全异 ⇒ 归一化熵
**恒取到上界**。这是「**字段有值 ≠ 读数有信息量**」的教科书案例。

| 轮次 | 方案 | 真跑实测 | 结论 |
|---|---|---|---|
| **R1（出厂）** | 本条目 text + **全池** amps | 6/6 恒 **1.0** | ❌ 零信息量 |
| **R2** | 改按条目**自身** `occurrences` 算 | 恒 **None** | ❌ 仍不可用 |
| **R3（定稿）** | 只留**包住本条目 text** 的那个簇 + `thr=0.30` | 近义 → **0.0** / 无关 → **None** | ✅ |

**R2 失败的根因**：`upsert_belief` 按**精确文本**认领 ⇒「同主张换说法」成了
**新条目**（各 1 次出现）；而逐字重复又被去重挡掉 ⇒ `occurrence_n` 恒 1
⇒ 两头都 `None`。

**R3 的关键实测**：`_sim3` 是**字符二元组 Jaccard**（`_tokenize` 按 bigram 切）——
- 「同主张换说法」实测 **0.41 ~ 0.79**
- 「不同主张」实测 **0.00**

⇒ 原 `0.70` 阈值**只有近乎逐字才够得着**（直测
`'落盘的最小单位是约束'` vs `'落盘的最小单位是那条约束'` → `_sim3 = 0.6667`
⇒ **卡在阈值下**）。改 **0.30**，落在实测空隙 `0.00 ↔ 0.41` 内。

**R3 行为矩阵**（`_diag_d3r3.py`，真实入口驱动）：

### 2.5 ★★ `View.belief_items` 回填**时序颠倒** —— 「走得到」的第三种失败

**发现方式**：第二次真跑（`20261013_152451`）读产物 ——
`pools.1.belief_items` 有 **6 条**（text 完整），`views.1.amps[0].desc`
与 `belief_items[0].text` **逐字相同**，但 `views.1.belief_items` **仍是 0 条**。

⇒ **不是匹配键对不上**（我一度如此以为），是**回填时条目还没进池**：

```

    pool.merge(...)
    【F3 回填读 pool.belief_items】           ← ★ 此刻池是空的 ⇒ 恒 []
    ...
    pool.add_undecidable(_und_prod, ...)      ← 信念条目**在这里**才 upsert

```

**修法**：把回填块**整块搬移**到 `add_undecidable` 之后（唯一变化是执行时点；
匹配键、判据、异常兜底一字未改）。

**验证三件套**（缺一不可）：

| 项 | 手段 | 结果 |
|---|---|---|
| 构造性证明 | `_diag_f3_order.py` 直接驱动真实入口 | 修前 `view n=0` → 修后 **`n=2`** |
| 负对照 | 同上 N1：text 对不上 | 保持 **`[]`**（不猜、不倒全池）✓ |
| **变异体** | `_mut_v12328.py` **M11**：回填块搬回原位 | **判红**（`view n=0`）✓ |
| **真跑探针** | `_diag_f3_trace.py` 猴补丁打点（**不改主文件**） | `pool_after=5 / view_after=5` ✓ |

★ M11 走本脚本既有范式 `_run_case_via_import(变异文本)` —— **不碰主文件**，
从根上避免「变异体没跑完把源码留在变异态」（也曾是 `_mut_f3_order.py` v1
的隐患：要靠 `finally` 手工复原）。

★★ **一次重要的自我纠偏**：第二遍真跑（`--rounds 2`）产物里
`views.1.belief_items` 仍是 `0`，我一度准备**再修一次**。是**真跑探针**
（`_diag_f3_trace.py`）把两件事分开了：
- `#1 entry=0 has_und=False ⇒ view_after=0` 是**正确**的（本圈没产出条目）；
- `#2 entry=1 has_und=True ⇒ view_after=5` 证明**修正确实生效**。

⇒ `--rounds 2` 的 `0` 来自「最后一圈的 `amps` 与池内条目文本不再重叠」——
**按设计如此**。★ 教训：**判据要能区分「没触发」与「坏了」**；
分不开就会把正确行为当缺陷反复"修"。探针（打点读数）正是为此而生。

**这条与 §1、§1.1 并列成「走得到」的三种失败形态**：
① 调用点存在但**结构性不可达**（§1）；

## 3. D2 `revoked` 规则**重新设计**（对称化）

### 3.1 问题

改前规则：

```python
if _atk and len(_atk) >= len(_sup):
    return "revoked"
```

真实入口下：`_sup` 每圈**恒 +1**（每层都是一个来源），`_atk` 每圈**至多 +1**。
⇒ `len(_atk) >= len(_sup)` **只在「每一圈都带攻击」时成立** ——
「攻击面 ≥ 支持面」实际退化成「**攻击从未缺席**」。

v1.23.27 因登记被守卫吞掉（条目恒 0 个），这条退化**从未暴露**；
v1.23.28 修好登记后它立刻变成「只要一直被骂就推翻」——
与 DGTF 的「对撞」语义不符。

### 3.2 重新设计：与 `stable` 对称

DGTF 的核心是「对撞」。对撞的判据从来不是「谁说得次数多」，而是
「**谁经得起独立复现**」。支持方如此，反对方亦然。

| 状态 | 判据（**同一把尺子**） |
|---|---|
| `stable` | 支持被 ≥2 个**不同来源**、跨 ≥2 圈独立复现 |
| `revoked` | 攻击被 ≥2 个**不同来源**、跨 ≥2 圈独立复现 |

实现：新增 `attack_sources` 字段（与 `support` 对称），
`_BELIEF_REVOKE_SOURCES = 2`。缺省回落 `sources`（旧调用点零改动）。

**三档对照实测**：

| 场景 | 结论 |
|---|---|
| 跨层复现（layer0 + layer1） | `stable` ✅ |
| 跨层攻击（layer1 + layerboth） | `revoked` ✅ |
| 同层反复攻击（layer0 ×4，负对照） | `active` ✅ |

★ 为什么更好：① 真实入口可达；② 不再是「一直骂就赢」；③ 与 `stable`
完全对称 ⇒ 可做负对照。

★ 配置化：`belief.revoke_sources`（默认 2）经 `Pool.revoke_sources` 下发到
纯函数 —— 实测 `revoke_sources=1` 时同层反复攻击即判 `revoked`，证配置**真接线**。

## 4. 全仓库复审抓到的三类问题

### 4.1 ★ E1 增益透传真 bug（`_gains` 键取错字段）

```python
_gains = {str(x.get("text", "")): x.get("g")
          for x in (_det.get("trace") or []) if x.get("picked")}
```

`select_probe_focus_submodular` 的 trace 条目键是 **`"picked"`**（值是文本），
**没有 `"text"` 键** ⇒ `str(x.get("text",""))` **恒为 `""`** ⇒
`_gains == {"": G}` ⇒ 后续 `_gains.get(str(_r.get("question")))` **恒 miss**
⇒ `expected_gain_engine` **恒 `None`**、`gain_source` **恒 `"model"`**。

**E1 算出来的 G 从未到达输出** —— 「有接线 ≠ 这跑走得到」的又一例：
纯函数（`probe_information_gain` 直接喂参）全绿，真实入口把结果丢了。

修：`x.get("picked")`。实测：

```
修前: {'expected_gain_engine': None, 'gain_source': 'model'}
修后: {'expected_gain_engine': 1.0, 'gain_source': 'engine'}
```

这也**收口了 v1.23.27 段尾记的已知待办**（「探针 `gain_source` 标记未落盘」）。

### 4.2 `_GAIN_MARGINAL_FLOOR = 0.0` 让守卫恒假

`G ∈ [0,1]` + `if _best_g < _fl:` ⇒ **永不成立** ⇒ `below_floor`
**结构性不可达**（「宁少勿滥」的核心分支从没跑过）。改：`0.02`。

★ 这是本项目反复出现的坑：**默认值让守卫失效**。写「不许低于 X」的守卫时，
先问「**默认 X 是否让条件恒假**」。

### 4.3 A1 `A{n}` 两套编号不同物 + `untouched` 从不带 id

- `aspect_units['A1']` = 锚点触及第 1 条；`aspect_targets['A1']` =

修：写入带 `id`；`aspect_targets_v12327` 按 `aspect_units` 实际 id 对齐。
