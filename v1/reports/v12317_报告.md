## 二、三处改动逐项

### 2.1 sat 间隔 3 → 2（`structure_saturation_every_n`）

改 3 处：`DEFAULT_CONFIG` 定义 + `_run_layer` / `_b_check_stop` 两处 `.get` 缺省。

**为什么**：真跑诊断发现研究层**六条停止通路全够不到**，它唯一现实的出口是 sat
判定；而 sat 的检查点是 `layer_no % sat_every_n == 0`。研究层上限 4 时，间隔 3
只在**第 3 圈**查过一次（判「有新维度」）—— **第 4 圈（最后一圈）没有检查点**。
间隔 2 让检查点落在第 2 / 4 / 6…圈，最后一圈也被查到。

★ **历史风险（必须说）**：出厂 yaml 的注释里留着 v1.21.48 / v1.21.49 的实测记录 ——
间隔 **2** 曾让研究层**第 2 圈就停**、可判定覆盖率只有 **33%**；v1.21.49 把间隔
放宽到 **3** 才让它走到第 3 圈。本版回到 2 是**有意**的（间隔 3 漏检查点），
但这条老风险客观存在 ⇒ 已写进 yaml 升级段，并给了「改回 3」的回退路径。
两版真跑读数见 §五。

### 2.2 soft_max 3 → 2（`spiral.soft_max`）

改 5 处：`DEFAULT_CONFIG` + `_run_layer` / `_init_b_state` 两处缺省 +
`plan_resources` / 方法级 `_auto_plan` 两处（后两处只用于 prompt 里的
「圈数区间：soft～hard」文案）。

**为什么**：`soft_max` 是两件事的闸门 ——
① 条件 6「自然安住」要求 `layer_no >= soft_max`；
② 条件 1 的**推迟**（早圈不许停）也要求 `layer_no >= soft_max`。
降到 2 ⇒ 两者都从第 2 圈起生效。

### 2.3 条件 1（复述 / 自省点名未消化）四层通用 —— **两处**改动

**(a) `_stop_reasons`**：去掉 `if entry in ("all", "both"):` 这个门外，整段缩进回一层。
`layer_no < soft_max` 的推迟**保留**。

**(b) `_apply_view_to_pool_locked`**：★ 这一处是「改了门槛也等于没改」的关键 ——
`_stop_reasons` 用的是 `rephrase_streak`，而它由 `_compute_rephrase_streak(view, state)`
算出，读的是 `state["meta_idle_streak"]` 与 `view._meta_idle_streak`。
**这两个载体只对 `all` / `both` 累加**（同一函数里的 `if _is_meta_or_duel … else …`
分叉），所以 0 / 1 层的 `rephrase_streak` 结构性恒 0。
本版在该 `else` 分支末尾补一行 `view._meta_idle_streak = rephrased_streak`
（`try/except` 与元层同款），**不改 `view.idle` 的既有语义**。
⇒ 条件 1 的**两半**（复述 / 自省点名）这才同时对四层生效。

实测（§五 探针）：带 `carry_streak=2, rephrase_streak=2` 调 `_stop_reasons`，
改前 `entry="0"/"1"` 返回空，改后返回「ing 连续 2 圈复述… + 自省连续 2 圈点名同一批
问题未消化…」。

## 三、修掉两个 v1.23.16 引入的真缺陷

### 3.1 判据死代码：约 90 行 / 33 条语句**从没跑过**

**现场**：`check_v12316_stop_therapy`（v1.23.16 新增）的**第一条顶层 `return` 在
第 1130 行**，而它下面还有 33 条语句（1132–1221）—— 那是 `check_cost_profile` 的
原 body。v1.23.16 的计划是「把 `check_cost_profile` 整条重写为
`check_v12316_no_profile_dimension`」，实现时**连它里面与成本档无关的判据一起丢了**：

- 覆盖率双口径（可判定通道：自评折算 + 代码实算 2/3；不可判定通道：清晰度 +
  结构覆盖率 + 两通道并排 + fallback）
- 不可判定命中轨迹（`struct_trace` 圈号 / 逐圈命中数 / `aspect_first_hit` / `newly`）

它们成了死代码，`✗` 永远不打印、`✓` 也永远不打印 —— **静默到底**。

**为什么当时没发现**：`ast.parse` 通过（缩进合法）、脚本退出码 0、冒烟
`exit 0 / 0 ✗`。唯一的线索是 ✓ 数从 210 掉到 207 —— 而那一版**没有对照规模**。

**修法**：恢复成 `check_v12317_und_coverage_trace()` 并在 `main()` 接线，
只把 `✓` 文案里已不存在的「成本档 / 探针按角色跳」半句去掉。
并在注入器里加一条**自检**：`return <常量>` 之后还有语句 ⇒ 直接断言失败。
（实跑：恢复后该函数判绿 —— 说明那段判据本身没坏，只是没跑。）

### 3.2 两处夹具把「停止」当成了常量

本版让 0 / 1 层更容易停 ⇒ 两个夹具的「层会跑满 N 圈」假设当场失效：

| 夹具 | 现象 | 处置 |
|---|---|---|
| `[P1-6 补]` errors 跨圈累积 | 研究层（上限 3）改后**第 2 圈就停**（停因含条件 1），「晚写者 3/3」→ 2/3 | **固定停止变量**：`soft_max=99`（同时关掉条件 1 的推迟与条件 6）+ 三条 idle 阈值 99 + 关 sat ⇒ 实测 0 层 2 圈 / 1 层 3 圈 |
| `[v72 #13]` 预算耗尽 barrier | 修行层改后**自然停**（条件 1 +「产物相似度高」），「四层都带预算用尽」→ 3/4 | 同上固定 ⇒ 实测预算 30 → 四层全带「预算用尽」、预算 0 → 0 层 |

★ 两条都是**固定该变量**，不是把期望值改小（项目纪律：预期不该跟着实现漂）。

## 六、未做 / 遗留（如实记账）

1. **v1.21.48 的「间隔 2 ⇒ 覆盖率 33%」风险未在本版被单独测**：本节真跑只给了
   停止行为与成本，**没测可判定覆盖率**。要证或证伪这条，需要把研究层的
   `可判定覆盖率` 逐跑对上（`_coverage_segment` 的读数）。
   —— 本版**未做**，如实记。
2. **修行层（0）的复述理由文案仍写「ing」**：那是元 / 对撞层的用词
   （`_compute_rephrase_streak` 的 docstring 也这么写）。改文案要动判据锚点，
   本版不动。属**文案债**。
3. **条件 1 对 0 层的语义**：修行层「不追求收敛」是既有红线，而条件 1 现在也能让
   0 层停（`layer_no >= soft_max`，soft_max=2）。本版按用户指令执行，
   行为变化已如实记录。
4. **`_apply_view_to_pool_locked` 里两条 streak 载体并存**（`rephrased_streak` 给

   `view._meta_idle_streak`，**没有合并**这两个载体。属结构债。
5. **冒烟的 P1-6 / #13 夹具靠「抬阈值」隔离停止**：这是在夹具侧抵消本版的
   默认变化；若将来再加早停通路，这两处仍会先红（这是设计意图）。

## 七、经验教训

1. ★★ **`return` 之后的语句是死代码，而 `ast.parse` 照样通过**。v1.23.16 把
   `check_cost_profile`「整条重写」时丢掉了 33 条语句，冒烟仍然
   `exit 0 / 0 ✗` —— 唯一的线索是 **✓ 数从 210 掉到 207**，而那一版没有对照规模。
   ⇒ **改判据（尤其重写某个 check 函数）后，必须比对 ✓ 数与上一版**；
   并给注入器加「return 之后不许有语句」的 AST 自检（本版已加）。
2. ★★ **改了「早停」，所有「跑满 N 圈」的夹具都会先红**。修法是**把停止这个变量
   固定住**（抬 `soft_max` / 抬 idle 阈值 / 关 sat），**不是**把期望圈数改小。
   本版两处夹具修改都写了实测读数佐证（0 层 2 圈 / 1 层 3 圈；预算 30 → 四层全带）。
3. ★★ **「去掉一个 if 门槛」不等于「判据生效」**：条件 1 的另一半（复述圈数）
   由**另一个函数**维护，而它只对 `all`/`both` 累加。改门槛前先 grep「这个判据读的
   变量是谁写的、对谁写的」—— 否则会做出「门槛去掉了、行为没变」的静默改动。
   ★ 本版探针的 `D_` 段就是为这条设的（改前读回 0 / 改后读回 2）。
4. ★★ **同一个键在「引擎默认」与「出厂 yaml」里可以不一致**，且**没有任何判据
   看得见**（登记表只要求「差异已登记」，不管差异是不是笔误）。
   `structure_saturation_every_n` 默认 3 / yaml 1 就这么活了很久 ⇒
   同一个版本「裸跑」与「带 yaml 跑」行为不同。**顺带统一**是本版附带价值。
5. ★ **改「默认值」要连带 grep 描述它的注释**：yaml 里那三段注释（「只在研究层与
   元层跑」「为什么是 3 不是 2」「原为过期值 2」）全都会在改后说假话。
6. ★ 变异体脚本里 `re.sub` 的替换串含 Windows 路径会 `bad escape \U`
   ⇒ 用 `lambda` 作替换（本项目第 N 次）。
