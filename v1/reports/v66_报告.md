## 一、[A] `_starve_rounds` 的写入语义：3 处写入收敛成「写一次、记一次峰值」

**改动**：`_starve_escalation` 原本有 3 处直接写 `sq["_starve_rounds"]`
（被触碰 → 0 / 无进展 → +1 / 升级走 → 0）。收敛成一个内部函数：

```
def _set_starve(_sq, _val):
    _sq["_starve_rounds"] = _val
    _pk = int(_sq.get("_starve_max_seen", 0) or 0)
    _sq["_starve_max_seen"] = _val if _val > _pk else _pk
```

⇒ 峰值 = `_starve_rounds` 在整段运行里**取到过的最大值**，两个清零点都带不走它。

**为什么不写成「在清零前各抄一次」**：3 个写入点里，**末圈那次 +1 没有
「下一圈」来抄它** —— 只有「写时即记」才不会漏。

**★ 峰值必须无条件写（这是被真跑抓出来的，见第六节）**：
若只在「抬升」时写字段，那么「字段存在与否」度量的是**峰值是否为 0**，
而不是「机制跑没跑」。G1q 首次真跑正是这样报了 `计数已写 1/6` 的**假覆盖**。

## 二、[B] `🍽` 行改成**加性**输出（旧探针不动，新探针另接）

**新格式**（前缀与旧格式逐字相同，只在中间插新段）：

```
- 🍽 无进展计数：最高 {本轮} 圈（{分布}）｜运行期峰值 {峰值} 圈（{峰值分布}）｜名下有挂账的子问题 {M} 条｜计数已写 {k}/{n} 条
```

**为什么选加性而不是改口径**：审计脚本 `_audit_v64_zero_triggers.py` 的机制一
正则吃的是从「🍽 无进展计数：最高」一直到「名下有挂账的子问题 N 条」的**整条**
—— 只保留前缀也救不了它。改口径会让已有探针**静默失配**，产出又一份
「看着像没触发」的空报告。所以：

- **产物侧**加性输出；
- **审计侧**把新增段全写成**可选组** `(?:…)?`，v1.21.65 的旧产物仍能解析。

## 三、[C] 覆盖计数：把「有渲染点且为 0」与「压根没这个渲染点」分开

**为什么必须加**：`_starve_escalation` 若没跑（该层没走到 / 开关为 0），
`_starve_max_seen` 字段**不存在**，而渲染取值带默认 0 —— 出来**同样是 0**。
也就是说：新加的峰值列**自己就会掉进本项目反复踩的那个坑**。

**做法**：行末补一列 `计数已写 k/n 条`，为 0 时显式写
「★ 计数未写（机制未运行）」。审计脚本把它读出来，并据此把「峰值 0」
**三分**：

| 情况 | 判读 |
|---|---|
| 覆盖计数为 0 | **机制未运行** —— 没有观测点，既不能说「差 2 圈」，也不能说「每圈都被碰过」 |
| 覆盖计数在（k=n>0） | **真 0** —— 机制确实每圈都跑了，该层子问题每圈都被碰过 |
| 无覆盖计数（老产物） | **无法区分** —— 显式声明，不硬判 |

## 五、★ 修正 v1.21.65 的一处推断

**v1.21.65 的说法**（载于其 changelog 与当日日志）：
> 条件一（连续 ≥2 圈没被碰）**在圈 4 达到过**（圈 3、4 都 `回答0`）。

**本轮的直接测量**：G1q 峰值只到 **1 圈**。

**为什么那条推断偏松**：`_starve_rounds` 认的「被碰」= 本圈的
`engagements` / `deferrals` / `escalations` / `reclassifications` / `resolutions`
—— 其中「深入（engagement）」「挂新账」「分类变更」**都算被碰**，范围比
「被回答」宽得多。所以「某一圈没人被回答」**不等于**「某个子问题连续两圈没被碰」。

**结论（以直接测量为准）**：机制一离触发差的是
**「再攒够到 2 圈」+ 条件二（名下有挂账）**，而不是「差一道更难的题」。
这与 v1.21.65 拍板的「设计上狭窄」一致 —— 但「离门槛多远」从**推断**变成了
**可测量**（峰值 / 门槛 = 1 / 2）。

## 六、★ 自伤缺陷：G1q 撞出 [C] 自己的假覆盖（已修 + 已复验）

**症状**：G1q 那行的 `计数已写 1/6 条` 是**假数**。

**根因**：`_set_starve` 第一版**只在「抬升」时写** `_starve_max_seen`
（`if _val > 旧峰值`）。于是：

- 某子问题若一直是 0（每圈都被碰）→ **永远不带字段**；
- ⇒ 「字段在不在」度量的是**峰值是否为 0**，而不是「机制跑没跑」；
- ⇒ **[C] 想防的正是这个病，[C] 的实现自己又犯了一次。**

**修正**：峰值**无条件写**（`_srm = _val if _val > _pk else _pk`，每次都赋值）。

**并补一条直调生产函数的单测**（不经产物，`check_v66_starve_writes_key`）：

1. 跑一次 → **每个子问题都带 `_starve_max_seen`**（= 1）；
2. 第 2 圈把 s1 标为「被触碰」→ 断言
   `[(_starve_rounds, _starve_max_seen) for s] == [(0, 1), (2, 2)]`
   —— 即**清零带不走峰值**。

**复验**：G1r 的 `计数已写 5/5 条`（见 4.2）。

## 十一、已知遗留与下一轮建议

1. **峰值是逐子问题存的**（`_starve_max_seen`），产物只报**全池最大与分布**。
   要看单个子问题的历史，读 pool JSON（字段已在）。产物侧是否要报
   「是哪个子问题够到过」—— 属格式改动，需单独一轮。
2. **机制一的裁决不变**：接受为「设计上狭窄」并保留（见 v1.21.65 遗留 2）。
   本轮把它的「离门槛」从推断变成了**可测量**（峰值 1 / 门槛 2）。
3. **条件二仍是瓶颈**：G1q 的「名下有挂账的子问题」= 0 条 —— 峰值够到 1 圈的
   那个子问题**名下没有挂账**。要在同一圈上两条都成立，仍需要「先挂账、
   再连着 N 圈没人碰」的题面，不可强求。
4. **短跑的 `--min-rounds` 未使用**：G1r 刻意只走 2 圈，用于验证覆盖计数，
   不代表研究层的自然停止行为；自然停止行为以 G1 / G1q 为准。

## 十二、经验教训（本轮三条）

1. **新增一个「计数列」时，必须同时加「这一列有没有被写」的自检。**
   否则新列自己就会变成下一个「看着像 0 的空报告」。★ 更狠的一点：
   **自检逻辑必须用「无条件写」实现，不能用「有值时写」** —— 本轮 [C]
   就是为防这个病而加，结果实现上又犯了一次，是**真跑**把它抓出来的。
2. **观测出口要报过程极值，不是瞬时终值。** v1.21.65 写下了这句话，
   本轮把它做完：问「离门槛差多少」要的是**过程极值**，而被测的
   `_starve_rounds` 是个会被清零的**瞬时量** —— 两者不是同一个对象。
3. **加性改产物格式比改口径安全。** 旧字段照用、新段另加，并让下游探针
   把新段写成**可选组**：老产物仍能解析，不会因为改格式而静默失哑。
   反例正是「改口径」会让已有正则**整条失配**。
