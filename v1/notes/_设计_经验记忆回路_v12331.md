# EML · 经验记忆回路（Experiential Memory Loop）· v1.23.31 设计

> 诉求：让元DGTF **储存记忆**，并在**每次运行中自我学习与迭代**。
> 本文件是设计依据 + 落地口径；实现见 `_mk_v12331_p*.py`，验收见 `v12331_报告.md`。

## 一、现状（为什么现在不是「会学」）

| 已有的 | 缺的 |
|---|---|
| `auto` 调度读 `outputs/*.packed.json` 的**统计量**（calls_med / cut_rate / 各层停圈 / 三态一致率 / 联网命中） | 只读**数**、不读**内容**：不知道「哪类经验有效」，也没有任何**经验条目** |
| `.workbuddy/memory/*.md`（人写的项目约定） | 机器**不回写**：跑完不产生可复用经验 |
| `CHANGELOG.md` + `_archive/v*/`（版本史） | 是**版本**记忆，不是**行为**记忆：下一版不会因为上版的失败自动改行为 |
| v1.23.30 的 `duty` / `duty_trace` 读数 | 读数**只留痕**，不参与「下次怎么跑」的决策 |

⇒ 缺口是 **经验层（episodic → procedural）** 与 **闭环（写回 → 生效 → 再验证）**。

## 二、前沿依据（2025，均已读到原文要点）

1. **ACE · Agentic Context Engineering**（Stanford / SambaNova / UC Berkeley，arXiv 2510.04618）
   - 三角色：**Generator / Reflector / Curator**；把上下文当**演化的作战手册**。
   - ★ **可用的反面数据**：把 1.8 万 token 的策略「总结压缩」成 122 token ⇒
     准确率 **66.7 → 57.1**。⇒ 两条铁律：**不要重写知识**；**增量条目（delta）
     逐条合并**，合并用**确定性逻辑**而不是「再让模型总结一遍」。
   - ⇒ 本设计的 playbook 采用 **append-only + 状态位（shadow/active/retired）**，
     永不重写、永不删除。
2. **Memory-R1 / Mem0**：写入决策二分 —— 抽取 salient 事实 → **ADD / MERGE / UPDATE /
   DELETE（含矛盾删除）**。⇒ 本设计把「矛盾」单独建档（不静默覆盖）。
3. **WebCoach**：WebCondenser 标准化 episode + Coach 把经验当**建议**注入
   （成功率 47%→61%，且**平均步数不增**）。⇒ 学习**必须双边记账**：
   只涨成本不涨质量 = 学坏。
4. **Expel / ReasoningBank**：从**成功与失败**轨迹里蒸馏**可泛化规则**（不只存实例）。
5. **MRRL · Memory-Reconsolidation Reflection Loops**（2025）：
   - **Layer B 记忆质量闸**：入长期记忆前评「事实支持 / 矛盾风险 / 预期效用 / 错位风险」，
     可 **拒绝 / 重写 / 隔离（quarantine）**；
   - **Layer C 多级反思**：micro（即错即改）/ meso（任务级错误模式）/ macro（可迁移原则）；
   - **forgetting sweeps**：定期遗忘清扫。
6. **SAGE**：用**艾宾浩斯遗忘曲线**决定记/忘。⇒ 与项目既有 `history_halflife_days=14`
   同源，本设计把半衰期**同时用于检索排序与遗忘判定**。

## 三、设计（EML）

### 3.0 与红线的对齐（先写清楚，再写代码）

- **输入是形状不是数据** ⇒ 记忆**只注入调度/探针/结构选择**（procedure），
  **绝不注入答案内容**（facts）。每条经验必须是「条件 → 动作」，不是「结论」。
- **悬置不打分 / 未对齐合法** ⇒ 记忆里**不记录**「哪条悬置好/坏」。
- **失败留痕** ⇒ playbook append-only；retire 只改状态位，不删行。
- **入池前挡重复** ⇒ 复用既有 `_DUP_SIM` / 语义归并阈值 0.85 做去重与聚合。
- **参数按层可覆盖** ⇒ 记忆给出的建议（如 rounds）仍走既有「按层覆盖」链。
- **默认零行为差** ⇒ 出厂 `playbook.mode = shadow`（记录 + 报告，**不生效**）。

### 3.1 存储：`dgtf_memory/`（新增目录）

| 文件 | 内容 | 口径 |
|---|---|---|
| `episodes.jsonl` | 每次跑的**标准化 episode**（append-only） | `{run_id, t, q_features, route, mode, rounds, cut_layers, duty{层→S}, tri_rate, cost{tokens,calls}, cand_ids}` |
| `playbook.jsonl` | **增量经验条目**（append-only，状态位演进） | `{id, kind, cond, action, evidence[], readings{before,after}, status, weight, t_written, t_used[], contra[]}` |
| `stats.json` | 聚合读数（可重建，非权威） | 由 episodes 聚合 |
| `MEMORY.md` | 人可读摘要（自动生成） | active/shadow 分类列 |

`kind` 四类（对齐 MUSE 的分层 + 本项目机制面）：
`schedule`（路由/模式/圈数/预算）· `probe`（探针取向）· `structure`（结构/属性选择）·
`guard`（停止/职责守卫阈值）。

### 3.2 读（跑前 `recall`）

排序分（Generative Agents 的 retrieval score 结构，此处原创为三元）：
```
score = recency^0.5 × evidence_strength × kind_relevance
  recency          = 0.5 ** (Δdays / halflife)      ← 与 history_halflife_days 同源
  evidence_strength= 1 - 0.5 ** n_evidence          ← 证据条数越多越硬
  kind_relevance   = 该 kind 是否对本题型可判（规则）
```
- `mode = off` ⇒ 不读不写（完全关）；`shadow` ⇒ 读出来**只留痕不生效**；`on` ⇒ 生效。
- **生效面**（只在这三处）：① 调度建议（route/mode/rounds/预算档，仍走「显式 > 配置 >
  记忆 > auto > 默认」链的**新一级**，位于 auto 之下）；② 探针取向偏置；
  ③ 守卫阈值（`duty.floor` 等，仍按层可覆盖）。
- **留痕**：`view.used_lessons` / 产物头部「本次记忆」块；episode 里记 `used_ids`。

### 3.3 写（跑后 `consolidate`）

**micro**（即错即改）：从本跑产物抽候选，规则化、**必须带读数**：
| 触发 | 候选动作 |
|---|---|
| 某层 `cut`（体力耗尽） | `schedule/rounds` 该层 +1（或提示预算档偏低） |
| 某层 `duty.S < floor` | `probe/carve` 先做问项抽取再进层 |
| `web_fail > 0` | `schedule/web` 降档或提前关 |
| `tri_rate < 0.33` | `guard/decidable` 该题型标记三态不稳（不参与判据） |
| `cost > p75` 且 `duty` 未升 | 记**负面**条目（学坏的证据，留痕） |

**质量闸（Memory Quality Gate）四问**（MRRL Layer B，逐条必须过）：
1. **事实支持**：候选是否引本跑的**具体读数**？（无读数 ⇒ 拒）
2. **矛盾检查**：与已有 `active` 条目是否矛盾？（矛盾 ⇒ 进 `contra`，**不覆盖**；
   `contra` 达 `promote_n` 才允许翻案）
3. **预期效用**：动作是否**可被后续跑验证**？（必须能定义 before/after 读数 ⇒ 否则拒）
4. **错位风险**：动作是否**触碰红线**（打分/拦悬置/注入答案）？（触碰 ⇒ 拒并留痕）

**meso**（任务级模式）：同 `(kind, cond)` 的候选累计**同向**证据 ≥ `promote_n`（默认 3）
⇒ `shadow → active`；出现反向证据 ⇒ `weight` 降，降到 0 ⇒ `retired`。

**macro**（可迁移原则）：多条同类 `active` 用**确定性聚合**（sim3 ≥ 0.85 才合并，
沿用 v1.23.30 既有阈值）生成 `parent` 条目 —— ★ **不重写、不压缩原文**
（ACE：压缩会掉分）。父条目只做索引。

**遗忘清扫（forgetting sweep）**：`retired` 判定 =
`recency < 0.05` **且** `t_used == []` **且** `n_evidence < promote_n`；
清扫只改状态位，**不删行**。

### 3.4 学坏防线（五条，每条都要有判据）

| 防线 | 机制 | 判据 |
|---|---|---|
| F1 隔离 | 新条目默认 `shadow`，不生效 | 影子条目不进生效面（负对照：`mode=shadow` 时行为与 `off` 逐字相同） |
| F2 双边记账 | 每条记 `{cost_delta, quality_delta}`；**只省成本 ⇒ 不升级** | 构造「只省成本」候选 ⇒ 断言**不** promote |
| F3 一键关/降级 | `playbook.mode ∈ {off, shadow, on}` | `off` ⇒ 不读不写；`shadow` ⇒ 只写不生效 |
| F4 遗忘 | TTL + 半衰期 | 陈旧低证据条目 ⇒ retired（且行仍在） |
| F5 只增不删 | append-only + 状态位 | 任意操作后行数**单调不减** |

### 3.5 验收设计

- **纯函数**：`episode_from_result` / `gate_check`（四问，各配负样本）/ `recall_rank` /
  `promote`（正负两向）/ `sweep_forget`（两向）/ 聚合去重。
- **真实入口**：跑一次 mock → 断言 `episodes.jsonl` 落一行 + 候选过闸；
  **第二次**跑 → 断言「本次记忆」留痕（`used_ids` 出现）。
- **变异体 ≥9**：闸门四问各一个恒真/恒假、promote 门槛、双边记账、append-only、
  recall 排序、mode 三态。
- **构造性证明「会学」**：用同一个 mock 跑 **N=4 次**，第 1 次 `shadow`、
  之后 `on`，断言第 4 次「用了 ≥1 条 active 经验」且读数被记录
  （**不是**断言「分更高」—— 红线：只升不降的指标是自欺）。
