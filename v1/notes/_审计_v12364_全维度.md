## 1. 基线与复现

在**强制 UTF-8**（`PYTHONUTF8=1`）下，V1.23.63 的三道门是绿的：

| 门 | 结果 |
|---|---|
| 冒烟 `smoke_test.py` | 264 ✓ / 0 ✗ |
| 跨档验收 `_v122_verify.py --phase all` | PASS 319 / FAIL 0 |
| 工程审计 `_probe_v1232_audit.py` | PASS 69 / FAIL 0 |

而**本机默认环境**（不设 PYTHONUTF8）下，第一道门直接失败：

```
python _run_gate.py _gate_base_v12363.log -- python smoke_test.py
# EXIT=1
# UnicodeEncodeError: 'gbk' codec can't encode character '\u2713'
```

这不是测试逻辑错，是**可移植性缺陷**：门禁在成功之后自己崩了，把成功报成失败。

## 2. critical：GBK 编码面（14 条）

根因一句话：Windows 下 stdout 被重定向到管道/文件时，Python 用 locale（cp936）；
本项目第一条 print 就带 ✓/✗/emoji ⇒ `UnicodeEncodeError`。

| 文件 | 证据 | 影响 |
|---|---|---|
| `_run_gate.py` | 打印 `EXIT=…` 时崩 | **门禁假失败**（命令成功但退出码 1） |
| `bench/bench_calibrate.py` | `print(f"✓ 导出 …")` | 三态校准导出/回填不可用；冒烟 v1.22 阶段2 因此红 |
| `bench/bench_diff.py` / `bench_report.py` / `bench_run.py` | 用法/统计行含中文 | bench 全链路在默认终端不可用 |
| `_v122_verify.py` / `_probe_v1232_audit.py` / `_mut_v12332.py` | ✅/── 判据行 | 三道门在默认终端不可跑 |
| `dgtf_app/server.py` / `dgtf_app/selftest.py` | 口令提示/自检行 | 本地工作台首次启动即崩 |
| `_probe_gain_dist.py` / `_probe_gain_live.py` / `_run_matrix_v12333.py` / `_git_save.py` | 读数行 | 实验脚本不可复跑 |

**修法**（已落）：每个入口在模块加载期把 stdout/stderr 切到 UTF-8（`errors="replace"`），
并给子进程 `setdefault` `PYTHONUTF8=1` / `PYTHONIOENCODING=utf-8`。
主文件的 `_force_utf8_streams()` 同时承担这两件事；`_run_gate.py` 另把子进程输出按 UTF-8 落盘。

**验证**：同一命令在默认 GBK 环境下重跑，退出码与日志都正确（见 `v12364_报告.md` §五）。

## 3. major

### 3.1 子进程编码（3 条）

| 文件 | 问题 | 修法 |
|---|---|---|
| `smoke_test.py` | 调审计子进程未注入 UTF-8 环境 | 注入 `PYTHONUTF8`/`PYTHONIOENCODING`，并用 `SRC` 取代过期回退版本名 |
| `_run_gate.py` | 子进程继承 locale | 同上 + 显式 `env=` |
| `dgtf_app/docparse.py` | `subprocess.run(capture_output=True)` 未固定 | 输出已显式 decode，风险低；留作残余 |

### 3.2 「except Exception 静默处理」115 条：不是 115 个 bug

审计器按 AST 数出 115 处 `except Exception: pass`（或等价静默返回）。
逐条看，大体分三类：

1. **守卫型**（合理）：如 `_force_utf8_streams` 的 reconfigure 失败跳过、
   `dgtf_app` 里带 `# noqa: BLE001` 的「读不到不影响主流程」。
2. **数据路径型**（真问题）：`_load_bandit` 解析失败静默归零（学习被抹掉）、
   `_save_bandit` 返回 False 但调用方不看、`eml_append_jsonl` 失败静默、
   `eml_write_memory_md` 失败静默。这些直接违反红线「失败留痕」。
3. **兜底型**（可接受但要留痕）：调用外部 LLM/联网失败后走 fallback。

本轮只修了**能量化证明**的那几条（EML 读写/锁/重试）；其余列在 §5 残余风险，
不装作一次审计就能清完。

### 3.3 EML 耐久性（真缺陷，已修）

| 缺陷 | 证据 | 后果 |
|---|---|---|
| 整表重写非原子 | `_eml_finish` 新增行时裸 `open("w")`；`eml_rewrite_jsonl` 同样先截断 | 崩溃/断电 ⇒ 半截 jsonl；坏行又被跳过 ⇒ **静默丢证据** |
| 只增不删只靠断言 | 新行分支不走 `eml_rewrite_jsonl` 的行数/id 校验 | 理论上可绕过 F5 |
| 锁失败仍裸奔 | `_lk.__enter__()` 的返回值没人看 | 并发真跑时可能**无锁读-改-写** |
| 陈旧锁只看 mtime | 长跑持锁 > 900s 会被第二个进程抢走 | 互斥失效；释放时还会误删别人的锁 |

修法：`tmp + os.replace` 原子写；`allow_grow=True` 统一「只增」；锁文件写
`pid:token`、回收前问活进程、释放只删自己的、超时改 `monotonic`。

### 3.4 LLM 重试（真缺陷，已修）

| 缺陷 | 证据 | 后果 |
|---|---|---|
| 4xx 也重试 | `except Exception` 一视同仁 | 参数错/鉴权错重试 3 次，白烧钱与时间 |
| 无抖动 | `time.sleep(backoff ** attempt)` | 并行分层同拍重试（thundering herd） |
| 分母用错 | 日志/条件用 `self.max_retries`，循环用 `_tries` | `max_retries=0` 时日志写 0/0 |

修法：4xx（除 408/409/429）不重试；抖动 `[0.5,1.0]×backoff`；尊重 `Retry-After`（≤60s）；统一 `_tries`。

### 3.5 文档漂移（真缺陷，已修）

| 位置 | 写的 | 实际 |
|---|---|---|
| `README.md` | 当前 `V1.23.61`、26819 行、冒烟 263 | 审计时已是 V1.23.63 / 26857 行 / 264 |
| `smoke_test.py` 审计回退路径 | `元DGTF-V1.23.3.py` | 旧版（文件在，但早已不是当前版；现改回 `SRC`） |

README 的「只写能被验证的事」这条自我要求，在这里被自己的版本号破了。

### 3.6 统计口径保守（设计取舍，不是 bug）

`stitched_hoeffding_lower` 是有效的 anytime-valid 下界，但小样本偏保守。
真实序列上（51 条 / 245 圈），e-process 比它**多判出 4 条**、没有反向；
合成仿真里同时判时中位省 17 圈（37 vs 54）。因此新增 `stop.anytime_mode=evalue`
作为 opt-in，默认仍走 hoeffding（零行为差）。
