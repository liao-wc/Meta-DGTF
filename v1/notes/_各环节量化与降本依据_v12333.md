# 各环节量化 + 降本 · 前沿依据与落地方案（v1.23.33 第六期）

> 用户指令：「检查各个步骤中是否可以弄一些量化的知识点或者关键点或者是依据，
> 或者输出是否是最优解。比如锚点重述…是否也有相关依据佐证，阴阳展开也是否有
> 依据，各自输出内容是否最优，比如 ing 中应该输出什么内容，view 的输出重点应该
> 是什么等等。**以及整体过程是否是最优的，是否可以减少 LLM 调用，或者降低
> 成本**，毕竟这是一个消耗的过程。」

## 一、检索所得（四条硬依据）

### 依据 1 · 重述失真会毁掉整条下游链（→ 锚点重述）
**BenchDrift: The Wording Effect**（Thakur et al., arXiv:2608.11694, IBM）：
- 含义保持的重述 ⇒ 答案**双向漂移**，最强模型**损失远大于收益**（脆弱的不是模型，是重述本身）。
- **Revisiting the Reliability of LM in Instruction-Following**（arXiv:2512.14754）：
  同一意图换措辞 ⇒ 指令跟随率**最多掉 61.8%**；提出 `reliable@k` = 对 k 个同义变体
  是否**同时**做对。
- ⇒ **落地**：锚点重述必须**量化保真度**；不达标的对面下游全部白跑（那才是最大的浪费）。
  这是**降本**的最上游闸门：**一次重述校验 ≪ 一整轮跑偏的代价**。

### 依据 2 · 阴阳是否真「对立」（→ 阴阳展开）
**SIEV: A Dialectical View of LLM Reasoning**（arXiv:2510.18134）：
- 核心指标 **对抗性依从率（adversarial compliance）**：反题与正题**实际不一致**的比例。
- 「过于胆怯」的模型 **pS 高但推理深度低** —— 即**假对撞**（只是换个说法复述）。
- **Hegelian Self-Reflection**（arXiv:2501.14917）：辩证需**明确的缺陷类别**
  （未定义构成要素 / 内容不完整 / 不兼容性 / 自我决定不完整）。
- ⇒ **落地**：量化「阴阳**分歧度**」；分歧过低 ⇒ 这一对**没产生新信息**
  ⇒ 触发下游的**低成本路径**（降本点）。

### 依据 3 · 用早期信号提前停掉低价值样本（→ 减少 LLM 调用）
三条独立证据指向同一机制：
- **RASC**（Wan et al., NAACL 2025）：基于「推理质量 + 答案一致性」的
  **criteria-based early stopping** ⇒ **省 ~70% 采样**。
- **DeepConf**（ICLR 2026）：**局部**置信窗口（最差片段）作早停触发
  ⇒ 省 **84.7% token**、准确率**还升**。★ 关键洞察：**全局平均会掩盖局部塌陷**；
  塌陷是**局部的**（「wait / however / think again」连发 = 推理流被打断）。
- **Think@n**（arXiv, UVA+Google）：只解**短前缀**（50 token）算 DTR
  ⇒ **只继续解码 Top-K** ⇒ 成本 **−49%**，准确率持平或更好。
- ⇒ **落地**：阴阳两臂**先跑一臂**，用**早期信号**判另一臂是否值得跑
  （这在**已有并行实现**下就是一开关）。

### 依据 4 · 语义密度 / 信息瓶颈（→ ing 输出与 view 重点）
**Information-Theoretic Principles for Prompt Engineering**：
- **提示压缩率** `R = I(X;Y) / H(X)`，优秀提示 `R > 0.6`。
- **语义密度**：每个 token 承载的任务相关信息量；**超过 5 个无信息 token
  ⇒ 性能降 15%+**。
- ⇒ **落地**：ing（进行中）输出与 view 重点，都该按**语义密度**筛
  ——低密度内容**不进 prompt**（直接省输入 token）。

### 依据 5 · 降本策略的**叠加顺序**（→ 全局最优）
**Tokonomics 2025 生产案例**：单策略 30~50%，**叠加达 85%**；推荐顺序：
① **批处理**（半天工作量，立即省 50%，**零功能代码改动**）
② **Prompt 缓存**（静态前缀 50~90% 折扣）★ 要求**静态内容在前、动态在后**
③ 模型路由 ④ 提示压缩 ⑤ 输出长度控制 ⑥ 语义缓存

## 二、现状核查（★ 本仓库实测，不是推测）

| 项 | 现状 | 结论 |
|---|---|---|
| `_expand_pair_merged_once`（阴阳合并成一次调用） | **孤儿函数**（v1.23.16 删档造成，历史文档明记「未删」） | **能力存在但不可达** = 本项目第 1 类失败。**接线即可省一次往返 + 整份重复 user 输入** |
| 并行展开 | 已实现（`parallel_expand`） | 只省**往返**，不省 **token**（两份 user 各发一遍） |
| 锚点重述 | 有 `refchecker` 离线解析，**无「与原问题保真度」读数** | 缺依据 1 的闸门 |
| 阴阳分歧度 | 无读数 | 缺依据 2 的量化 |
| 早停（省采样） | 每圈阴阳**都跑** | 缺依据 3 的降本 |

## 三、落地（本期实施，全部「可开关 + 有读数 + 有留痕」）

### L1 · 激活阴阳合并（**零新增机制**，纯接线）
- `expand_pair.merge_once`（配置键，默认 **false** ⇒ 零行为差）。
- 开启时：一次调用拿两臂 ⇒ **省 1 次往返 + 1 份 user 输入 token**。
- 兜底已在（缺标记则补跑），最坏退化 = 现状，**不亏**。

### L2 · 阴阳分歧度读数（依据 2）
- `yin_yang_divergence(cands_yin, cands_yang)` → `{divergence, n_yin, n_yang,
  n_shared, verdict}`（纯函数）。
- `divergence` 低（< 0.3）⇒ 判 **`fake_duel`（假对撞）**，只出**读数与提示**。
- ★ 红线：**不改产物、不删候选**（悬置不打分）。

### L3 · 锚点重述保真读数（依据 1）
- `restate_fidelity(question, anchor)` → `{fidelity, coverage, verdict}`
  （纯函数，基于关键词覆盖 + 长度比，**不调 LLM** ⇒ 零成本）。
- `verdict` ∈ `ok / thin / drifted`。只出读数与告警。

### L4 · 语义密度读数（依据 4）
- `semantic_density(text) -> float`（纯函数）：
  内容词占比 / 每 token 的信息量代理（**不调 LLM**）。
- 用于 ing 输出与 view 重点的**质量线索**（进现成的 `quality_hints`）。

## 四、判据与变异体

| 编号 | 判据 |
|---|---|
| ㉗ | 合并开关：默认关 ⇒ 走原路径（两臂各一次）；开 ⇒ **一次调用**（真实入口产出） |
| ㉘ | 分歧度：低分歧判 `fake_duel`、高分歧不判；**样本不足不表态** |
| ㉙ | 保真度：漂移判 `drifted`、正常判 `ok`；**缺输入不表态** |

## 五、降本账（可核算）

以真跑实测 `_fullrun_GOALRUN` 为基准：**136 calls / 1.27M tok / 57.2min**。
- L1 合并开启（四层 × 每圈 1 次展开，2 圈估）：**约省 8~16 次调用**
  （≈ 6~12% calls），并省掉等量 user 重复输入。
- L4 语义密度筛 prompt：按依据 4 保守估 **省 5~15% 输入 token**。
- 合计：**calls −6~12% / 输入 token −5~15%**，且**不改任何停止/判定语义**
  （读数与开关皆 opt-in）。
