## 一、前沿依据（检索所得，逐条对应落地）

### 1.1 ★★ E³-Agent（arXiv 2605.27428, 2026）—— **快慢双路径 + 显式控制面**

> 把**毫秒级调度**（fast-path router）与**事件驱动的 LLM 元控制器**（slow-path
> meta-controller）**分开**，两者通过**一个小的、显式的控制面**（tool interface：
> 风险门 / 路由器配置 / 快速性能标定）连接；**从执行反馈在线学习**，持续适应
> 未知且时变的映射。

⇒ **这就是「自由调度与自我学习是一体的」的工程形态**：
- 「自由调度」= **fast path**（每圈/每层的即时决策）
- 「自我学习」= **slow path**（元控制器）
- 「可控 + 可追溯」= **显式控制面**（所有调整只经它，一处收口）

**落地**：`ControlSurface`（本方案 §三.2）。

### 1.2 ★ Heartbeat-Driven Activity Scheduling（arXiv 2604.14178, 2026）

> 用**周期性「心跳」**主动编排认知模块（Planner / Critic / Recaller / Dreamer），
> **不是**等失败才反思（reactive）；调度策略由**历史交互日志元学习**持续改进；
> 模块可**运行时增删**，无需结构改造。

⇒ **落地**：把 `_before_round`（**已经是**两条通道共用的「圈前统一动作」）
升格成**心跳**：每圈**主动**检查「要不要做点什么」，而不是等异常。

★ 该文作者的自我批评也值得记：**「有效性全靠断言、没有数字」** ⇒
我们落地时必须配**判据 + 变异体**，不许只写机制不写证据。

### 1.3 ★ MetaClaw（arXiv 2603.17187, 2026）—— **双时间尺度学习**

> **快适应**：从**单次失败轨迹**合成「技能」（自然语言规则），**零停机**注入 ⇒
> 立即改善；**慢适应**：梯度级策略优化，由**机会式调度器**在空闲窗口触发。
> 两者**互相强化**。

⇒ **落地**：EML 已有「快」（`_eml_note_contra` 记反面证据）与「慢」
（`playbook.jsonl` + `shadow→on` 升格）⇒ **补齐「快适应」的注入闭环**。

### 1.4 ★★ 可追溯：三层模型 + 决策链 + **不采样**

| 依据 | 要点 |
|---|---|
| **Agent Observability 三层**（zian.ai） | **L1 推理/决策 trace**（回答 *why*：看到了什么、**考虑过哪些选项**、置信度、什么定夺）；**L2 工具/动作日志**（*what*）；**L3 结果归因**（*did it matter*） |
| **OpenTelemetry GenAI 约定**（2026） | agent 专属 span：`invoke-agent` / `plan` / `execute-tool`；**`decision.chain` span kind**：记录**每步候选动作的分布**，审计能看见**「没走的路」** |
| **Decision Log Format (DLF)**（2026.04 提案） | JSON schema 含**每个被考虑动作的内部评分** ⇒ 不只看到选了什么，还看到**为什么否掉其他** |
| **Observing ≠ Auditability**（specswriter） | 观测平台会**采样/截断/14 天滚动删**；**审计级 trace 不许采样** —— 差异在**保留期 / 不可篡改 / 完整性** |
| **95% 盲点** | 「**不到 5% 的部署 agent 记录了每次生成的 temperature / top-k / seed**」—— 多数框架把它们当环境变量而非**可追溯属性** |

⇒ **落地**：`view.trace()` 三层 + **决策含被否选项** + **参数全记** + **不采样不截断**。

## 二、融合设计（一张图）

```
┌─ Fast path · 心跳级（圈） ─────────────────────────────────────┐
│  _before_round  ← 升格为「心跳」                                │
│    ① 主动检查（读读数 + 读 EML，不等失败）                       │
│    ② 出「本轮调整」                                            │
│    ③ 全部经 ControlSurface 落地（白名单 / 边界 / 必留痕）         │
│    ④ 写 trace：L1 decide（含被否选项）+ L2 动作                  │
└───────────────────────────────────────────────────────────┘
                        ↕ trace（单向：fast → slow）
┌─ Slow path · 元层（跑 / 跨跑） ───────────────────────────────│
│  元层 + EML + AutoTune                                         │
│    ① 从 trace 汇总「什么条件下调什么有效」（含 L3 归因）           │
│    ② 写 EML 条目（web_policy / carve_first …）                  │
│    ③ 出下一跑的**初始策略**（★ 只建议，不自动落地）                │
└───────────────────────────────────────────────────────────┘
```

**一体的关键是「闭环」**：fast 的每次调整都留痕 ⇒ slow 从留痕学 ⇒
slow 的结论成为下一次 fast 的**初始条件**。没有 trace 就没有闭环 ——
所以 **trace 是地基中的地基**。

## 三、三件地基（P1，每一件都可独立验收）

### 3.1 `view.trace(kind, **kw)` —— 三层 + 决策链

| 层 | kind | 关键字段 |
|---|---|---|
| **L1 决策**（why） | `decide` | `what` / **`options`（考虑过的全部选项）** / `chosen` / `why` / `conf` |
| **L2 动作**（what） | `llm` / `web` / `judge` / `pool` / `stop` | 各自参数与结果 |
| **L3 归因**（matter） | `outcome` | `ref` / `reading_before` / `reading_after` |

**四条纪律**：
1. **记被否选项**（DLF / `decision.chain`）—— 不只记选了什么；
2. **LLM 调用记全参数**（`model` / `temperature` / `max_tokens` / `thinking` /
   `trunc` / `degraded`）—— 补那 95% 的盲点；
3. **不采样、不截断**（审计级；红线「失败留痕」的延伸）；
4. **空值不表态**（没发生的事不写壳条目 —— 与 quant_readings 同纪律）。

### 3.2 `ControlSurface` —— 所有调度调整的**唯一收口**

```python
surf.read(key) -> 当前值
surf.write(key, val, why, trace_ref)   # 白名单 + 边界 + 必留痕（缺 why 直接拒）
surf.revert(key)
surf.snapshot() -> dict                # 进产物（可对账）
```

**白名单与边界**（可被调度器调的参数）：

| key | 边界 | 谁调 |
|---|---|---|
| `web.<stage>.allow` | bool | 心跳 / EML |
| `web.quota.per_stage_round` | 1..5 | 心跳 |
| `rounds.<layer>` | 1..`hard_max` | EML（已有 `rounds_delta`） |
| `duty_floor` | 0..1 | EML（已有） |
| `stop.anytime_alpha` | 0..0.5 | 心跳 |

★ **白名单外一律拒且留痕**（可控性的本体）。
★ **绝不写配置**（红线：建议与执行分开）—— 只改内存态；产物里留 `control_snapshot`。

### 3.3 心跳级调度 `_schedule_tick()` —— 主动，不等失败

挂在 `_before_round`（**已是**两条通道共用的唯一实现）：读
`quant_readings` + EML ⇒ 出调整 ⇒ 过 `ControlSurface` ⇒ 写 trace。

**首批规则（三条，都可判据化）**：

| 条件（读现有读数） | 调整 | 依据 |
|---|---|---|
| `candidate_yield.collapsed` | `web.<该层相关 stage>.allow = True`（放宽找新东西） | 产出率低 = 复述多 |
| 职责不足（`duty` 读数低） | 启用 `carve_first`（**修 EML 空转**） | EML 条目已有、无应用点 |
| 停滞（`sem_stagnation`） | 允许探针（`probe` 相关 stage） | 停滞 ⇒ 需要外部刺激 |
