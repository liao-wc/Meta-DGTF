# Meta-DGTF-道生三阶模型 · 来源与定义

## 1. 一句话定义

Meta-DGTF-道生三阶模型是一个**自相似的、四相完整的、方法统一的、默认全留但可覆盖的、三通道记忆的、领域开放的、会记得自己的 DGTF**。

它把“修行 / 研究 / 对撞 / 元”四种认知模式做成四个并列入口，每层用同一套“锚点 → 展开 → 对偶判断 → 对撞 → 沉淀 → 探针 → 显形”的方法，螺旋推进，并在 V2 中拆成“知识面 EML、控制面 Scheduler、执行面四层契约”三个职责分离的平面。

## 3. 四层各自做什么

| 层 | 目标 | 必须留下 | 不做什么 |
|---|---|---|---|
| 0 修行 | 把潜在方面摊开 | 方面图、悬置、探针、novelty | 不替 1 下结论 |
| 1 研究 | 对可判定子问题给出带不确定性的答案 | 答案集、弃权、覆盖、引用、债务 | 不闭合决策、不行动 |
| both 对撞 | 在论证场里消解或保留张力 | 综合、论证图、张力集、败方 | 不强行裁决、不删败方 |
| all 元 | 决策级闭合 | 决策、动作、不做、残余风险、provenance、置信 | 不重写前层、不编造闭合 |

三通道：content（写了什么）、context（凭什么写）、self（自己怎么看这次写）。

## 4. 当前能力（V2.1.0）

- 单文件四层螺旋推理引擎，四层可单独跑、可并行、可断点续跑。
- EML 双时态知识面：事件溯源、AGM/TMS 修正、BM25/RRF/MMR、只给调度数值先验。
- Scheduler v2：MAPE-K + EVOI + MPC + Pareto + 安全盾，可影子、可接管初始排程。
- 四层契约 F2–F5：ClosurePackage、AnswerSet、论证图、0 层审计/生成，越权直接拒绝。
- 事实门/答案门/过程门：FactCard、证据去重、引用、一致性、answer_quality。
- 质量-成本 Pareto：分层 calls/tokens/ms、覆盖率、三态、决策动作数。
- 历史谱系融合：178 个历史版本 → 17 条能力轴 → 运行时 provenance；readiness=1.00。
- 本地 App 工作台、HTTPS/鉴权/CSRF、RAG v2、DSH 会话、本地产物库。
- 本地模型路径：Qwen2.5-0.5B/1.5B、DeepSeek-R1-Distill-Qwen-1.5B；LoRA/scheduler 小模型脚本可复跑。

## 5. 不是什么

- 不是把问题当语料做摘要的“总结器”；
- 不是所有题都必须给唯一答案的问答机；
- 不是用记忆污染答案的系统：EML 只影响调度/阈值，不改答案内容；
- 不是把 V1 历史文件重新打包一遍的“版本合集”——V2.1.0 的融合层只把历史变成可审计的 provenance，不改历史归档事实。
