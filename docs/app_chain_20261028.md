## 3. 守护状态机（dgtf_app/local_chain.py）

两段服务放进**同一张状态表**，每个目标：
ok（就绪）/ reachable（进程活着）/ status / error / failures / starts /
next_start_at / backoff_idx / readings。

关键口径（都有判据钉住）：

- **ok 与 reachable 分开**：HTTP 有响应（哪怕 5xx）⇒ reachable=True。
  8772 模型后台加载时 status=loading ⇒ ok=False 但 reachable=True。
- **loading 不重启**（PENDING_STATUSES=loading）：进程活着，重启只会多起一个抢显存的进程。
- **只有硬掉线才重启**：reachable=False（连不上/无响应）+ failures >= 2
  + 退避到期（now >= next_start_at）+ 该段有 start_cmd。
- **指数退避**：120 → 300 → 600 → 900 → 1800（封顶）；成功恢复后
  failures/backoff_idx/next_start_at 全部归零。
- **日志节流**：状态迁移（掉线/恢复）必记；重复失败每 60s 窗口最多 1 行，
  并带「期间抑制 N 条重复」计数（不静默丢）。
- **模式**（显式可关）：auto（默认）/ on / off。
  auto = 首次 /api/health 或侧栏读数时才启动守护线程（与旧 8772-only 的懒启动同节奏，
  「只跑云档的实例」不会被强加后台进程）；on = App 启动即守护；
  off = 关闭守护（**读数仍可用**，探头只读不重启）。
  开关：CLI --local-chain-watchdog {auto,on,off}，env DGTF_APP_LOCAL_CHAIN_WATCHDOG。
- **云档不受影响是结构保证**：状态机只探活/重启进程，不读改任何配置；
  /api/health 里的 endpoint_kind 只是读数；本地档必须显式选预设。
- 启动命令（修对的）：
  - 8772：<repo>/local_model/envs/dgtf_llm_env/Scripts/python.exe -m dgtf_local_llm.service --port 8772
  - 8773：<App 的 python> scripts/local_model/openai_shim.py --port 8773 --upstream http://127.0.0.1:8772
- 日志：outputs/_lead_audit/local_chain_watchdog.log（与旧 local_llm_watchdog.log 分开）。

## 4. /api/health 的 local_chain 读数

GET /api/health 返回新增字段 local_chain（沿用 _app_health_cached 的 2s TTL；
local_chain 自身读数缓存 8s，探头 1.2s/段、两段并行、总等待有界）：

| 字段 | 含义 |
|---|---|
| endpoint_kind | local / cloud / unknown（按 effective api.base_url 分类；回环=local） |
| ok | 两段都就绪才 True；任一段未测出 → null；测到掉线 → False |
| service_ok / shim_ok | 各段是否就绪（True/False/null） |
| service_reachable / shim_reachable | 进程是否可达（区分「掉线」与「加载中/未就绪」） |
| service_status | 8772 /health 的 status（ready/loading/error/…） |
| service_queue_depth | 8772 队列深度（取不到 null） |
| service_gpu_mem_mb | 8772 显存占用 MB（取不到 null） |
| service_model / service_adapters | 模型路径 / 适配器就绪表（取不到 null） |
| shim_status / shim_upstream | 8773 /health 的 shim=up / upstream |
| shim_stage_channel | 8773 的 stage 通道对账计数（explicit_stage / mismatch_avoided） |
| engine_path / engine_version | runner.find_engine() 透传（App 当前用的引擎） |
| checked_at / age_sec | 读数时间戳 / 距今秒数 |
| reasons | **任何非 True 的段都点名原因**（「没有读数就不假装有」） |
| probe | on_demand（本轮是否重探）/ timeout_sec / max_age_sec |
| watchdog | mode/enabled/ticks/failures/restarts/next_restart_in/backoff_seconds/restart_capable/log/spawn_errors |
| preset | 本地全链路档 name/path/exists/endpoint |

null 语义（两向可分，判据 S4.3/S4.4 钉住）：
- False = **测到了**（端口拒绝/超时/5xx/loading 未就绪）——结论是「现在不能用」；
- None = **没测出**（守护关闭且从未探过等）——结论是「不知道」，并必须带 reasons。
