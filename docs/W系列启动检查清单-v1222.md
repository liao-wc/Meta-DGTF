## 附录 6 · v1.23.4 运行期三项总控（联网 / 思考 / 强度）

需求原文：**「为联网功能和思考模式和强度做一个总开关和可选项，并在交互时由用户可选」**。

### 形态

顶层新增 `runtime:` 段（与既有 `cost_profile` 同构），默认三项全 `auto`：

| 键 | 取值 | 含义 |
|---|---|---|
| `runtime.web` | `auto` / `on` / `off` | 联网总开关（`on` 仍受 `web_search.stages` 授权与配额约束） |
| `runtime.thinking` | `auto` / `on` / `off` | 思考总开关（`on` = 全环节开，成本↑） |
| `runtime.effort` | `auto` / `low` / `high` / `max` | 思考强度（只在思考开启时生效） |

**优先级**：命令行 `--web/--thinking/--effort` > yaml 的 `runtime:` 段 >
yaml 里各处既有键（`web_search.enabled` / `api.thinking.*`）。
★ `auto` 的语义是「**按配置文件**」，不是「跟上次一样」。

### 两条入口

- **交互**：`_ask_runtime()`，每轮询问一次（回车=auto），**不跨轮记忆**
  （在深拷副本 `run_cfg` 上生效）。
- **命令行**：`--web / --thinking / --effort`，`choices=` 收紧 ⇒ 敲错直接拦；
  位置在 `load_config` 之后 ⇒ 命令行覆盖 yaml。
- **产物留痕**：`_runtime`（`requested` = 归一后的请求值 + `web_enabled` /
  `thinking_default` / `thinking_stages_enabled` / `effort` 生效值）。

### 三处「不做就会静默出错」的设计点（配变异体钉住）

1. ★ **思考总开关必须连 `api.thinking.stages` 整表一起改** —— `LLM.call` 的
   优先级是「显式 > stage > default」，出厂 8 个环节是 `enabled`，
   只改 `default` 会被盖住 ⇒ 总开关成空话。变异体 **M2** 专钉。
2. ★ **`effort` 只在思考开启时才进 `extra_body`** ⇒「思考关 + 设了强度」是
   完全无效组合，必须**当场提示**（否则正是「配置写了但没生效」那一类 bug）。
3. ★ **`_apply_runtime` 是纯函数**（深拷后改、绝不改入参）—— 否则交互第二轮
   选 `auto` 会读到第一轮的值。变异体 **T7** 专钉。

### 其他要点

- `effort` 取值集 `low / high / max` 的**权威来源是出厂 yaml 自己的注释**
  （2026-10-02 实测），不是先验。
- `load_config` 改「**套外层**」（原名体 → `_load_config_raw`）：它有四个
  `return` 出口，插中间漏一处没有判据看得见。
- `_runtime.requested` 记**归一后**的请求值 ⇒ `runtime` 段三值恒在合法集合内
  （一条可断言的不变式）。
