# Meta-DGTF 引擎 V2.2.108 发布说明（2026-10-31）

> 类型：PATCH（回归判据细化）。主题：**一致性脚本区分「读数一致」与「调用数一致」**。
> 引擎零行为差；App 2.0.83 不变；零云 API。

## 1. 背景（如实发现）

V2.2.107 的 `--runs 2` 在本轮复跑中出现 **MISMATCH：all.calls 85 vs 96**，
但 status/main 逐项相同。说明「逐项一致」此前把 **LLM 调用数**也算进严格相等，
而调用数会随状态/缓存波动；读数（判定与主值）才是质量口径。

## 2. 修复

- `_diff` 拆成 `(readings_diffs, cost_diffs)`：
  - readings = status/main + pass/fail 汇总 ⇒ 差异才算 **MISMATCH**（退出码 1）；
  - calls 差异降级为 **WARN**（退出码仍 0），写入证据 `cost_warnings`。
- 证据字段 `consistent_readings` / `cost_warnings`；`--compare` 同步改口径。

## 3. 验证

- `--compare` 对上一轮证据对：`CONSISTENT（readings）；calls 有波动（WARN）`；
- 重新 `--runs 2`：`CONSISTENT（readings_diffs=0；calls_warn=0）`。
