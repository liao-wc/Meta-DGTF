# Meta-DGTF 引擎 V2.2.28 + App 2.0.53 发布说明（2026-10-29）

> 类型：PATCH。主题：预算层级 → 运行期 token 硬上限（动态依赖调整）+ dual_judge A/B 校准。
> 引擎侧零行为差（复用 V2.2.22 起的 --max-tokens）。

## 1. 预算依赖闭环

- 预算 warn/critical 时：plan 计算 running token 硬上限 = 动态配置估算 tokens × 1.5
  （最低 20k，千位取整），写入 plan.max_tokens 与 plan.dynamic_opt.budget_cap；
- apply_plan 把它落成 opts.max_tokens → engine_runner 透传 --max-tokens；
  引擎在预算边界优雅停（V2.2.22 起的机制），防止估算偏差导致超支；
- 显式 opts.max_tokens 永远优先（plan 不覆盖）；ok/quality 档不设上限（max_tokens=0）。

## 2. dual_judge=cache 的单题 A/B（有界，约 ¥0.12）

同题同 route=0/rounds=0:1/web off/预算 warn，两臂：
- A（动态默认 cache）：10 calls / 30,622 tokens ≈ ¥0.061；
- B（显式 dual_judge_mode=llm）：10 calls / 29,957 tokens ≈ ¥0.060；
- 差值：+665 tokens（cache 臂略高，冷缓存单次无节省）；两臂均 done。
结论：冷缓存下单次评审复用收益不显著；保留该阶段路由作为"缓存热/预算极紧"备选，
下轮验证热缓存场景。证据：docs/dynamic_dual_judge_ab_20261029.json。
