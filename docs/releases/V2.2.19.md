# Meta-DGTF 引擎 V2.2.19 发布说明（2026-10-29）

> 版本类型：**MINOR（机制）**：输入驱动的自动模式选择 + 每模式专属配置 + 运行期动态调整 + 模式集裁剪。
> 生产文件：`dgtf_engine/dgtf_v2/engine/Meta-DGTF-V2.2.19.py`（`__version__ = "2.2.19"`）。
> 不给 `--mode` 时逐字保持 V2.2.18 行为（所有历史回归/探针走旧路径，零行为差）。

## 1. 目标与结论

用户要求：**由用户输入出发自动选合适模式；每个模式有专门配置参数；整个运行自动动态调整；只保留已保留的模式（B/serial/fast），其他模式去除；并保证所有选择最优。**

本版交付：

| 要求 | 落地 |
|---|---|
| 输入驱动自动选模式 | `plan_for_input(question)`：题面类型（事实/推理/选择）+ 长度 + 显式预算 → 偏好与约束 → 枚举最优 |
| 每模式专门配置 | `MODE_CONFIGS`（唯一事实源，App 与引擎共用）：B/serial/fast 各自的 parallel/thinking/effort/web/rounds/质量档 |
| 运行自动动态调整 | `dynamic_adjust(plan, progress)` + 引擎层/波边界 tick：预算超支降档 fast、fast 质量代理低于目标升档 B，全部留痕 |
| 只保留保留模式 | 模式集只留 **B / serial / fast**；`web` 降为标志位；A、C–H 从 CLI 用户面移除（旧值回落 B 并留痕） |
| 保证选择最优 | 候选 ≤3 个 ⇒ **枚举精确最优**：`regret=0`；900 组约束网格 oracle 全命中；不可行显式 fallback；推断下限让位可审计 |

## 2. 输入驱动的选择策略（可解释、可证最优）

| 输入类型 | 推断偏好 | 约束 | 选中 | 依据（实测读数） |
|---|---|---|---|---|
| 事实题（短） | prefer=wall | 质量下限 0.90 | **fast** | quality 0.93 / 782.6s / 817k tokens（B：1.0 / 1064s） |
| 推理题 / 选择题 / 长题 | prefer=quality | 质量下限 0.95 | **B** | quality 1.0 / 1064s（质量/墙钟双优） |
| 显式 min_quality=0.99 | quality | 0.99 | **B** | 唯一始终满足 0.99+ 的模式 |
| 显式 max_wall≤900s | quality | 墙钟硬约束 | **fast**（推断下限按需让位并留痕） | fast 782.6s；B 1064s 超限 |
| 显式 min_q≥0.95 + tokens≤1.0M | quality | 两者 | **serial** | 997k tokens / 0.99 质量（唯一可行） |
| require_web | 质量档 | 只考虑有实测的联网档 | **B + web 标志位** | B+官方联网实测 0.933 / 1062k / 1073s |

**最优性证明（机器可核对）**：候选集 = KEPT ∩ 显式约束；目标函数为 quality/wall/tokens/balanced 四选一；候选只有 3 个 ⇒ 枚举即精确最优。
- `tests_auto_mode_optimal.py` 用 6×5×5×3×2=**900 组约束网格**独立 oracle 对账：全部命中、`regret=0`；
- 可行集为空 ⇒ 显式 `fallback=True / regret=None`（不假装最优），退路=质量下限优先再比墙钟；
- 推断出来的质量下限在显式预算无解时让位，记录在 `optimality.relaxed`（显式约束永不让位）；
- 三个保留模式在质量/tokens/墙钟上互为 Pareto 最优（无支配关系，测试 G1a 钉住）。

## 3. 每模式专属配置（MODE_CONFIGS）

| 模式 | parallel | thinking | effort | web | rounds 提示 | 质量档 | 定位 |
|---|---|---|---|---|---|---|---|
| **B** | B | auto | auto | off | 0:1,1:1,both:1,all:1 | floor .95 / target .99 | 质量/墙钟双优 |
| **serial** | serial | auto | auto | off | 同左 | floor .95 / target .99 | 低 tokens 备选（997k） |
| **fast** | B | **off** | auto | off | 同左 | floor .90 / target .95 | 墙钟/tokens 最低（782s） |

- App 端 `apply_mode_opts` 落成任务 opts（显式用户参数优先，`applied_opts` 可审计）；
- 引擎端 `--mode auto|B|serial|fast` 用同一份 `MODE_CONFIGS` 落 cfg/CLI 默认；
- `require_web` 时 web 只是标志位（B+web），不再是第 4 个模式。

## 4. 运行期动态调整

`dynamic_adjust(plan, progress)`（纯函数，引擎在层边界/波边界调用）：

| 触发 | 动作 | 保护 |
|---|---|---|
| 墙钟过半而层进度不足半 / tokens 已用 70% | **降档 fast**（thinking off、web off、B 波次剩余圈数压到 +1） | 仅当质量下限 ≤ fast 实测 0.93；质量下限更高时宁可超预算也不降档 |
| fast 且有 cascade，运行期质量代理 < 目标（0.95/0.99） | **升档 B**（恢复 thinking 档） | 质量代理 = 已完成层 errors/候选数（粗代理，非分数） |
| 进度/预算正常 | **keep** | 每次调整带 reason + alternatives + optimality |

引擎把计划与每次调整写进 `packed.auto_mode = {plan, adjustments[]}`（含 phase/wave/elapsed/tokens），App 回显在 `task.mode_fusion`。

## 5. 模式集裁剪

- `MODES` 只剩 B/serial/fast；`KEPT` 不变；`web` 成为标志位；
- 引擎 `--parallel` 用户面 choices = `serial / B / auto`；配置/历史里残留 A、C–H 时**回落 B 并打印留痕**；
- App 端不再有 `web` 模式分支；场景表"必须联网"行改为 B(+web)；
- 内部 A–H 并行实现保留（历史复现/回归对照用），但**不可从用户面选中**。

## 6. 集成与判据

- App 真实任务默认启用输入驱动自动选档（mock/自检关闭；`DGTF_AUTO_MODE=0` 全局关）；
- 引擎新增 `--mode`（能力门控：旧引擎自动不透传）；`packed.auto_mode` 出口；
- 一键验收新增 `auto_mode_local` 步骤（真跑本地 0.5B 链路，零 API）；
- 新判据：`tests_auto_mode_optimal.py`（45 项：保留集/最优性/输入驱动/专属配置/动态调整/静态接线/变异体）、`scripts/local_model/test_auto_mode_local.py`（12 项真跑）。

## 8. 边界（如实）

- 实测读数来自云端真跑（V2.2.3 同题数据）；本地 0.5B 链路只验证"链路与协议"，**不把质量读数迁移到本地档**；
- 运行期质量代理是粗代理（errors/候选数），只用于 fast→B 升档触发；预算降档是确定性规则，不声称全局最优；
- 度量为单次模式读数，跨题方差存在；选择策略给的是"在已有读数下的最优"，不是"质量预言"；
- 显式约束不可满足时 fallback 会明确标记，不冒充最优。
