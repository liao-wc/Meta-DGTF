# Meta-DGTF 引擎 V2.2.17 发布说明（2026-10-28）

> 版本类型：**PATCH**（引擎）；App 2.0.37 不变。
> 生产文件：`dgtf_engine/dgtf_v2/engine/Meta-DGTF-V2.2.17.py`（`__version__ = "2.2.17"`）。
> V2.2.16 及更早只读保留；App glob 自动选用最高版。

## 1. 问题：50% 的 prompt 超 2048，且被**右截断**切掉尾部指令

真实转储（584 条引擎经 shim 发出的 system+user 全文）：

| 指标 | 读数 |
|---|---|
| prompt token p50 / p90 / max | 2042 / 3713 / 6170 |
| 超过服务端 2048 上限的比例 | **292 / 584（50%）** |
| 结构性重复 | 【0层侧面清单】1594 次、【Agent知识回声】1388 次、参考记忆哈希每 prompt 2~3 份 |
| 行级完全去重可省 token | **45.3%**（1,065,576 → 582,887） |

服务端 `truncation=True, max_length=2048` 是**右截断**（丢尾部）——而尾部恰是最终 JSON
指令/schema 所在；0.5B 既读不完重复记忆，又看不到真正的指令。

## 2. 机制：本地端点 prompt 瘦身（纯函数，云端零行为差）

`LLM.call` 出货前的唯一咽喉处，对本机端点（`_is_local_llm_endpoint`）执行
`diet_local_prompt`：

| 规则 | 内容 |
|---|---|
| R1 行级完全去重 | strip 后相同的非空行只留第一次出现（顺序不变） |
| R2 噪声块 | 已知噪声头（参考记忆特征 / 【Agent知识回声】/【0层侧面清单】/【你上一次是谁】）只留第一份，超 240 字符截断 |
| R3 尾部保护 | 末尾约 320 字符按**整行对齐**原样保留，不参与 R1/R2（JSON schema/最终指令优先） |
| 安全阀 | 空文本/瘦身后为空/变长 ⇒ 原样返回；失败不阻断调用 |

- 开关：`api.local_prompt_diet`（默认 true）+ CLI `--local-prompt-diet on|off`；
- 读数：packed 新增 `llm_prompt_diet = {applied, chars_before, chars_after, lines_removed, blocks_truncated}`；
- 云端（base_url 非本机）**直接返回原值**，prompt 一字不动（零行为差）。

## 3. 证据

### 3.1 离线（584 条真实 prompt，原型规则与引擎实现同源）

- 总 token 1,065,576 → 582,887（**−45.3%**）；
- 尾部 schema 行零丢失（逐条检查最后一条含 `{` 的行仍在）、无「过短」样本；
- 复杂 stage 缩减最大：manifest 56.5%、self_check 55.2%、re_anchor 54.6%、dual_judge 53.7%。

### 3.2 机制级 A/B（16 条固定真实 prompt，同一引擎 `LLM.call`，服务每轮重启清缓存）

| 指标 | OFF | ON | 变化 |
|---|---|---|---|
| prompt 字符（16 条合计） | 78,561 | **48,110** | **−38.7%** |
| 删除重复行 | 0 | 267 | — |
| 噪声块截断 | 0 | 21 | — |
| token（16 条合计） | 32,669 | **27,622** | **−15.4%** |
| 单次墙钟中位 | 1.49s | 1.96s | 不作结论（生成长度方差主导，n=2/stage） |

> token 降幅小于字符降幅的原因：OFF 组 prompt 已被服务端 2048 截断，ON 组大部分落到
> 2048 以内 ⇒ 真实回收的是「让尾部指令重新进入窗口」，而不是继续压缩已截断的部分。

### 3.3 端到端（App 真入口 route=1，单次对照，如实记录）

| 变体 | 墙钟 | calls | 质量旗标 | 候选数 |
|---|---|---|---|---|
| OFF | 101.2s | 21 | 2 | 3 |
| ON | 121.9s | 27 | 5 | 1 |

轨迹/生成长度方差主导（同判据历史单跑 15~27 calls、59~122s），**单次端到端不可归因**；
本轮采纳依据是 3.1/3.2 的固定工作负载读数（上下文占用与尾部指令保全），不声称端到端提速。

## 6. 边界

- 瘦身只删「完全重复行」与已知噪声块（有截断损失），不做语义摘要；如质量 A/B 显示负向，
  用 `--local-prompt-diet off` 一键回滚（默认值在 `api.local_prompt_diet`）。
- 端到端墙钟收益未证明（缓存/轨迹方差）；本轮收益口径是**上下文占用与指令保全**。
- 0.5B 语义能力仍是层 1/both/all 达成的主瓶颈（与 V2.2.16 结论一致）。
