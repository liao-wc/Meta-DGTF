## 4. 已知边界（如实冻结）

- 本机 0.5B 底座的结构化输出能力是主瓶颈：json_repair 类调用多（多为 LRU 缓存命中）、ing/view 仍会撞 224 token 上限 ⇒ 层 1/both/all 的「达成」需要更强模型或更长的本地适配训练，不是链路问题；
- 四层分开跑（probe）比一次全跑快（431.2s vs 818.4s），但都远超云端；本地档定位仍是「零成本链路验证 / 离线可用」，不是生产质量档；
- 引擎层两处口径结构边界（元层 crystallize 圈内停止判据不可达、层1/both 圈内尺子≠收尾读数）已在 docs/四层目标读数审计_20261028.md 量化记录，本版不做行为修改（需云端 A/B 预算）；
- App 前端暂无 profile 下拉（API 通道与预设已通，UI 选择器另立）。
