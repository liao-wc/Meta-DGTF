# Meta-DGTF 引擎 V2.2.20 + App 2.0.45 发布说明（2026-10-29）

> 版本类型：**PATCH**（道生支路接入统一模式体系 · 方案 A）。
> 生产文件：`dgtf_engine/dgtf_v2/engine/Meta-DGTF-V2.2.20.py`（`__version__ = "2.2.20"`）+ App 2.0.45。
> 不给 `--mode` 时引擎行为与 V2.2.19 一致；道生默认行为不变（quality-first / 事实题强制 web / 预算降级保留）。

## 1. 问题：道生支路与统一模式体系割裂

V2.2.19 建立了"输入驱动选档 + 每模式专属配置（MODE_CONFIGS）+ 运行期动态调整"，但道生支路：

- server 刻意 `_auto_fused=False`（避免两套调度互相覆盖）；
- `apply_plan` **不传 `--mode`** ⇒ 引擎 `cfg["_auto_mode"]` 为空 ⇒ MODE_CONFIGS 不落参、
  `dynamic_adjust` 不生效、`packed.auto_mode` 为空；
- 参数来源两套：道生 fast 用 `parallel=serial / thinking=off / rounds_fast`，
  统一配置 fast 是 `parallel=B / thinking=off / rounds_hint` ⇒ 同名模式两种行为。

## 2. 方案 A：保留道生独立 plan，统一参数来源与动态调整

| 改动 | 内容 |
|---|---|
| 统一配置来源 | `build_plan` 取 `MODE_CONFIGS[engine_mode]`（B/fast/serial）作为默认 `parallel/thinking/effort`；道生预设显式值（rounds/rounds_quality/rounds_fast/parallel）与场景规则（事实/选项题强制 web）**仍然优先** |
| mode 透传 | plan 新增 `mode` / `unified_config` / `rounds_locked`；`apply_plan` 把 `mode` 落 opts ⇒ 引擎启用 MODE_CONFIGS + `dynamic_adjust` |
| 圈数锁定 | 显式 rounds（质量档/快档）⇒ `rounds_locked=true`；引擎 tick 只在 patch 带 `cap_rounds`/`rounds_extra` 时才改圈 ⇒ 锁定场景动态调整只调 thinking/web（与「显式圈数优先」补丁同口径） |
| 回显可审计 | `task.mode_fusion = {unified, mode, config, rounds_locked, dynamic}`；M4 回显 `first_config / optimality / policy` |

**效果**：道生任务也拥有"模式专属配置 + 运行期动态调整 + 最优性证据"，但调度决策仍由道生 plan（M4/预算守卫/preset）负责，不引入两套调度互相覆盖。

## 3. 参数对照（当前）

| 模式 | 道生质量档（daosheng） | 道生快档（daosheng_fast） |
|---|---|---|
| engine_mode | B | fast |
| parallel | B（预设/统一配置一致） | **B**（统一配置；不再固定 serial） |
| thinking | auto | off |
| effort | auto | auto |
| rounds | auto（未锁定）或 rounds_quality（锁定） | rounds_fast（锁定） |
| web | 预设 auto + 场景规则（事实/选项题强制 on） | off + 场景规则（事实/选项题强制 on） |
| 动态调整 | 生效（锁定场景不改圈） | 生效（升 B 只调 thinking，不改圈） |

## 6. 边界

- 道生 rounds 的"质量档/快档"仍是 preset 语义，统一配置只补默认参数，不重写 rounds；
- 运行期动态调整的质量代理仍是层内 errors/候选数（粗代理）；
- MODE_CONFIGS 的实测读数来自云端真跑，本地 0.5B 仅验证链路与协议；
- 旧引擎下 `--mode` 能力门控自动不透传（App 2.0.45 与引擎 V2.2.20 配套）。
