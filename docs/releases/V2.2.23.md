# Meta-DGTF 引擎 V2.2.23 + App 2.0.48 发布说明（2026-10-29）

> 类型：**PATCH（修复）**。主题：route 安全门——本地 route 预测默认不再砍层，
> 修复"最近一次运行只调度 1 层"问题。引擎侧零行为差（V2.2.23 仅版本/说明）。

## 1. 问题（真实运行复盘）

任务 20261029_113643_e25f29（问题「极端天气为什么越来越频繁」，mode=auto→daosheng）：
- 本地 0.5B route 适配器预测 route=["1"]（source=http，无置信度字段）；
- 道生 build_plan 直接采用预测 ⇒ plan.route="1" ⇒ apply_plan 落 opts.route="1"
  ⇒ 引擎以显式 --route 1 调度，只跑研究层（dispatch ran=["1"]），其余层只有占位产物；
- 旧 standard 模式默认四层；融合后"按题面砍层"能力被带进标准路径，而预测器无置信度门控，
  会出现只留 1 层的极端切法（该问题复现率 100%，HTTP 404 同样预测 ["1"]）。

## 2. 修法：route 安全门（默认 union）

新增预设配置 `route_policy`（configs/道生专属模式.yaml + _BUILTIN_DS 默认 union）：

| 策略 | 行为 |
|---|---|
| **union（默认）** | 预设 route ∪ 预测 route；预设为四层时结果恒四层，预测只作审计/补充（不砍层） |
| preset | 完全忽略预测（纯预设） |
| predict | 旧行为（预测非空即采用，可砍层；仅用于显式省层实验） |

- plan 新增 route_policy / route_source / route_prediction 读数，预测被安全门拦下时写 warnings；
- 非法策略值自动回落 union（不会静默退化成 predict）；
- 默认行为：**标准模式四层能力保留**；要省层需显式改 `route_policy: predict`。

## 5. 兼容性与边界

- 默认（union）行为变更是**修复**：四层不再被 0.5B 预测静默裁掉；
