# 圈内检查点（更细粒度检查点）· 设计与可行性

- 需求来源：用户点名「更细粒度检查点」（2026-10-18）
- 现状：检查点只在**层完成**时落盘
- 结论（先说）：**能存，但"续了等于没断"这件事证不了 —— 所以分两步走，先观测后恢复**

---

## 一、现状：细到什么程度

| 环节 | 现在 |
|---|---|
| 落盘时机 | daemon 心跳（`ckpt_interval`）+ 层边界 + 收尾 |
| 快照内容 | `views`（**只有已完成的层**）、`pools`、`llm_calls/tokens`（累计）、`rounds_run` |
| 续跑行为 | `load_resume_snapshot` 恢复 pools；`_run_serial` **跳过已完成层**；被墙钟截断的层**整层丢掉重跑** |

⇒ 一次 30 分钟的层，跑到第 5 圈被杀，**这 5 圈全废**。这是"更细粒度"要解决的事。

---

## 二、可行性：状态**可以**序列化

用现有产物实测（`_ab_v1255/V1255A.json`）：

| 项 | 结果 |
|---|---|
| `pools.both` 字段数 | 23 |
| 字段类型 | 全是 `list` / `dict` / 标量 —— **纯数据** |
| 单层 pool JSON 体积 | **18.0 KB** |
| 整个产物 | 752 KB（含各层候选正文） |

⇒ 存 pool 不贵（18 KB/层）。**序列化不是障碍。**

---

## 三、真正的障碍：等价性证不了

要"续跑接着跑第 6 圈"，得把**当圈的输入**还原出来。而每一圈的输入不只有 pool：

| 需要还原的 | 现在有没有 | 备注 |
|---|---|---|
| `inp.pool` | ✅ 快照里有 | 18 KB，纯数据 |
| 圈号 `r` | ✅ `rounds_run` 里有 | |
| 目标读数历史 `_goal_hist` | ❌ **没有**（只在内存） | v1.23.57 才引入，产物里有 trace 但没进快照 |
| 停止连击 `_duty_streak` / `_rephrase_streak` / `_meta_idle_streak` | ❌ | 影响"下圈还停不停" |
| 当圈的 `seeds`（探针筛出的重点）/ `sub_questions` | ❌ | 由**上一圈 view** 派生，重建方式不唯一 |
| `carry`（跨圈携带的候选） | ⚠️ 部分 | pool 里有，但 `carry_dropped` 之类是派生量 |

问题在最后两行：**`seeds` 与 `carry` 是从上一圈结果派生的，重算会得到"另一个版本"**。
一旦不同，续跑出来的跑次就**不是原来那条轨迹** —— 但它会以"同一 run_id"的完整产物出现，
**没人看得出它中途换过轨**。

> 这比"整层重跑"更危险：整层重跑至少是**干净的一次**，产物的 `rounds_run` 是自洽的；
> 而"伪续跑"会得到一条**谁也没真正跑过的轨迹**，却挂着正常的完成标记。

### 所以：能不能证？

理论上要证「从第 k 圈接着跑」≡「一次跑完」，得让 `seeds` 的生成**只依赖 pool**
（确定性重建）。现在的实现里它依赖上一圈 View 的随机/启发式筛选 —— **不是纯函数**。
改造它等于改运行语义，属于另一类工作。

---

## 四、两步走（建议）

### 第 1 步：观测（零风险，先做）

**只记不恢复**：每圈结束把「层内进度」写进快照的附加字段，续跑行为**一个字不改**。

```json
{
  "layer_progress": {
    "0":  {"rounds_done": 5, "carry": 12, "amps": 8, "last_round_at": 1750000000},
    "both": {"rounds_done": 2, ...}
  },
  "streaks": {"_duty_streak": {"both": 1}, "_rephrase_streak": {"both": 0}},
  "goal_hist": {"both": [{"round": 1, "fuse": 0.8}, {"round": 2, "fuse": 0.82}]}
}
```

价值：
- 被杀之后**能看见死在第几圈**（现在只知道"这层没完成"）；
- 能算出「一层平均每圈多久」⇒ 以后**按圈数而不是按层数**估算预算；
- 为第 2 步提供数据（先收集若干跑次，看 `seeds` 到底依赖什么）。

**判据**：一次被截断的跑，快照里 `layer_progress.<层>.rounds_done` 必须等于该层实际圈数；
且**续跑行为与现在逐字相同**（旧判据全绿 + 一个新判据钉"只记不改"）。

### 第 2 步：恢复（要先证等价）

前置条件（缺一不可）：
1. `seeds` / `carry` 的生成改成**只依赖 pool + 圈号**（纯函数）；
2. 一条**等价性判据**：同一题，一次跑完 N 圈 vs 跑 k 圈后中断再续 ⇒
   两边的 `views`（除 `rounds_run` 与时间戳外）**逐字相同**；
3. 做不到就**别开** —— 或者开了也要在产物里明写 `resumed_mid_layer: true`，
   让人知道这不是一条完整轨迹。

---

## 五、为什么不建议现在直接做第 2 步

1. **风险落在最核心的累加器上**：`inp.pool` 是跨圈累积的候选/&/线头，半截恢复出错会**静默污染**整层产物。
2. **等价性证不了 = 引入"看不见的换轨"**（见 §三）。
3. 当前已知的痛点（长层被截断整层重跑）**代价可控**：实测一层 4~7 圈 ≈ 8~15 分钟 / ¥0.3~0.6。
   相比之下，为它冒"产物不可信"的风险不划算。

---

## 六、如果要做第 2 步，最小可行范围

- 只支持 **serial 模式**（并行模式的状态更复杂，先不碰）；
- 只对**被墙钟截断**的层生效（`stop_reason` 带截断标记的），不碰自然停止的层；
- 恢复时**必须**在产物里写 `resumed_mid_layer: true` + `resumed_from_round: k`；
- 判据：`check_v1xxxx_mid_layer_equiv`（上面第 2 条）。

---

## 七、当前建议

**先做第 1 步（观测）**。它零风险、能立刻回答"死在第几圈/一圈多久"，
而且是第 2 步的必要数据来源。第 2 步等 `seeds` 的确定性改造单独评估后再动。
