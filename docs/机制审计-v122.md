## 一、审计口径

三列命中数：源码 / 日志 / 产物。**日志侧与产物侧的标记串必须分别数** ——
本项目已知的坑是同一件事两侧写法不同（日志 `【螺旋停止】…` vs 产物
`**螺旋停止**：…`），照一侧数另一侧会数出 0，然后被误读成「出口没通」。

判定三档：`可达` / `仅源码` / `需核对`。**「零触发」不等于「没用」**：
要分清 ①条件不可达（真该死）②条件窄但在特定情形成立（留着）
③机制压根没工作（重写）—— 分不开就必须做**负对照**。

### 为什么 #3 不直接删（2026-10-09 决策）

仓库内实测**零**布尔调用点（出厂 `dgtf_config.yaml` 与 `DEFAULT_CONFIG`
两处都是字符串档）。但删掉兼容分支的后果是：外部配置写 `as_evidence: true`
→ `str(True).lower()` = `"true"` 不在五档 → 落 `off`，**从「作证据」静默
降级成「关闭」，且没有任何提示**。这比留着更糟。
**正解是先让它可观测**（v1.23.5：走一次 `logger.warning` 一次），留痕确认
没人走之后再删 —— 那时删是有证据的删，不是赌。

### v1.23.5 新增：调度归一化收口（原 pending_fix #1）

**★ 文档原记载不准**：写的是「两份」，实测**三处**调用点各写一份 ——
模式白名单 3 处、confidence 解析 3 处、圈数归一化 2 处、低置信退 serial
3 处（后者的处置还有意不同）。这就是「登记表没有判据盯着」的代价。

**做法**：抽成三个模块级唯一实现，三处调用点各留一行。

| 唯一实现 | 管什么 | 调用点 |
|---|---|---|
| `_plan_conf(data)` | `confidence` → float，不可解析记 0.0 | 3 处 |
| `_normalize_plan_mode(data)` | `mode` → A~H 或 serial | 3 处 |
| `_normalize_plan_rounds(data, hard, route=None)` | `rounds` 解析 + 中位数补漏 + 钳制 + 可选按 route 裁 | 2 处 |

**刻意保留的差异**：「低置信退 serial」三处处置不同 ——
`_decide_parallel_mode` 与单调用分支会**改写 reason 并提前 return**
（「低置信(x)，退回 serial：原 reason」），`plan_resources` 只把 mode 改回
serial 后继续、**reason 不动**。合并它会改变返回值形状，所以不合并；
由 `check_v1235_pending_fix` [1e] 三向钉住（变异体 M3 验证判据有判别力）。

**行为零变化的证据**：`_probe_v1235_pendingfix.py` 改前/改后逐行对表 ——
16 组输入 × 三处的 mode/rounds/conf/reason **全部逐字相同**，低置信一组
亦然；唯一差异是 `[A]` 形态计数段（那正是本次要改的东西）。

**顺带修掉**：单调用分支的 `conf = float(...)` 原来是裸调、不在 try 里，
模型返回非数字 confidence 会抛 ValueError 逃出 `auto_plan`；现在统一兜成
0.0（保守方向 ⇒ 退 serial）。
