# v1.22.1 · 明确不做的三件事

> 性质：**决策记录**（不是产物级告警 —— 因此不进 `save_result` 头部，避免噪音）。
> 目的：下一版看到这一页时，不要重开这三件事；要重开，先满足下面写明的**前置条件**。

---

## 1. 不拆模块

**依据**：`docs/拆模块方案-v122.md` 实测 —— 顶层符号 201、依赖边 384、
双向边 10 对、跨候选模块边 48%。

**前置条件（未完成前不拆）**：

- 12 处字面串判据要改成按模块 glob；
- 2 处单文件比对要改成多文件口径；
- `other` 里 136 个符号要先立命名法。

★ 也就是说：拆模块**不是**一次文件搬运，而是「判据体系跟着改」的连带工程。
判据不跟着走，拆完就会出现「文件搬了、检查还在找旧路径」的静默腐烂
（本项目在 v1.22 的配置同步上已经见过一次同类问题）。

---

## 2. 不扩动词白名单 / 不放宽 `min_actions`

**依据**：v1.22.0 阶段 3 报告第七节 —— 扩白名单是「把判据拟合到数据」，
放宽 `min_actions` 是「改阈值」。任务书明令禁止。

**正路**：P1 已做（研究层 schema 直接产 `actions`），不再走词法拟合。

★ 具体说清楚这两条为什么是禁的：

- 扩动词白名单 = 把「引擎能不能抽出行动」这件事，从「模型有没有按 schema
  产出」改成「我认不认它用的那个动词」。那是拿**判据**去迁就**数据**：
  真实跑出来的动词只要不在我名单里就被丢掉，我加一个就多算一个 ——
  数字会好看，能力没变。
- 放宽 `min_actions` = 直接把门槛下调。同一条产出，门槛从 3 降到 2 就过，
  这不是修好了，这是把尺子改短。

两条都会让指标变绿而**不改变系统行为**。本版宁可让判据红着，也不动它们。

---

## 3. 不删任何机制

**依据**：v1.22 六阶段 + 本收尾，累计 **3 次红线判定**，全部要求
`count_del_lines = 0`。

即使 P3 判「条件不可达」的机制（`_all_settle_streak`），**本版也不删** ——
归档到 `pending_fix`，由下一版在拿到 ≥3 题负对照后再决定。

★ 为什么「条件不可达」也不删：

- 「零触发」≠「没用」。一条机制在 316 份日志里 0 命中，可能是条件确实不可达，
  也可能是**我们还没跑到**那类问题。这两种情况在当前证据下**分不开**。
- 删掉是**不可逆**的：名字没了，历史对比就断了（`mechanism_removed()` 会判红）。
- 本项目的规矩是「失败留痕」：判「不可达」就把判据和证据写进
  `docs/机制负对照-v1221.md`，让下一个人能复核，而不是把代码抹掉。

---

## 附：本版的三次红线判定

| 版本 / 档 | 判据 | 实测 |
|---|---|---|
| v1.22.0 六阶段 | `count_del_lines == 0` 且 符号消失 0 | 通过（纯删除 0 / 消失 0） |
| v1.22.1 第一档（P1/P3） | 同上 | rc1 纯删除 0 / 丢弃 0 |
| v1.22.1 P2b | `rc1 → rc1b` 纯删除 0 且 符号消失 0 | 通过 |

★ 补充口径（v1.22 起）：`count_del_lines` 用 **difflib 纯 delete 块**数，
不数「以 `-` 开头的行」—— 后者会把**改写**也算成删除，而改签名/搬正文
本来就是任务书要求的动作。判「机制有没有被拿掉」另按 **AST 符号**判
（`mechanism_removed()`），那才是红线真正想拦的东西。
