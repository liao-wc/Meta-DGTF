# 元 DGTF · 长期约定（精简）

> 完整历史见 `MEMORY_archive_2026-10-03.md` 与每日 `YYYY-MM-DD.md`。

## 形态与红线
- 单文件 `元DGTF-V1.21.xx.py`（~17k 行），无包/测试框架；四层
  （0/1/both/all）× 螺旋跑圈；三通道 content/context/self。
- 红线：输入是**形状**不是数据；悬置不打分；未对齐合法；停止与清算分开；
  失败留痕；入池前挡重复；参数按层可覆盖；自省是**另一个视角**，不可合并。

## 版本迭代（每轮固定动作）
1. 不覆盖源文件：从上一版**复制**出下一版。
2. 版本号两处：docstring 标题 + `__version__`。
3. changelog 在 docstring、最新在最前，写「改了啥 + 实测证据 + 未采纳项」；
   收束时加「收束摘要」。
4. 跑 `smoke_test.py`（`SRC` 指当前版）。
5. 分隔线用 U+2550 `═` / U+2500 `─`（各 60）。
6. 开版/插块脚本要断言**出现次数与块顺序**（打印 `v1.21.*` 行号序列），
   不能只断言"文本存在"——重复插入是真实事故。

## 已知的坑（高频）
- **docstring 里写单反斜杠会被转义** → 「摘 docstring 再扫源码」断言失效，
  症状是**历史遗留检查突然误报**；先查它，别改业务代码。
- ★ **抠 docstring 的工具函数必须先 `textwrap.dedent`**：`_find_method_body`
  返回的是**带缩进的片段**，直接 `ast.parse` 会 SyntaxError → 静默退回原文 →
  docstring 没被抠 → 方法体里"文档提到过的符号"被当成代码
  （v1.21.76 实测：`_before_round` 体被数成 2 处 `_anchor_round` 调用，真值 1）。
  **失败是静默的**（except SyntaxError: pass），所以只能靠对表发现。
- ★ **`_find_method_body(src, "__init__")` 返回的是第一个同名 def** —— 在大文件里
  那是 `LLM.__init__` 而不是 `MetaDGTF.__init__`，于是"初始化点"数成 0。
  要按**类**定位，或改用精确字面串。
- ★ **判据要随实现更新**：改掉了某个形态之后，**断言该形态的旧判据必然失败**——
  那不是回归。v1.21.76 有两条 v75 判据（形态断言 `_anchor_round(entry, pool, r)`、
  预算测「calls=9+anchor=1 → 用尽」）因 A1/A2 的修复而失效，要把判据本身改到新语义，
  并在报告里写明"是判据过时不是代码错"。
- ★ **探索性结论外推到新场景会翻车**：v1.21.75 用一份 `route=[0,1]` 的 packed
  探索出「claims 换成 candidates 后沾边 7/12」，据此改了 M1 口径；
  在 B 模式四层、另一份 packed 上实测 **仍是 0/12 无对应**（claims 只是从
  认识论层换成操作层，与事实锚点还是不同层）。**加了改动 ≠ 修好了**——
  M1 已在 v76 报告里如实记为"没解决"。
- ★★ **"结构性解释"是最诱人的甩锅对象 —— 先查自己那一版新加的代码**：
  v1.21.76 把 M1 的失败归因为「引擎产操作性论断、锚点是事实层，两者本就
  不同层」这种**听起来很深刻的解释**；v1.21.77 回头一查真根因是
  `_anchor_claims` 的**遍历顺序**写反了（`(1,0,...)` 里层 1 排最前，12 条
  配额被占满，层 0 的领域论断挤不进来）。同一份 packed 只换顺序：
  **印证 0 → 4、用到锚点 0 → 3**；真跑更是 **印证 7 / 用到锚点 8**。
  **扫代码看不出顺序错，只有「同一份数据只换一个变量对表」能逼出来。**
  结构性解释之所以诱人，正是因为它让我不用承认是自己写错了。
- ★ **同一份数据只换一个变量对表**，是查"我的新代码有没有低级错"的最快路径。
  比读代码、比加日志都快 —— 因为它是**差分**，而读代码是**顺序**。
- **主文件纯 CRLF**：禁用 `sed -i`/`awk`；脚本改要 `.replace('\r\n','\n')` →
  替换 → `.replace('\n','\r\n')`，并断言 `count("\n")==count("\r\n")`。
- ★ **写文件一律 `write_bytes`，别用 `write_text`**：Windows 文本模式会把 `\n`
  再翻成 `\r\n`，于是"自己转好的 CRLF"变成每行 `\r\r\n`。Python 容忍 `\r` 当
  换行，所以**不会报错、能跑通**——`_arm_v74.py`/`_anchor_report.py` 就这么带病
  跑了很久，直到 smoke_test.py 抛 `SyntaxError` 才发现。自检：
  `b.count(b"\r\r\n") > 0` 即中招。
- ★ **扫源码枚举「引擎会打什么标记」前，先摘掉 docstring/changelog**：v1.21.75
  扫零触发 emoji 时 `🍽` 被报成"零触发"，其实它**只出现在 changelog 里**——文档
  里提到的 emoji 被当成源码标记。这是"摘 docstring 再扫源码"那条坑的 emoji 版。
  结论：**任何"源码侧枚举 + 运行侧核对"的审计，两侧口径先对齐再下结论**。
- ★ **"零触发"≠"没用"**：判据要先分清三种解释 —— ①条件不可达（真该死）
  ②条件窄但在特定情形成立（留着）③机制压根没工作（重写）。分不开就得做
  **负对照**（喂一个该触发的输入看它触不触发）。实测：输入自检 244 份零触发，
  负对照证明**机制有效**，但它**没防住让它诞生的那次事故（`P=PN` 漏报）**。
- **改动脚本重跑会对已打补丁的文件报 AssertionError**（文件其实已改对）——
  以**文件状态**为准，别把 traceback 读成"没写进去"。
- **「同一条逻辑两条通道各写一份」已 **7 次**（最近：v1.21.71 F1 —— serial 的
  `rounds_n > 1` 与 B/C/D-H 的 `total_rounds <= 1` 是同一道门的两份写法；
  外部清单只点了 serial 一侧，另一处靠 `grep 形态` 才找到）。**查重复要 grep 形态，
  不要读清单**。调度依赖 ≠ 内容依赖。
- **验接线要用生产入口**，手造 Input 会绕过 bug 所在层。
- **判定类状态不许定成终审**：当前值 + append-only 履历，两方向都能翻转；
  「有足够证据」要落成确定性校验（引用物此刻真在池里），靠 prompt 恳求不算。
- **"只升不降"的指标是自欺**：分母变的那圈只重置基线，不计停滞也不计改善。
- **给 LLM 的 schema 别放具体示例值**（会被抄回）；同一 JSON 块多套编号必混，
  要明写不能互换；新加的示例和旧的一样泄漏。
- **冒烟断言别硬编码版本号**，一律从 `SRC` 派生。
- **只读审计必须带格式自检**（区分「有渲染点且为 0」与「没这个渲染点」）。
  ★ 自检字段/列必须**无条件写**——「有值时才写」度量了错的对象（G1q 实测
  覆盖计数报 1/6）。★ 改产物格式优先**加性**，下游新段写成**可选组**。
- **断言会假通过**：验跨圈累积要逐个覆盖写入时机，并用负对照证明判别力。
- **`view.errors` 只留最后一圈**；**测试桩签名落后会静默失败**（宽 `except` 吞掉）。
- **真跑题面**从 `upstream_batch01.txt` 的「6 领域各 1 题」里选。
- **要"一次真实跑圈"又要跨版本对表**：读 `smoke_test.py` **源码**、正则只换
  `SRC = HERE / "元DGTF-V1.21.NN.py"` 那一行（断言恰好 1 处）再 `exec` 成自己的
  module —— 比复制一份 harness 安全（不会分叉）。★ `smoke_test.run_mode()` 返回的是
  **汇总行**（`views` 成了 key 列表），要 packed 本体必须直接 `MetaDGTF.run(...)`。
- **沙箱里 `shutil.rmtree` 会被拒**（`SAFE_DELETE_FAIL_CLOSED`）→ 探针落盘一律
  `tempfile.mkdtemp`；**固定目录会跨进程累积**（实测把 4 个数成 12）。
- **同一件事的标记串，日志侧与产物侧常常不同**：日志 `【螺旋停止】…`
  （`_view_block_lines`）vs md `**螺旋停止**：…`（`save_result` 模板）。
  **照一侧的串数另一侧会数出 0**，别当成"出口没通"。判据要两端分别 grep。
- **打补丁脚本**：正文/模板里含 `{}` 时**别用 `.format()`**（代码片段会被当占位符）
  → 用 `@@BAR@@` token + `.replace`；正则形态的断言容易被自身转义坑到 →
  **优先用字面串**（`'    try:\n        save_result(result, cfg[...])'`）。
- **`inspect.Parameter.empty`** 才是"无默认值"的判据；`default is not empty → bad`
  这种方向写反会让"修好了"报成"没修"。
- ★ **合并/搬运 dict 时会静默吞掉新加字段**：`merged = dict(pool_res)` 只继承一路，
  v1.21.73 就这么把 `_assess_decidability` 算好的 `anchor_refs` 丢了，产物里显示
  `None`，看着像"外判没引用"，实际**引用就在那里被丢**（直接调 assign 实测 8/12）。
  **凡是 `dict(x)` 起手的搬运，加新字段时要回头确认它有没有出口。**
- ★ **探针自己的前提要先打出来**：`_probe_v73_refs.py` 第一版直接 `_load_anchors()`，
  而 yaml 默认 `enabled=false` → **载入 0 条**，两臂都没锚点却打印 `anchor_refs=[]`，
  差点被读成「assess 不返引用」。凡是结论建立在「某变量已带到位」上的探针，
  **第一步就 print 它到底带没带上**。
- **同名概念撞车**：引擎里早有一套「锚点重述 / 锚点·触及」（把**题面**当锚点由
  LLM 重述），与 v1.21.73 起的 `external_anchor`（外部事实）完全不是一回事。
  日志里前者打 `🪞`、后者打 `⚓`，别混。
- **变异测试换被测对象的小技巧**：smoke 的判据若每次调用都读模块级 `SRC` /
  `mod`，变异测试只需重赋这两个全局再调该函数，就能换掉被测源码（见
  `_probe_v74_mutants.py`），不用复制 harness。

## 跑批纪律
- 多 run **并行**是默认（`_run_parallel_batch.py --max-concurrency N`），别退回
  `for` 串行；起批量前先跑 1 个 pilot，必须设并发上限。
- **限流(429)会自愈；降级/超时是"卡住且不报错"** → 判活看有无新产物/日志
  + 单次往返是否回基线，别只看进程在不在。
- 卡住排查顺序：① 余额 `/user/balance` ② 其它端点 ③ 杀净自己进程
  ④ 换回老 ID/去掉新参数。
- 后台批次 `TaskOutput` 句柄**会丢**（进程活着）→ 定位进程：★ 本沙箱里
  `Get-CimInstance` / `Get-Process` / `wmic`/`tasklist` 取不到 python 命令行
  （PoSh 工具无输出）→ **用 `ps -W | grep python` 看启动时刻**（能区分哪个是本次）。
  杀 python 用 PoSh `Stop-Process -Force`。
- ★ **后台长跑绝不要在 bash 命令末尾加 `&`**：工具会回收 wrapper，子进程成
  **孤儿继续跑**（实测与第二次启动并发 2.6 min → 双份花费）。用工具的
  `run_in_background=true`，命令末尾**不加** `&`。
- 判卡死看 **≥45 秒**窗口 + 层/圈标记推进，别只看日志字节数。

## 测量学（最贵）
宣称「某指标很稳」前，先确认它不是被下游 clamp/fallback 压出来的。想测上游就
**摘掉下游**（在被污染字段外留上游快照），别关机制。改口径后比 baseline 变差
往往说明**改对了**。新指标先算**饱和度**（单一取值 >80% 即无判别力）；
须**同条件重复观测 ≥3**，组内极差 < 想宣称的组间差。
★ **上述「重复 ≥3」已被实测钉死，不是原则性建议**：两对「同题同配置、只差一个
开关」的对照跑出来 calls 差分别是 **-3** 与 **-10（-15.9%）**，连 0 层的停止判据
都不同（ON 2 圈 vs OFF 3 圈跑满）。**单次跑动的涨落远大于任何单机制的效应量**
→ 任何「接了/关了 X 省多少钱」的结论，不重复做就是假的。写预注册时若把
`calls 差 ≤2` 当门槛，这条门槛本身就是错的（本轮踩到，已在 v74 报告点名）。
★ **counts 类判据先考虑它是不是确定量**：随机重试（如「对偶判断命中 2/8，降级
重试」）一次就能把差值顶破。

## 外部锚点（v1.21.73 起）
- 所谓「外判」在 v1.21.72 及以前**从来不是外部的**：`web_search`/`external_facts`
  引用数 0，`_assess_decidability` 只收题面 → 实际是模型的第二意见。
- v1.21.73 起 `cfg.external_anchor.{enabled,path,max_items,crosscheck}`，默认关；
  快照 JSON 每条带 `id/claim/source/url/as_of/kind`，**不进池不改判定**，只做只读对照。
- ★ **claims 取值处决定成败**：从「decidable_product.answer + 研究池已答子问题」取，
  两次跑动都是 **全判「无对应」、anchor_used=0**（那两处全是认识论层的句子）；
  改从 **`views[*].candidates`** 取，同一份 packed 同一把尺 → **沾边 0/5 → 7/12、
  用到锚点 0 → 9/12**。**引擎的领域论断在 candidates**，下一轮正式纳入 M1 口径。
- 对照器对「如果…则…」的**条件句偏松**（出现过 note 自认"未直接反驳"却判印证的
  案例）→ 印证数要打折，判据要显式写「纯假设句判无对应」。
- **负对照必须做**：`_anchor_negative_control.py` 1 次调用，4 条反向合成结论 4/4
  判冲突 + 1 条一致判印证。没有它，「冲突 0」不可解读。

## 模型与成本
- 看 `resp.model`（请求 chat/reasoner/flash 实际多为 `deepseek-flash`）。
- thinking 走请求级 `extra_body`；`reasoning_effort=` 无效；`_is_reasoner()`
  靠名字猜，换新 ID 会静默判 False。
- 优先级实为 `default_model(yaml) > DGTF_MODEL(env)`。
- 输出单价是输入 4 倍 → 省 token 优先省**输出**。非高峰半价。
- 档位 quality / balanced(默认) / economy；self_check 降频刻意不在任何档。
- 耗时：route 0,1 ≈ 15–21 min；四层 5 圈 ≈ 38–50 min。
- ★ **真实价格**（`deepseek-flash`，官网 2026-10-04，¥/M token）：输入缓存命中
  空闲 0.02 / 高峰 0.04；未命中 空闲 **1** / 高峰 **2**；输出 空闲 **4** / 高峰 **8**。
  **高峰 = 北京时间周一至五 9:00–12:00、14:00–18:00**；周末/法定节假日全天空闲（半价）。
- ★ **一次完整四层跑的实测**（v1.21.72 · balanced · route=full · rounds=0 · serial）：
  **269 calls / 1 837 502 token / 65.1 min / ¥4.17**（空闲价，余额差）。层停点 12/8/4/4。
  对照历史 v1.21.59 同配置 = 333 / 1.586M / 47 min。
  历史 206 次真跑样本 **token/call 中位 5049**。
- ★ **钱几乎全在输出**：探针实测输出占 token **57.5%**、缓存命中仅 **25.5%**；
  ¥4.17 反解全跑 `out_share≈0.47` → **输出占花费 ~82%**。大头是 reasoner 的
  **ing / view 思考调用**（completion 6k–9.6k，因 thinking 把 max_tokens 抬到 32 000）。
  **要省钱先压这两处的输出长度**，不是压输入上下文。
- ★ **钱怎么测**：引擎只累计 `usage.total_tokens`（无输入/输出拆分）→ ① 余额差
  `/user/balance` 给真实花费（**账单有分钟级延迟，要等一会儿再读**）；② 探针
  `_probe_usage_split.py` 在**类层面**包 `Completions.create` 记录拆分（不改引擎）。
  运行器 `_run_v72.py` 由 `_run_v60.py` **只改 SRC 一行**派生；做**档位/模式旋钮
  对照**用 `_arm_v72.py`（load_config 后覆盖 cfg，不改引擎）。
- ★ **四臂 A/B 实测**（同题、四层、`0:3,1:3,both:3,all:3`；基线 balanced/serial
  = 122 calls / 896 314 token / 30.4 min）：
  · **economy 省 13% 调用 / 17% 钱**（同圈数）；
  · ★ **并行只省时间、还多花钱**：C 模式耗时降到 47%（1824→855s），但 token **+12%**、
    钱 **+12%** —— "模式只省时间不省钱"已从推测变成实测；
  · `re_eval_every_n 1→3` **单独只省约 4% 调用**（13 圈里该调用只触发 5 次），
    别按外部分析说的 ~10% 期待；
  · **token/call 实测 6773~8186**，明显高于历史中位 5049 —— reasoner 思考输出是主因；
    任何"按 4300~4800 token/call 估预算"的算法都会低估。

## 文档与观测出口
- **两份产物互不包含**：日志记**过程**（逐圈时序 / 展开候选 / API 往返 / 异常栈 /
  `[completeness]`），产物记**状态**（终态视图 + packed 全量附录 + 成品文本）。
  问"为什么"看日志，问"结果/字段"看产物。
- 报告落 `vNN_报告.md`；审计报告 `audit_zero_triggers_<TAG>.md`。细节只写：changelog、报告、日志。
- **评估质量只读探针 `_audit_eval_quality.py`**（+`_audit_eval_quality_README.md`，报告落
  `audits/eval_quality_*.md/.json`）。静态读产物 md 的「全量附录」；`--repeat N` 从 packed
  重建**同一个 view** 只重复评估调用（**不重跑流程**，省 15~20 min/200+ 调用）。
  实测：同一 view 30 次评估 → 判定值 **30/30 一致**（全 decidable），但清单**逐字重合 0%**、
