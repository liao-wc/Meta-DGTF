## 二、治本三条（停止判据）

### 2.1 sat 判定对四层同等生效

**旧行为**：`_check_structure_saturation`（LLM 判「本圈新 & 有没有引入新的结构
维度」）的结论**只对研究层生效**：

```python
if sat_verdict is False:
    if entry == "1":
        idle_new_amp = max(idle_new_amp, r_idle_limit)   # 只有研究层推
        sat_override = True
    else:
        self.vp(f"      ↳ 元层无新维度（软判据，不直接推 idle_new_amp）")   # 元层丢弃
```

真跑日志里元层**确实**判出了「无新维度（仅换措辞）」，然后被丢弃、一路跑到上限。

**改法**：新增模块级纯函数 `_sat_override(entry, sat_verdict, idle_new_amp,
idle_stall, r_idle_limit, r_stall_limit)` —— serial 的 `_run_layer` 与并行 B 的
`_b_check_stop` **共用同一份实现**（本项目「同一条逻辑两条实现」的第 N 次收口）。

- 四层同等：`sat_verdict is False ⇒ idle_new_amp = max(_, r_idle_limit)`；
- 0 层例外：`_stop_reasons` 的条件 2 排除了 `entry == "0"`，所以 0 层的落点是
  `idle_stall = max(_, r_stall_limit)`（条件 3，四层通用），`sat_override` 返回 False；
- 未判定（`None`）/ 判「有新维度」（`True`）⇒ **一律不动任何计数**。

### 2.2 惰性化归零

`_lazy_every_n` 原来对 balanced/economy 把低频项（结构饱和度 / 池重估）的间隔
**拉大一档**。它以「省调用」为名，实际把**停止判据的检查频率**也一起改了：
`sat_every_n = 3 → 4`，而层上限低于 4 的层**永远跑不到那条判据**（v1.23.15 实测：
up2 四层上限 ≤3、间隔 4 ⇒ 一次都不触发）。

**改法**：`_lazy_every_n` 恒等返回 `n`（并更新 docstring 讲清这段历史）。

### 2.3 参照集改「池内全量」

`recent_amps = [x for lst in win_amps[-r_window:] for x in lst]`
—— 只比**最近 2 圈的 new_amps**，第 N 圈与第 N-3 圈的重复抓不到。

**改法**：参照集 = **本圈开始时的池内全部 &**（`list(snap_amps)` / `list(snap_threads)`），
serial 与并行 B 两处都改；`win_amps` / `win_threads` / `r_window` / `round_window`
配置键一并删除。sat 判定的 prompt 文案同步从「近几圈已有 &」改成「池内已有 &」。

## 四、影响面与冲突自查

1. ★★ **去惰性化会连带改变池重估频率** —— `_lazy_every_n` 也被
   `re_eval_every_n`（池重估）用。balanced 下间隔是 2，去惰性化后是 1 ⇒
   **每圈都重估**。冒烟的 `P0-2`（「最后一圈不该重试」）立刻翻红：它比较两条
   路径的**调用数**，而「池空时重估不适用」让这条路少一次调用 —— 与「重试」
   无关。修法是把该变量固定（`re_eval_every_n=0`）再比，**不是放宽阈值**。
2. **删键会撞配置三向检查** —— `CONFIG_TUNED` 登记表里的 `cost_profile` 与
   `spiral.round_window` 变成「过期条目」⇒ 必须销账（判据设计如此）。
3. **`_expand_pair_merged_once` 成孤儿函数**（原 economy 档专属）。**本版不删**：
   冒烟判据 `check_merge_fallback` 直接调用它验「合并失败要回落」的语义，
   而那条语义与档位无关。见 §六。
4. **成本上升是明确取舍**：删档 = 恢复「不裁剪」，真跑 token 会高于上一版的
   balanced 档。这是用户明确要求的（只保留 quality）。

## 七、本轮教训（都进了技能）

1. ★★ **AST 删语句有两个相反的坑**：取「最小语句」会只删掉 `bad.append(...)`、
   留下孤立 `if ...:`（`IndentationError`）；取「最外层」会上溯到**包装它的大 If**
   （本次把刚注入的新判据本身都删了 —— 因为它的 `for _sym in (...)` 里出现了那个
   符号名）。**正解：只看语句的「首行」含不含特征**。
2. ★★ **重叠区间必须合并后再按下标删** —— `if hasattr(mod, "_auto_profile"): … else:`
   的 body 里还有含同名特征的 `if` ⇒ 先删内层、再按**旧行号**删外层 ⇒ 删错位置。
3. ★ **特征串不加括号**才能覆盖 `if/else` 整块（`_auto_profile` vs `_auto_profile(`）。
4. ★★ **`yaml` 里写占位符必须带 `#`** —— `@@REALRUN@@` 裸行 ⇒ `ScannerError`，
   而且冒烟报错只显示「出厂 yaml 解析失败」，看不出是占位符。
5. ★★ **判据失效要在正确的文件版本上取行号** —— 我拿「已注入版」的行号去改
   「原始版」，锚点命中 0 次（第 N 次踩「锚点 0 次」）。
6. ★ **`_is_dup` 是 `_run_layer` 内的局部函数**，模块级取不到。判据要复现它的口径
   （`_overlap_coef ≥ thr or _similar(thr)`），不能用 `mod._is_dup`。
7. ★★ **有 FAIL 时后面判据根本不跑** —— 冒烟前 151 ✓ 里**不含**新判据（它在
   main 尾部，而审计那条 FAIL 提前 `return 1`）。所以「✓ 数够多」不等于
   「新判据跑过」；变异体必须以「显式调用判据函数」为准。
8. ★ **锚点缩进要按实际文件量**（M1 第一版写成 8 空格，实际是 4）。
9. ★★ **改了默认语义，必须 grep「描述它的文案」** —— 产物表头写死「十二项逐项
   来源」，而表体已经是 11 行 ⇒ **真跑产物那一行与它正下方的表格自相矛盾**。
   修法不只是改字：表头改成**动态**（`len(_AUTO_ITEM_ORDER)`），以后加删项不用再
   改文案。★ 这类「产物内部自相矛盾」**离线探针量不到**（探针只量返回值），
   只有真跑产物照得出来。
10. ★ **`grep -n` 是 1-based**，行号列表不能直接当 `lines[i-1]` 的索引再减 1 ——
   我把 grep 给的 18103 写成 18102 ⇒ 7 处锚点全不命中（逐个报「首行不符」）。
11. ★ **删一个维度要 grep 它的「消费点」而不是「定义点」** —— `cand_limit` 有
   **两处**消费（`_build_inp_duel` 与 `_self_check`），第一版只改了前者。
