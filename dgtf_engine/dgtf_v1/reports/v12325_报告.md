- **版本**：`元DGTF-V1.23.25.py`（18593 行 / 896053 bytes / 纯 CRLF；上一版 v1.23.24 = 18491 行）
- **主题**：把上一版**换掉名字**的「结构覆盖率」**按它本来的含义重新设计并加回** ——
  上一版把旧读数改名成了「独立度」（结构视角：有多**新**），

- **性质**：**运行期可见变化**（喂模型的 shape 多一行读数、产物第七节多一段读数）⇒ 不适用「AST 等价跳过真跑」豁免。

## 二、三轮诊断：六个候选凭据**全部实测排除**（本版最费时的部分）

上一版留下的问题是「结构覆盖率该按什么算」。我按「先找凭据、再定公式」的次序做了三轮诊断，
**六个看起来都像的候选，逐个用真产物打掉** —— 这一节是结论的依据，照实写下。

| 候选凭据 | 直觉用途 | 实测结果 | 排除原因 |
|---|---|---|---|
| ① `structural_amps` 撞 `und_aspects`（overlap ≥ 0.3） | 「结构被方面覆盖」 | 4/5 份产物 **max overlap ≤ 0.17** | 7 份里 6 份恒 0 —— **这正是上一版要换掉的那条**（提示词要求「不得复述」，用它打分必然恒 0） |
| ② `aligned_amps` 撞 `und_aspects` | 「结构被对齐上」 | 值域正常 | **已被「对齐覆盖率」占用** —— 再算一遍就是同一条读数改个名 |
| ③ `view.covered_aspects` 撞 `und_aspects` | 「模型自报触及的方面」 | 实测 **`aligned ⊇ covered`** | 是 ② 的**子集** ⇒ 用它做分子等于把「对齐覆盖率」算小一号 |
| ④ `struct_trace.newly` | 「本轮新出现的结构」 | **全空** | 引用体系已改（`A#` 引用实测 0 次），该轨迹已废 |
| ⑤ `amp.polarity` 填充率 | 「结构是否被判过属性」 | **100% 填充** | 零判别力 —— 人人都有值 = 没有区分度 |
| ⑥ 引用表里的 `A#`（`structural_amps` 被引用） | 「结构被后续圈引用」 | **真产物里 0 次** | 模型只引 `C#`（候选），从不引 `A#` ⇒ 分母非零而分子恒 0 |

### 2.1 破局：由「自己触及」重新起算

六个候选都排掉后，**用户给出了定义**，一句话钉定：

> **结构覆盖率 = 被研究出自己触及的概率**

这个定义绕开了上面所有凭据的死结 —— 它问的不是「别人（方面 / 对齐项）提没提到这个结构」，
而是「**这个结构会不会在后续圈的产物里再被自己呼回来**」。据此定公式：

```
结构覆盖率 = |{ sa ∈ structural_amps : ∃ t ∈ 后续圈产物文本, overlap(sa, t) ≥ 0.3 }| / |structural_amps|
```

- **分子凭据** = `_und_self_touch_texts()`：后续圈**自己的产物**文本池；
- **分母** = `structural_amps` 条数（**与独立度同分母** ⇒ 两者可直接对比、可正交）；
- **空池** 记 `None`（不可计算）；
- **视角**：「有多**活**」（独立度是「有多**新**」，两者不同轴）。

### 2.2 凭据池的取舍（写进 docstring，免得下轮以为漏了）

`_und_self_touch_texts()` **取**：
`threads[].desc`、`threads[].polarity_why`、`probes[].question`、`covered_unders[]`。

**刻意不取**：
- `und_aspects` —— 会和**独立度互为函数**（独立度就是拿结构撞方面），取它就破坏正交；
- `evidence[].cite` 里的 `A#` —— 实测引用 **0 次**（见候选 ⑥），取了等于空池。

## 三、算式与正交性论证

### 3.1 两个读数为什么正交

| | 独立度（v1.23.24） | 结构覆盖率（v1.23.25） |
|---|---|---|
| 分母 | `|structural_amps|` | `|structural_amps|`（同） |
| 分子 | 结构**不与** `und_aspects` 重合 | 结构**被**后续圈自身产物**再次触及** |
| 参照物 | **评估阶段圈出的方面**（外部） | **后续圈自己的产物**（内部·自身） |
| 视角 | 有多**新** | 有多**活** |

分母相同、分子参照物不同（一个向外比方面、一个向内比自身产物）⇒ **不是同一条读数的变体**。
实测 **Pearson r ≈ 0.13**（见 §五-4），且 M8 变异体专门破坏这条正交性（让线头影响独立度）后**判据判红**。

### 3.2 与「对齐覆盖率」并存不冲突

「对齐覆盖率」问的是「**方面**被对上了几成」（方面视角），
「结构覆盖率」问的是「**结构**有多活」（结构视角）——
一个是**对账**口径，一个是**活力**口径。第七节并列印出，各自标注量的是什么。

## 八、经验教训

1. **「同名重设计」比「改个名」更能暴露口径问题。** 上一版把结构覆盖率改名成独立度是对的（口径确实错），
   但**原名空着**这件事本身说明还有一路视角没被承载 —— 本版按用户语义补回，两个读数**同分母不同参照物**才正交。
2. **判据会抓出你自己没意识到的错。** `covered_unders` 忘挂 `to_dict` 出口，是冒烟前向守卫当场拦下的。
3. **变异体脚本本身也会自欺。** 把「加载期抛错」当「判红」，8 个变异体全部假绿 ——
   **判红必须能区分「判据返回 False」与「根本没执行」**。
4. **验收判据的对照基准要选对。** 配置同步拿「出厂默认」当基准 ⇒ 被 28 项历史偏离误伤；
   换成「上一版」逐字比 ⇒ 0 差异。**基准选错，判据会稳定地报假红。**
5. **凭据要实测排除，不能靠直觉。** 六个候选凭据全部用真产物打掉 ——
   其中 `A#` 引用 **0 次**、`polarity` **100% 填充**这类事实，**只有跑了才知道**。
6. **`_overlap_coef` 的判据夹具要用「不相似」的样本。** 第一版自检用了互相太像的短方面名，
   `overlap ≥ 0.3` 全部命中，读数失真 —— 夹具的判别力取决于**样本之间够不够不像**。
