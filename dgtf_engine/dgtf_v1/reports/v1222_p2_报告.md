## 三、★ 为什么必须改四处（本轮最贵的一条教训）

任务书只描述了**入口**（prompt schema），没描述**出口**。
`dec_norm` 是**显式白名单 dict**：

```python
dec_norm = {
    "answer": ..., "answered_sub_ids": ..., "evidence": ...,
    "actions": _norm_schema_actions(dec.get("actions")),
    "distance": 0.0,
}
```

不往这里加 `not_do` 键，模型产了也会被**静默吞掉** —— `view.decidable_product`
里根本没有这个键，`_extract_not_do` 读 schema 恒 `None`，现象与「模型不产」
**一模一样**。本项目已踩过同款坑（v1.22 往 `DEFAULT_CONFIG` 加键时被后面
同名键吃掉）。

**通则（写进 changelog）**：凡「给模型加一个新产出字段」，必须同时核
**prompt schema → 归一化白名单 → 抽取函数 → 渲染点**，四处缺一即静默失败。

## 五、未做的 / 遗留

- **真模型跑批未做**（本轮口径：主要做检查、每题只跑 2 次）。「模型到底会不会写
  `not_do`」在真模型上仍是**未测量**的：离线 E2E 证的是**管线通**（桩给了就能一路

  `n_not_do ≥ 1` 的题数占比（任务书原判据 ≥ 2/3）。
- md 侧 rubric（`bench_score.score_decision_rubric`）第三项读的是 `"不做清单" in md`，
  而产物模板的标题是「### 五、不做什么」—— 这个字符串**对不上**，md 侧第三分实际
  只能靠 `fallback=` 拿到。本版**不改**产物标题（改标题是破坏性改动，会让旧断言失效），
  只记录该落差。结构化侧（`score_actions`）才是主判据。

## 六、经验教训

1. **给模型加新产出字段 = 四处一起改**，否则静默失败（本轮最值钱）。
2. **负对照是唯一能发现「判据不可达」的手段**：E2E 第一版正对照全绿、
   负对照红，才暴露出 `orientation` 是入参不是配置键。
3. **rubric 不用改就别改**：任务书 Step 2.4 要求改 `score_decision_rubric(res, gold)`
   —— 该函数不存在，且结构化版早已判 not_do。改判据会把「产出缺失」这个真问题
   掩盖成「判据太严」。
