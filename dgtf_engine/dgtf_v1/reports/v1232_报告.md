## 二、★ 最重要的一条：15 个 thinking stage 键 **永远选不中**

### 2.1 怎么发现的

`thinking` 的解析是：
```python
th = thinking
if th is None and stage:            # ← 只有 stage 非空才查分档表
    th = self.thinking_stages.get(stage)
if th is None:
    th = self.thinking_default
```
审计 **K 类**把「配置里声明的 stage」与「代码里真的传的 stage」对表：

```
声明 23 个 / 代码真的传 8 个 → 15 个永远选不中
```

根因：`_decompose_normal` / `_probe_*` / `_settle_research` / `re_anchor` … **16 个调用点
根本没传 `stage=`** ⇒ 一律掉回 `thinking.default`。**用户把 `decompose_normal`
改成 `enabled` 会毫无效果，而且没有任何提示。**

### 2.2 yaml 自己就是矛盾的

`dgtf_config.yaml` 里那 15 行所在的分组注释写着：

```yaml
      # ── 关：简单映射 / 结构化罗列 / 输出本来就短，思考无收益 ──
      decide_parallel_mode: "enabled"     # ← 注释说「关」，值却是「开」
      ...
```
⇒ **注释与值互相矛盾**。而因为「从未生效」，实际行为一直是「关」（= 注释说的那样）。
`CONFIG_TUNED` 还把「×15」登记成「thinking 分阶段全开」（按值描述，与实际行为不符）。

### 2.3 改法：接线 + 把 yaml 改成与**实际行为**一致

| 动作 | 结果 |
|---|---|
| 新增 `_thinking_stage(cfg, name)` | **以配置为准**：键已声明才返回该名，拼错返回 `None`（拼错 = 静默掉回 default，与没接一样） |
| 16 个调用点接线 | 分档配置**首次真正可控制** |
| yaml 那 15 行 `enabled` → `disabled` | 与注释一致、与**实际行为**一致 ⇒ **行为零变化** |
| `CONFIG_TUNED` 销掉 15 条过期登记 | 登记表两向对账的正常运转（改值就必须销账） |

### 2.4 「行为零变化」的**机器证明**（不是嘴上说）

`--phase v1232` 用**两版配置对读**直接证：

| 判据 | 内容 | 结果 |
|---|---|---|
| `V1` | 每个 stage 的**解析结果**（改前 vs 改后）逐字相同 | ✅（`wired=15 / lit=10`，差异为空） |
| `V2` | 抽样非空（防空过） | ✅ |
| `V3` | 两版配置的差异**只允许**是「改前从未生效」的两类 | ✅（意外改动 `[]`） |
| `V4` | yaml 里被改的 stage 一律 `== thinking.default` | ✅（15 个全 `disabled`） |

★ **怎么真的打开**：把那 15 行的值改回 `"enabled"` —— **本版起会真正生效**。
  这是一次**可测量的变更**（thinking 开启会走 `max_tokens ≥ 32000`、不带 temperature，
  成本与耗时都会上去），所以本版**不擅自替你打开**，只把开关接通。

### 二、三票正交度（W4 的验收）

**度量**：逐条子问题取三票标签，算两两一致率 `agree12 / agree13 / agree23`。

★ **口径**：一致率按**可用票对**汇总 —— 遍历「所有跑 × 全部子问题」，
  只要该对两张票都投了就计入。**只有 2 票可用的跑不再被整跑丢掉**

第三票与前两票的一致性应**低于**前两票之间的一致性（它不是复读机）。

#### 2.1 第三票是否「特立独行」（臂内比较）

- **ON（第三票 = 外部证据裁判）**：均值 agree12=0.556 / agree13=0.528 / agree23=0.361 ⇒ 第三票相对前两票的落差 = **0.028**（agree12 的**跨组**极差 0.834）
  · **方向**：落差 > 0（第三票与前两票的一致性更低）
  · ★ **但这个均值的落差没有减去噪声**：本臂的 agree12 组内极差 = 0.167，落差 = 0.028 ⇒ **落差 ≤ 组内极差 ⇒ 不可判定**（只是方向线索）
- **OFF（第三票 = 普通中立票，W4 未生效）**：均值 agree12=0.445 / agree13=0.333 / agree23=0.778 ⇒ 第三票相对前两票的落差 = **-0.333**（agree12 的**跨组**极差 0.500）
  · **方向**：落差 ≤ 0（第三票与前两票一致度不低于前两票之间）
  · ★ **但这个均值的落差没有减去噪声**：本臂的 agree12 组内极差 = None，落差 = -0.333 ⇒ 落差 > 组内极差（仍需看 2.2 的三项对账）

#### 2.2 组间 ≥ 组内？（这是「能不能拿这个指标下结论」的前提）

| 指标 | 组间差（不同题的规定） | 组内极差（同题两跑） | 可判定？ |
|---|---|---|---|
| agree12 | 0.832 | 0.167 | 可判定 ✅（组间 ≥ 组内） |
| agree13 | 0.083 | 1.0 | **不可判定 ✗**（组内极差更大：1.0 > 0.083） |
| agree23 | 0.582 | 0.333 | 可判定 ✅（组间 ≥ 组内） |

#### 2.3 结论（写死，免得读者自己在数字里推断）

1. **「三票正交化」的统计可判定性**：三个指标里 **2 个可判定**（agree12、agree23）、**1 个不可判定**（agree13）。不可判定的那些是「组内极差 > 组间差」= **噪声大于信号**。
   ⇒ 「第三票是否更特立独行」**只能说方向线索**，**不许写成「正交度已验证」**（ON 臂落差见 2.1 与其组内极差的比较）。
2. **负对照的完整度**：本批 10 跑里 **1 跑**存在「不足 3 票」的子问题（OFF 臂 0/3）⇒ 涉及第 3 票的指标在这些跑上算不出来，ON vs OFF 的对照会缺腿。
3. ★ 但本次**测出了一件实质问题**（比正交度本身更重要）：
   **「三票」会静默退化成两票** —— 某票返回**合法 dict 但 `judgments` 为空**时，
   既不报错也不留痕，`ok_votes` 还照样 +1 ⇒ 读者在产物里看不出「三票实际两票」。
   v1.23.1 已补留痕 `[三态多票] N/3 票可用（空票 K 张）`（**纯留痕**）；
   v1.23.2 起再加 **`actions.tri_vote_retry_empty=1`（空票重试一次）**。
   ⇒ 本批就是**开启重试之后**的数据：不足 3 票的跑从上一批的 **4/10** 降到
     本批的 **1/10**（对照见 `v1231_报告.md` §四）。

### 6.1 ★ 判据形态修正：`P2.4.a` 从**采样**改成**构造性证明**

`v1231_报告.md` §十 没提这一条，是**本版自己发现的**：`P2.4.a` 断言
「三题真跑里 ≥1 题 triage ≥1 条」—— 而 `triage` 是**低概率随机机制**：

| 批次 | 配置 | 真跑 **10 份产物**里 triage ≥1 的份数 |
|---|---|---|
| v1.23.1 那批 | 同 config | 2 份（含全路由跑） |

⇒ 用 n=3 采样去判「机制**能不能**触发」，**本质是掷硬币**。
两步修法：

1. **抽纯函数**：把 triage 的组装逻辑从 `_anchor_crosscheck` 抽成
   `_triage_suggestions(und_aspects, anchors, cfg)`（行为一字不改，只搬位置）；
2. **判据改构造性证明**：喂已知合格输入 ⇒ 断言必产 ≥1 条；配 3 条负对照
   （真·自指 / 不属「缺外部材料」/ 锚点 tier 超门）+ **2 个变异体**
   （破坏 tier 门 / 破坏自指剔除 ⇒ 对应负对照必须判红）；
   真跑采样读数降为**观察项**（打印 `[0,0,0]`，**不判红**）。

★ 通则：**能力存在性用构造性证明，效果大小才用采样。**
★ 本版也顺手把「P2.4.a 的采样口径」算清了：`_p24_power.py` 读**本版全部 10 份
  产物**，读数 **k=1/10**（见 §三 的 `P2.4` 行与脚本）—— 这才是这条机制的真实频度。

### 6.2 ★ 抽函数的连带：**区域判据**成批失效

「triage 组装逻辑搬走」之后，4 条**区域判据**（判据的锚是「某个函数体内必须出现
某字面串」）全部判红 —— 它们读的区域里不再有那些调用：
`P2.1.b` / `P2.1.c` / `P2b.4.a` / `P2b.4.b` / `P2b.4.a2` / `P2b.4.a3`，

  按函数体取区域。

## 九、经验教训

1. ★ **「配置写了但没生效」要当成一类 bug 系统性地查** —— 本版一次查出 **13 个**
   这样的键（15 个 stage 中的 11 个 + `tier_floor` + 2 个「声明了不做」）。
   **判据**：`DEFAULT_CONFIG` 的每个键都要能在源码里找到**读点**（J 类），
   且 stage 型键还要能**被选中**（K 类）。
2. ★ **注释与值矛盾时，先怀疑值** —— 那 15 行的注释写着「关」、值是 `enabled`，
   而实际行为是「关」。**把值改成与实际行为一致**（而不是让行为跟着错值跑），
   才是「先量后改」的最小步。
3. ★ **接线（让配置生效）本身是有风险的改动**，必须配「行为零变化」的机器证明
   （`V1`/`V3`/`V4`）——否则「修好配置」会顺手把一个从未生效的高成本档悄悄打开。
4. ★ **局部变量与模块级函数同名 = 定时炸弹**（`UnboundLocalError`，且报错位置
   离定义很远）。凡新增模块级函数，先 grep 同名局部。
5. ★ **变异体的锚会随实现失效**；失效时**改到新语义**，不是删掉变异体。
   （本版两处：W# 进表的连续锚 → 尾段锚。）
6. ★ **`x or default` 会吃掉 0/""/False** —— 只有 `None` 才该回落默认值
   （`tier_floor: 0` 的语义是「谁都不许进」）。
7. ★ **审计必须有自检变异体**：没有它，「全绿」只能说明判据没跑。
8. **判据代码自己也会有 bug**（本版 7 处）：抠不出东西就「空过」、引号类型不匹配、
   忘了套 `%`。**判据必须先证「非空」再判**。
9. ★ **判据的「样例形状」也是判据的一部分**：把**裸字符串**传给期望**列表**的参数
   （`_triage_suggestions(und_aspects, …)` 内部 `for _a in (und_aspects or [])`）
   ⇒ 变成**逐字符迭代** ⇒ 恒返回空 ⇒ 变异体永远不判红（**假绿**）。
   写判据样例时，先确认入参**类型**与实现一致。
10. ★ **负对照的样例必须落在「被变异体的那个条件」上**：
    「真·自指」样例若不是 triage **候选**，拦住它的是 `_is_triage_candidate`，
   抠掉 `_is_never_downgrade` 它照样不触发 ⇒ 变异体测不到东西。
   正解：样例要**同时**满足「候选」且「自指」。
11. ★ **重构搬函数 = 成批触发「区域判据」失效**：本版把 triage 组装逻辑搬进
   `_triage_suggestions`，一口气让 **7 条**区域判据判红（P2.1.b/c、P2b.4.a/b/a2/a3、
   冒烟 `check_v1221_p2b` 第 7 步）。搬之前先 grep「按函数体取区域」的判据，
   搬完把它们改成「两处之和 + 钉调用关系」。
12. **生成器被 heredoc 撕坏**（`\n` → `/n`，本轮第 7 次）：改脚本/主文件**一律走
   脚本文件**；写完立刻 `ast.parse` + 跑一次。
