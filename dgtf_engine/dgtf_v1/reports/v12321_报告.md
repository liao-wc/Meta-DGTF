# v1.23.21 报告 · LLM 每次调用后输出 token 累计

- **版本**：`元DGTF-V1.23.21.py`（相对 v1.23.20）
- **主题**：在 LLM 调用点补一行 `logger.info("[tok] calls=%d tokens=%d", …)`，
  让调用方（工作台）能在**运行中**读出实时 token。
- **一句话结论**：纯**新增输出**，产物零变化；读数走 `logging` 不走 `vp`，
  所以关 `verbose`（v1.23.20 的默认姿态）也看得到。

## 结论速览

| 项 | 改前 | 改后 |
|---|---|---|
| 运行中的 token 读数 | 无（只在**结束**时打一次 `完成 \| N 次 LLM \| M tokens`） | 每次调用后打一行**累计** |
| 产物 md / packed.json | — | **一字不变** |
| 与 `verbose` 的关系 | — | **无关**（走 logging） |

## 逐项

1. **LLM 调用点**（`total_calls` 累加处）：锁内取快照、**锁外**打
   `logger.info("[tok] calls=%d tokens=%d", _tok_calls, _tok_total)`。
   为什么要取快照：避免在持锁时调 logging（也顺手拿到一致的一对数）。
2. docstring 标题 / `__version__` → `1.23.21`。
3. `dgtf_config.yaml` 头部版本 → v1.23.21（**键无增删**）。
4. `CHANGELOG.md` 顶部插入 v1.23.21 段。

## 经验教训

1. **「运行状态」与「调试细节」要分通道**：`vp` 受 `output.verbose` 控制，适合调试细节；
   运行状态读数必须走 `logging` —— 否则 v1.23.20 把 verbose 关了之后，读数会跟着一起消失
   （而读数恰恰是给"不想看细节"的人用的）。
2. **解析行要与显示行分离**：`[tok]` 由应用层消费并从卡片日志滤掉，
   否则真跑 ~269 次调用会往日志面板灌 269 行噪声 —— 那正是 v1.23.20 刚清理掉的那类东西。
