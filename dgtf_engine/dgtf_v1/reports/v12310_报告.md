## 二、四项各做了什么

### R1 形态声明（落地层读得懂「哪些是模板约定」）

新增纯函数 `_with_form_declaration(res, body, template, why)`，在落地层标题**之后**
插一行：

```
> **形态声明**：本次落地层用 **decision** 模板 —— 取向 decision：题面含决策语境。
> 模板里的分节（如 decision 的「行动清单 / 负责人 / 时限 / 验收」）是**渲染约定**，
> 不等于提问者的要求。
```

- **必须插在标题之后**：md 里标题前放正文，那个标题就不再是章节标题（探针钉住这条）；
- 三处 `return` 全部包上（boundary 短路 / auto 无决策语境 / decision），
  每条都有各自 `why`；
- 缺 `question` 键时不许崩（探针钉住）。

### R8 附录外置（红线不变，只换位置）

新增纯函数 `_appendix_to_file(text, side_path)`：把附录里的内联全量 JSON
搬到同目录旁挂 **`<产物名>.packed.json`**，正文只留统计行 + 文件名 + 读法。

- ★ **`_render_full_appendix` 一字未改** —— 它依旧是「机械全量」的权威实现；
  新函数只做**搬运**，搬运失败就原样退回内联并留痕，绝不悄悄丢；
- 默认 `file`（`--appendix inline` 回旧行为）；
- 判据 `check_v67_full_appendix` 取源改到**两路都能取**（内联 / 旁挂），
  **判据意图一字未改**。

### R9 成本档自动路由（纯规则，不调 LLM）

新增纯函数 `_auto_profile(question)`：无决策语境 → `economy`，有 → `balanced`
（**不选 `quality`** —— 那是「不裁剪」，留给显式要求的人）。`--profile auto` 启用。

★ 注释里写明：`--profile` 只改 **token 裁剪**、**不改圈数** —— 要真控规模还得
显式传 `--rounds`（v1.23.9 实测：economy 反而跑了 12 圈）。

### R10 事实题未校验留痕（把「没校验」变成显式选择）

事实型询问（`not _has_decision_context(question)`）的产物里显式写明：

```
★ **本题是事实型询问，但本次未接入外部校验** —— 这是一次**显式选择**，不是默认特权：
  - 要接入：`--web on`（或配置 `web_search.*` 五档）。
  - 接入后头部会多出「锚点对照 / 冲突 / triage 降级」各行；
  - 未接入时，史实类结论**没有外部证据支撑**，请自行核对。
```

决策题**不出这句**（判据两向钉住）。

## 六、经验教训

1. ★★ **「用真实数据的快照重渲染」是渲染层改动的最优验收手段。**
   产物里的 packed 附录就是一份完整的输入快照 ⇒ 把它抠出来喂 `save_result`，
   就能在**零 LLM 调用**下复现整条渲染链。比合成 fixture 真，比真跑便宜三个数量级。
   **前提**：改动确实只在渲染层（本版四项都是）。
2. ★ **判据取源外移时，要同时把「取不到」写成显式分支。**
   v67 判据从「内联 JSON」改成「内联或旁挂」后，如果只加一个 `else: 读旁挂`，
   就会出现「两种都没有」时静默走空值。本版显式写了两个失败分支并各自报错。
3. ★ **`with TemporaryDirectory()` 的作用域是个静默陷阱**：出了块，文件在，
   但你读不到 —— 报的错是「不存在」，很容易被当成「渲染没写」。
   **凡在临时目录里落盘的东西，要在块内读完再出去。**
