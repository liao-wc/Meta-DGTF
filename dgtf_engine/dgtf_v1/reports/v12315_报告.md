## 二、窗口效应：分层抽样 + 时间衰减

### 2.1 `history_limit` 的语义改了：从「总样本数」到「**每题型上限**」

v1.23.14 的取样实现是「按 mtime 倒序取最近 N 个文件，边扫边分桶」。
问题：窗口一缩，**事实型会被整体挤掉** —— 「按题型比同类」退化成「比全语料」。

改法：两桶**各自**最多取 `limit` 条，扫描上限放宽到 `4×limit`；
`_put` 在两桶都满时提前停。

★ **判据用夹具**，不只数真实语料 —— 真实语料里两桶都够，看不出挤掉：
造一个「最新 2 份事实型 + 最旧 2 份决策型」的临时目录，`limit=2` ⇒
正确实现两桶都收满（4 份），「按总数限流」的实现会在收满事实型后停手（决策型 0）。
变异体 M1 打的正是这一点。

### 2.2 时间衰减：加权分位

读数从「普通分位」改成 **加权分位**，权重 `w = 0.5 ** (age_days / 半衰期)`：

- 新键 `auto.history_halflife_days`（出厂 **14 天**）；`0` = 不衰减（等权）。
- 为什么需要：语料跨了十几天，**旧样本是旧配置下的读数**
  （那时默认给满 12 圈、成本档是 balanced），与今天的读数等权平均会把结论拉向旧行为。
- 半衰期 14 天 ⇒ 两周前的样本权重 0.5、四周前 0.25。

★ 判据**两向**：① 三条记录（两条 28 天前的 100 + 一条今天的 10）
加权中位数 **10** < 等权中位数 **55**（确实偏向新样本）；
② 把半衰期设 0 ⇒ 加权分位**必须等于**等权分位（负对照，防「加权写成了别的东西」）。

### 2.3 抽取器补齐：联网行 + 「抽不到的字段不写键」

- 新增抽 `**外部锚点 · 联网**（`web_search`）：**开** —— 收 N 条（…）；失败 M 条`。
- ★ **抽不到的字段不写键**（不是写 0）：
  「`web_fail = 0`」与「这一行里根本没有失败子句」是两件事 ——
  前者能算「失败率分母」，后者不能。判据专门守这条（含「只有收条数没有失败子句」的负对照）。

## 三、真跑对照实验

### 3.1 方案（以及为什么砍掉两个组）

**同题、同模式（serial）、同 route（全四层），只改圈数上限**；
另跑一次 **auto 默认**（不传任何参数）验证统一调度器在真跑里生效。

原本设计四组（上限 2 / 6 / 10 / auto），**实测单次 LLM 调用 ≈ 25 秒**，
up2（四层 × 2 圈）单独就用了 40+ 次调用；up6 / up10 是 3× / 5× 规模，
预计 1.5 小时以上，而**边际价值低**：

## 四、结论：「上限给多少」

**用实测回答：上限给多少最省？**

两点对照给出的是一个**反直觉**的结论：

1. **「给足上限让它自然停」这条路走不通**。上限 2 ⇒ 四层全截断；
   上限 4/4/5/7 ⇒ **仍有 3/4 层被截断**，只有 1 层自然停。
   ⇒ 在这类题上 **上限就是成本**（实际停圈 == 上限），成本与上限近似线性：
   圈数约 2× ⇒ calls 79 → 193（2.4×）、tokens 74 万 → 242 万
   （**3.3×**：每圈上下文更长 + 联网 24 条）。
2. **所以「最省」不等于「上限最小」** —— 上限 2 的 79 calls 是**被截断**的产物
   （元层只跑 3 圈、四层全部「未触发任何停止判据」），质量没有交代。
   最优是**按历史给「够用」的上限**：这正是 v1.23.14 把 `_AUTO_ROUNDS_BASE`
   定为实测 p50（修行 4 / 研究 4 / 对撞 5 / 元 6）而不是给满 `hard_max = 12` 的依据。
   本轮复核这条基线：真实语料 `cap_rounds` 的 p50 也是 3~4，与 4/4/5/6 同量级。

**对调度器的直接含义**：
- `_auto_pick_rounds` 的回退链（实际停圈 → 种子上限 → 按层实测默认）**方向是对的**；
  但**别指望「跑够就会自然停」** —— 停止判据的零触发率应当作已知事实，
  于是「历史上限（p50）」比「跑满」更接近最优。
- 「实际停圈」这一行本版起才有真数据，往后会**累积出可用的历史上限**；
  在此之前 `cap_rounds` 的 p50 是唯一可用的代理。

**成本口径（本轮实测，供下次估算）**：单次 LLM 调用 ≈ **25 秒**；
四层 × 2 圈 ≈ **38 分钟 / 79 calls / 74 万 tokens**；
四层 × 4/4/5/7 圈 + 联网 ≈ **约 45 分钟 / 193 calls / 242 万 tokens**。
（据此砍掉 up6/up10 —— 见 §3.1。）

## 六、本轮踩的坑（已写进 `dgtf-version-bump` 技能）

1. ★★ **「无数据支撑」先查是不是抽取器漏了**。三条零样本里，最刺眼的一条
   （三态一致率）在产物里**有 254 份**，只是抽取器没写那个正则。
   ⇒ 报「样本不足」之前，先量一遍**覆盖率**（每个待抽字段有几个文件命中）。
2. ★★ **拍脑袋的阈值可能落在实测中位数附近，于是「保护」变成「禁用」**。
   0.5 这个「质量保护线」在实测（中位 0.333）里会拦掉 54%，
   等于把降档功能废掉。⇒ 阈值必须看分布，不只看「听起来合理」。
3. ★★ **插入点必须晚于它用到的所有变量**：v1.23.15 首版把
   「取样口径」那两行插在 `_hl` 赋值**之前** ⇒ `UnboundLocalError`，
   `_auto_dispatch_lines` 一调用就炸，**产物渲染整个失效**。
   是**上一版的留存判据**（v12314「产物渲染异常」）抓出来的。
   ⇒ 这也说明「老判据继续跑」是有价值的。
4. ★★ **补丁脚本的升级段也要幂等**：v1.23.14 的配置同步脚本我跑了两次
   （第一次口径 FAIL、改完再跑），而它**没给升级段做幂等** ⇒
   yaml 里同一段出现两次（手工去重，并在本轮加了显式判重 + 重复计数断言）。
   ⇒ 这条我自己写进技能第 25 条，然后又踩了一次。
5. ★★ **变异体的样例要选在「两种实现会分歧」的地方**（第二次强调）：
   - M1（不分层）：夹具用「3 事实 + 1 决策、上限 2」时，两种实现结果**相同**；
     改成「2 事实在前 + 2 决策在后」才分岔。
   - M5（缺字段写 0）：把 `setdefault` 放在 `if _mw:` 块**内**时，
     「没有联网行」的样例根本走不到它；移到函数出口才判红。
6. ★ **判据里的局部变量名会撞车**：判据里 `import time as _t`，
   而夹具循环变量也叫 `_t` ⇒ `'str' object has no attribute 'time'`。
   ⇒ 判据里给**导入别名**加前缀（`_tmod`），夹具变量另起名。
7. ★ 真跑成本要**先估再跑**：单次调用 ~25 秒，四层 × N 圈的成本随 N 近似线性增长；
   本轮据此砍掉 up6/up10，用 up2 + auto 两点对照（§三）。
