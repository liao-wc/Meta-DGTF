# 元 DGTF v1.24.0 · V2 影子 + 双写 + 契约 + 初始接管

- **版本**：元DGTF-V1.24.0.py（27757 行 / 单文件 / 纯 CRLF / 在 v1.23.66 上增量）
- **主题**：Phase 1——把 V2 三平面控制面以**影子模式**接进生产跑次；只观察，不改执行。
- **参考内核**：dgtf_v2/（41 项判据；20 份 packed 回放）
- **生产行为**：默认 scheduler.v2.enabled=false；本机 yaml 开 true 收集数据。

## 一、接了什么

MetaDGTF.run() 在 mode / route / rounds_plan 决定后挂载 dgtf_v2.shadow.V2Shadow：

- 起点：把初始层状态映射成 V2 WorldState，Scheduler.plan() 记录 V2 会先选哪层；
  与 V1 实际首层比较，写 v2_shadow.at_start.agreement。
- 终点：从 packed 还原层状态，记录 V2 在结束时还会不会继续（at_end）。
- 参考轨迹：用本次层读数喂 EML（只数值），在 mock 层上跑一次 V2 策略，
  写 v2_shadow.hypothetical，并明确标注“mock 参考，不是真实输出质量”。
- 产物：v2_shadow 进 packed；md 加一行“V2 影子调度”。
- 失败：只写 v2_shadow.error / logger，不阻断 V1。

**没有改变**：层顺序、圈数、停止阈值、prompt、答案、EML 的读写路径。

## 二、Phase 2：EML 双写

V1 的 episodes/playbook 继续原样写；V2 另起一份事件库：

    dgtf_memory/v2_events.jsonl

- 只写结构计数（候选/&/线头/悬置/探针）与 outcome（模板/质量/calls/tokens）；
- **不写答案正文**，不迁移、不删除 V1 记忆；
- 无 run_id 的测试/匿名跑次默认不写（allow_anon=false），避免污染生产库；
- 影子启动时从该库加载历史先验，跨跑先验开始积累。

## 三、Phase 3：契约体检（warn → raise）

V2MemoryBridge 把 packed 里的 View/Pool 映射成 LayerResult，逐层 validate：

- contract_gate=off：不查；
- warn（本机默认）：只写 v2_shadow.contracts，不阻断；
- raise（opt-in）：影子内抛 ContractViolation，被引擎兜住并记 error，**仍不影响 V1 主流程**。

首次用真实 packed 体检就抓到两类结构性缺口：

- 1 层 decidable 答案没有 citations；
- all 层 actions 为空（V1 的闭合是渲染出来的，不是结构化产物）。

这不是“V1 坏了”，而是说明 Phase 5 必须把层内产物契约化；在 warn 阶段先把缺口统计出来。

## 四、Phase 4：初始串行接管（opt-in）

默认 takeover=false；设为 true 且 mode=serial 时：

- V2Shadow.propose() 用空记忆 + mock 层跑一次 scheduler，得到 order/rounds；
- 若提案覆盖全部 route，写入 rounds_plan 与 _dispatch_plan；
- 层内仍调用 V1 的 _run_layer（不改 prompt/算法）；
- packed 增加 v2_takeover（applied/order/rounds/why）；
- 提案不覆盖全部 route ⇒ 回退 V1，不静默混跑。

**限制**：这是「初始排程」接管，不是动态逐层重规划；Phase 5 才能改层内机制。

## 八、真跑 A/B pilot（5 对 / 10 跑）

协议：同题、600k、serial；V1 自动排程 vs V2 takeover；评分用 bench_score。

| 题 | V2 | V1 | V2 成本变化 |
|---|---|---|---|
| Q1 远程办公信任 | 79 calls / 477k / 5/5 / .333 / 3/3 / 闭合 | 108 / 649k / 4/5 / .400 / 3/3 / paused all | −27% |
| Q2 数字 IC 边界 | 89 / 585k / 4/4 / 1.000 / 0（boundary）/ 闭合 | 109 / 625k / 3/6 / .333 / 0 / paused all | −6% |
| Q3 开源贡献者 | 80 / 495k / 2/2 / .833 / 3/3 / 闭合 | 109 / 637k / 4/4 / .667 / 3/3 / paused all/both | −22% |
| Q4 气候政策 | 88 / 523k / 5/5 / .500 / 3/3 / 闭合 | 120 / 632k / 4/4 / .500 / 3/3 / paused all/both | −17% |
| Q5 信息不完整选型 | 89 / 575k / 1/2 / .500 / 3/3 / 闭合 | 113 / 620k / 4/4 / .333 / 3/3 / paused all | −7% |

**汇总**：

- 完成率：V2 **5/5**；V1 **0/5**（全部被 600k 截断）。
- calls：V2 均值 **85.0**；V1 **111.8**；**−24.0%**。
- tokens：V2 均值 **531.1k**；V1 **632.4k**；**−16.0%**。
- 研究覆盖：V2 均值 **90%**；V1 **86%**。
- 三态：V2 均值 **.633**；V1 **.447**。
- 决策 rubric：两侧都是 3/3（Q2 boundary 0）；动作 3–6 条。
- 取舍：V1 在 Q1/Q5 覆盖更高；但五题都没闭合。V2 在成本 + 闭合上占优。

**2M 追加观察（Q1）**：

- V2 2M preset：89 calls / 528k / 四层闭合 / 覆盖 .5429 / 三态 .333；
- V1 2M 主配置：跑到 128 calls / 882k 仍停在 both，手动停止（超过 V2 全闭成本的 1.67 倍，非完成跑次）。

说明 2M 预算不是 V1 的瓶颈；瓶颈是初始排程把预算花在 0/1/both，all 迟迟轮不到。

**结论**：V2 takeover 进入推荐 preset（configs/方案G-V2接管.yaml，2M），但主配置仍默认 takeover=false；Phase 5 层内重写仍需逐层 A/B。完整表见 v1240_ab_pilot.md。
