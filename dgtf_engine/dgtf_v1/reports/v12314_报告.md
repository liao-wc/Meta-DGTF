## 一、为什么做这件事（两个真问题）

v1.23.13 的十二项自适应**读不到历史**：

| # | 问题 | 后果 |
|---|---|---|
| 1 | `_auto_history` 只扫 `**/*.packed.json` —— 而 `outputs/` 里有 **368 份产物 md**、只落了 **1 份** packed（旧版本不落 packed） | 历史样本 = 1 ⇒ 「历史自适应」形同虚设；所有阈值实际都在走「无历史」分支 |
| 2 | 它把「实际停圈」的字段名读成了 `rounds`，真实字段是 **`rounds_run`** | `dict.get` **静默**返回 `None` ⇒ 即使有 packed 也永远取不到「实际停圈」。而且产物里**没有任何渲染点**写这个量 —— 信号既没被读、也没被记 |

⇒ 本轮把历史语料接上，并**用实测分位替换拍脑袋的阈值**。

## 三、实测读数（全语料 384 条 vs 最近 200 份窗口）

**★ 重要发现：读数对「取样窗口」敏感** —— 同一份代码、同一批语料，只改窗口大小，
分位数就变了：

| 读数 | 全语料（368 md + 16 批） | 最近 200 份 md 窗口 | 差异 |
|---|---|---|---|
| `tokens` p50 / p75 | 534,416 / **1,050,814** | 287,455 / **711,161** | p75 差 **1.5 倍** |
| `calls` p50 / p75 | 108.5 / 171 | 63 / 135 | p75 差 27% |
| 种子上限 p50（修行/研究/对撞/元） | 4 / 4 / 5 / 6 | **3 / 3** / 5 / 6 | 前两层差 1 圈 |

⇒ **绝对阈值（如「40 万 token 就算贵」）会随窗口漂移而失效**。
这直接决定了本版的设计：**成本档改判据为「相对」**（同类题中位 vs 全语料 p75），
不写死绝对数字。

## 四、改了什么

### 4.1 修字段名 bug（`rounds` → `rounds_run`）

```python
-        _rn = (_v or {}).get("rounds")
+        _rn = _v.get("rounds_run")   # ★ 真实字段；读错时 dict.get 静默返回 None
```

并在产物头部新增一行，把这条信号**落进产物**（此前既没被读也没被记）：

```
**调度**：研究(1圈)
**停止**：自然 0 层 / 被截断（体力耗尽）1 层 ⚠️ 无一层自然收敛
**实际停圈**：研究 1 圈（上限 1）
```

### 4.2 历史取样扩到三类来源

新增 `_hist_from_packed` / `_hist_from_md` / `_hist_from_batch` + 累加器
`_hist_blank` / `_hist_add` / `_hist_finish` / `_hist_quant`：

- **md 只读前 8KB**（头部信息全在里面，正文可能几百 KB）；
- md 的圈数归 **`cap_rounds`（种子上限）**，packed 的 `rounds_run` 归
  **`actual_rounds`（实际停圈）** —— 两者**分开统计**，不混；
- **按题型分桶**（`by_type.fact` / `by_type.nonfact`），策略变成「同类题比同类题」；
- 半损坏样本只丢自己那几项；空目录 / 坏 JSON 都不崩。

**实测效果**：样本 `1 → 217`（1 packed + 200 md + 16 跑批），扫描耗时 **0.16 s**。
关掉 md/跑批两个源的负对照：样本掉回 `1`（证明样本量确实靠扩源拿到）。

### 4.3 阈值改成实测 / 相对

| 项 | v1.23.13（拍脑袋） | v1.23.14（实测依据） |
|---|---|---|
| 成本档降档 | `tokens_med ≥ 400000`（绝对） | **相对**：同类题 `tokens_med ≥ 全语料 tokens_p75` 或 `calls_med ≥ 全语料 calls_p75` |
| 圈数基线 | 无历史统一 `soft_max+2 = 5` | **三级回退**：实际停圈（需 ≥3 份样本）→ 种子上限（实测）→ 按层实测默认 `{0:4, 1:4, both:5, all:6}` |
| 圈数采纳门槛 | 「有就用」（1 份也算） | **≥3 份样本才采用**（实测：语料里实际停圈只有 1 份，单条噪声会盖掉 200 份的上限分布） |
| 截断率不砍层 | 0.5 | 保留 0.5，**标注**实测 0.333 但仅 6 层样本 |
| 三态一致率 | 0.5 | 保留，**标注** n=1 |
| 联网两条规则 | ≥3 | 保留，**标注**零样本 |

理由字符串也一起改了 —— 现在逐层报**钳制后**的值与来源与样本数：

```
按层：修行=4(种子上限(n=192)，原始 3 被钳)、研究=4(种子上限(n=197)，原始 3 被钳)、
      对撞=5(种子上限(n=68))、元=6(种子上限(n=68))（实际停圈需 ≥3 份样本才采用）
```

### 4.4 产物里的历史行也带上来源与分位

```
- 历史读数：**217 份**（batch 16、md 200、packed 1）· token 中位 287455 / p75 711161 ·
  calls 中位 63 / p75 135 · 三态一致率 1.00（n=1）· 被截断率 0.33（n=6 层）·
  联网 收96/失败0（8 跑有入池）· 取向错配 0
- 分题型：事实型 79 份（token 中位 —）/ 决策型 132 份（token 中位 —）
```

★ **样本量、样本来源、每个读数的 n** 都写出来 —— 这样读产物的人能自己判断
哪个读数可信（`n=1` 的一致率与 `n=192` 的种子上限显然不是一个量级）。

## 六、本轮踩的坑（已写进 `dgtf-version-bump` 技能）

1. ★★ **产物头部键**半角/全角冒号混用**：`**资源**: ` 是半角、`**调度**：` 是全角。
   抽取器只写全角 ⇒ 命中 0 条，样本停在 17 而我一度以为「语料只有 17 份」。
   ⇒ 解析历史产物一律写 `[:：]`；**先量覆盖率再写正则**。
2. ★★ **判据的样例要选在「两种实现会分歧」的地方**（M5/M6 假绿，见 §5.2）。
3. ★★ **`dict.get` 读错字段名是静默的**：`rounds` vs `rounds_run` 不报错、返回 None，
   于是「实际停圈」这条读数**一整版都没生效**。⇒ 读快照字段前先 `grep` 真实字段名
   （本项目第 N 次踩同类：`留痕字段名用之前先 grep`）。
4. ★ **读数对取样窗口敏感**（p75 差 1.5 倍）⇒ 阈值别写绝对值；
   要写就写**相对判据**，并把窗口大小与样本数一起报出来。
5. ★ **单条样本的「中位数」不该当作可用读数**：任何聚合都要带 `n`，
   策略要按 `n` 决定信不信（本版引入 `_AUTO_ACT_MIN=3`）。
6. ★ **heredoc 里写 `\n`/`\u` 转义会被再吃一层**（第 19 条的老问题又踩了一次，
   这次症状是探针里的替换断言「命中 0 次」）⇒ 含转义的补丁脚本一律用 Write 落盘再跑。

## 八、未做 / 边界（如实记账）

1. **三条规则当前无数据支撑**（截断率仅 6 层、三态一致率 n=1、联网失败/空结果 0 次）。
   保留 + 在产物里标注 n，**不宣称已校准**。等语料涨上来（尤其「实际停圈」行
   本版才开始写）再校准。
2. **`history_limit=200` 的窗口效应未消除**：语料再涨到上千份时，
   应该改成「按题型分层抽样 + 时间衰减」，而不是简单取最近 N 份。
   本轮已把「窗口敏感」这件事事实化（§三），但没做加权。
3. **未真跑**：取样与阈值都是纯规则，用真实语料 + 合成样例即可完整覆盖；
   唯一需要真跑的是「按新圈数基线跑一轮看停止行为」——属采样验证。
4. **`cap_rounds` 与 `actual_rounds` 的语义差**已分开统计，但**没有**据此推断
   「上限给多少最省」——那需要「同一题不同上限」的对照实验，属另一件事。
