## 一、缺口（实测，不是推测）

v1.21.67 的日志「流收全」了（stdout / stderr / logging 都进同一文件），
但引擎**每圈只打摘要**：

| 内容 | 旧行为 | 后果 |
|---|---|---|
| 候选 candidates | 只报**条数**（`📋 展开候选 N 条`），明细 `c.desc[:50]` 截断 | 正文不进日志 |
| `ing` 对撞（`view.collision`） | 只报**字数**（`🔥 ing 输出 N 字`） | **正文完全不在日志里** |
| 悬置 / 债务 / 清算 / 自省 | 只报计数 | 明细不进日志 |
| 视角展开原文 | `raw[:200]` 截断 | 长输出被切 |

**为什么后果严重**：出问题只能从产物反推，而产物**只留最后一圈的 view**
（`_run_layer` 每圈新建 view、只 return 最后一个）—— 中间圈的正文
在不落日志的情况下**永久丢失**。

## 二、[A] 每圈全量留痕：`DGTF.dump_round(view, inp)`

**做法**：在 `DGTF.run` 末尾（`return view` 前）调用一次
`self.dump_round(view, inp)`，把本圈 view 的所有字段逐条写进当前输出流
（真跑时即日志）：

```
╔══════════════════════════════════════════════════════════╗
║ 圈全量留痕 · entry=1 · 第 2 圈 · 转向
╚══════════════════════════════════════════════════════════╝
   ├ collision：str 925 字
   │ 一、让两端各自把话说完
   │ 0 端要的是一组退水曲线：同一节点在连续两场雨之间不叠加深水……
   ├ settlement：dict 0 项
   ├ …
   └ 圈全量留痕结束
```

实现要点：

1. `dataclasses.asdict` **逐字段**输出，**不截断**；
2. **动态属性也要带上** —— `asdict` 只覆盖 dataclass 字段，而
   `_expanded_descs`（去重账）是运行期挂上去的，单独补一段；
3. 列表 / 字典走 `json.dumps(ensure_ascii=False, indent=1)`；
   多行字符串**逐行加 `│` 前缀**（保持标记可读、且不丢换行结构）；
4. **asdict 抛异常也要写一句**（留痕，不许静默）；
5. `self.verbose` 关闭时直接返回 —— 被刻意静音的子运行（可判定性评估等）
   不会被这份留痕污染。

**★ 为什么挂在 `DGTF.run` 而不是各个跑圈循环里**：全库只有 **3 个**
`dg.run(` 调用点（serial / 汇流 / 其它通道）—— 挂在 `run` 里**一次覆盖
所有通道与并行模式（A–H）**，不必在 10 个模式里各补一行、也就不会漏掉
某一个模式。

**★ 与产物 md 的「全量字段」附录同一条哲学**：**不挑字段、机械全量**。
新增字段自动被覆盖，不会因为漏写一行 print 而丢。

## 三、[B] `ing` 正文就地打印

原来只有 `🔥 ing 输出 {N} 字`。现在紧接着把**正文逐行**打出
（前缀 `🔥 │ `），放在它被产生的位置 —— 读日志时不必翻到圈末的留痕段。

圈末留痕段同样含 `collision` 全文。**两处重复是有意的**：一处就地（可读）、
一处机械留痕（完整）。实测：就地 135 行、留痕段内 333 行。

## 六、已知遗留与下一轮建议

1. **日志会随圈数平方增长**：每圈留痕含 `round_log` 等**累积型**字段，
   同一信息随圈重复出现（n 圈约 n(n+1)/2 份）。两层两圈已 123K 字符；
   四层 5 圈预计 **MB 量级**。若要压，可对累积字段**只打增量** ——
   属格式决策，当前**完整性优先**。
2. **判卡死不要按日志字节数看推进**：日志在跑时增长很快，按字节数会误判。
   仍按层/圈标记推进、以及 ≥45 秒窗口判（已有约定）。
3. **`_run_verif.py` 本轮未改**：v1.21.67 的收全能力直接复用 —— 这也是
   分层的价值：流收全与内容收全解耦，各改一次。

## 七、经验教训

1. **「日志收全」分两层**：① **流要收全**（v1.21.67：stdout / stderr /
   logging 都进同一文件）；② **流里得有东西**（v1.21.68：引擎每圈真的把
   全量打出来）。只做 ① 会出现「日志很完整地记录了摘要」这种假完整。
   判据可量化：**留痕字段数 ≥ View 的 dataclass 字段数**。
2. **挂载点选「所有路径都必过」的地方**：`DGTF.run` 是 3 个跑圈入口的
   共同下游，挂一次覆盖 10 个并行模式；挂在各模式循环里必然漏。
3. **断言要防「死代码」**：方法写了、单测过了，但生产路径没调用 —— 所以
   `check_v68_round_dump` 里有一条**源码级接线断言**。
