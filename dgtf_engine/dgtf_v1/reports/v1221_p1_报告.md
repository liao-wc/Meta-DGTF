## 六、发现与偏离（如实记录）

1. **任务书内部不一致**：Step P1.2 骨架写 `return _extract_actions_lexical(view)`，
   但 Step P1.5 冒烟断言 `all(a["_source"] == "lexical")` —— 直接返回该断言必红。
   本实现按冒烟口径办：兜底路径**补 `_source` 标签**，返回形态与词法版逐字一致
   （只多一个键）。
2. **★ 接冒烟时引入过一次真回归**：第一版 `_mk_v1221_smoke_checks.py` 用
   `GUARD_RE.sub("")` 把 main() 里**全部**守卫摘掉再重排，结果 69 条老守卫
   （`check_v63*`~`check_v77*`、`check_config_parses`、`check_cli`）被清空，
   冒烟从 **158 ✓ 掉到 21 ✓**，而且 **EXIT=0 看着全绿**。
   已按备份 `_bak_smoke_test.pre_cfgsync.py` 恢复 73 条原序守卫，并加硬断言
   （守卫数 < 74 直接报错）。注入器改成「只碰自己管的名字」。
3. **真跑的 `-c` 配置没生效**：我生成的 `_p1_cfg{1,2,3}.yaml` 里 `\n` 被写成字面
   `/n`（多级转义），三份配置解析失败被忽略 → 产物落到 `outputs/` 而非
   `outputs/p1_runN/`。**三次真跑本身全部成功**（各 171 次调用 / 1.39M token），
   产物已按时间戳归位到 `outputs/p1_run{1,2,3}/p1_run{N}.md`。
   教训：**shell 里不写反斜杠转义**，配置/文本一律用 Write 工具落盘。
4. **成本**：三条真跑 ¥7.81（余额 31.71 → 23.90）。
