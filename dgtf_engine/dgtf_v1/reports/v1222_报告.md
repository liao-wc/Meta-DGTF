## 三、阶段 1：P4 OFF 臂口径统一

- **根因**：`stability` 只有多票路径写；OFF 臂连键都没有，而头部仍按 `stability`
  统计 ⇒ 印出「**三态多票**：high 0 / medium 0 / low 0　一致率 0%　⚠️ unstable（＜50%）」
  —— **非读数被当成测量值**。
- **改法**（3 处改设计，见 §二 #3/#4/#5）：

| 新增符号 | 作用 |
|---|---|
| `_single_vote_stability(sq)` | 单票口径：`abstained` / `medium` / `high` / `low` |
| `MetaDGTF._write_tri_stability(subs, mode, from_votes)` | 给**每一条**写 `_vote_mode` + `stability`，**在每个出口前**调 |

- **头部**：按 `_vote_mode` **多数**印标题（`三态判决（单票/多票）`）+ 印 `口径=`；
  分母 `_voted = _hi+_me+_lo`；弃权单列。**不再把单票印成「三态多票」**。
- **★ 两臂的 `stability` 不是同一把尺子**：单票量的是「单票 vs 拆解原标签」，
  多票量的是「三票之间」。所以口径必须印出来 —— 拿两臂的数直接比会得到错结论。

### 关键证据（离线 E2E，两臂各 1 跑）

| 版本 / 臂 | `_vote_mode` | `stability` | 产物头部行 |
|---|---|---|---|
| v1.22.1 OFF | `{None}` | `[None,None,None]` | `**三态多票**：high 0 / medium 0 / low 0（共 3 条）　一致率 0%　⚠️ unstable（＜50%）` |
| v1.22.2 OFF | `{'single'}` | `['high','low','high']` | `**三态判决（单票）**：high 2 / medium 0 / low 1（已判 3 条）　一致率 67%　口径=单票 vs 拆解原标签（共 3 条）` |

### 3.4 ★ P1b：真跑暴露的一格（本版唯一「跑出来才发现的」bug）

真跑第一次落进一格探针与 E2E 都覆盖不到的情形：**判决与原标签不一致，
且分歧落点恰好是 `partial`、而原标签本来就是 `partial`** ——
只看「两标签是否相等」会判成 `high`。

信号不是读代码，是**同一份产物的两行数字互相矛盾**：
OFF 臂 `stability` **6×high**，而同产物 `三态判决一致率` 只有 **5/6**。

修法：单票口径函数**先**看 `label_disagreed`。冒烟已加负对照
（`label_disagreed=["partial","decidable"]` 且两者相等 → 必须 `low`）。
真跑在 P1b **之前**，故 `v1222_p1_报告.md` 里的 `6×high` 是**bug 现场**，
报告里已明确标注，不把「重跑预期值」写成实测值。

## 十、经验教训

1. **核验阶段的产出可以比代码改动更值钱**：本版 9 处发现里，#1/#3/#7 任意一条照抄
   都会做出「看起来通过了、其实静默失败」的版本。
2. **「给模型加新产出字段」= 四处一起改**（schema / 白名单 / 抽取 / 渲染）。
3. **负对照是唯一能发现「判据不可达」的手段**：两处都是正对照全绿、负对照才红
   （P2 的 `orientation` 入参、P1 的弃权语义）。
4. **写留痕字段前先 grep 属性名**：任务书自己给出了「复用已有属性」的坏建议。
5. **过滤类改动会把下游的「空判据」变成假话**：`if not x.get(k)` 式的告警，
   在新增上游过滤后必须重新核「在原始数据上判，还是在结果上判」。
6. **阶段划分要检查判据的依赖方向**：W 的 B1（W2 判据依赖 W4 交付物）就是没做这一步。
7. **本项目的老坑又出现一次**：两臂对照先证「两臂都产出了同一个量」—— 本轮两臂的
   `stability` 口径**确实不同**，所以标题必须印口径，不能让读者默认可比。
