## 二、问题：一句只能"推断"的话

可达性审计（`_ab_v1255_对表.md` §十）里我写了：

> 库 11 条 < 冷启阈值 20 ⇒ `_eff_n` 会从 3 降到 1；3 个 shadow 各有 1 条证据，
> 在 `_eff_n=1` 下过了门槛，然后被质量闸挡下。

这段话**逻辑上站得住，但产物里查不到任何证据** —— `_eff_n` 只活在 `eml_promote`
内部，`shadow` 条目为什么没升级也没有记录。产物里只有 `promoted: []`，读的人
只会得出「没有东西可升」。

> **「我推断它降到了 1」与「产物里写着 1」，是两件事。**
> 前者是审计者的信心，后者是下次别人能复现的事实。

## 三、修法：多收一个 `trace`，返回值一个字不动

```python
def eml_promote(playbook, promote_n=_EML_PROMOTE_N,
                adaptive=False, trace: dict = None) -> list:
```

传了就填：

| 字段 | 含义 |
|---|---|
| `eff_n` | **自适应后的实际门槛**（本次是 1 还是 3） |
| `promote_n` / `adaptive` / `n_lib` / `cold_lib` | 算门槛的四个输入，一起留 |
| `shadow` | 逐条：`id` / `n_evidence` / `contra` / `quality_delta` / `cost_delta` / `verdict` |
| `shadow_verdicts` | 分类计数 |

**五类 verdict**（这是关键，只有分类才能回答"为什么 0 升级"）：

| verdict | 含义 |
|---|---|
| `n_short` | 证据不够（门槛没达到） |
| `contra` | 反向证据够了 |
| `quality_down` | 质量下降（防学坏） |
| `cost_only` | 只省成本、质量没升（F2 双边记账） |
| `promoted` | 真升级了 |

调用方挂成 `_blk["promote_trace"]`，产物 md 正文加一行：

```
↳ 晋升门槛 ≥1（名义 3；自适应：库 11 < 冷启 20 ⇒ 降到 1）｜shadow 拦截：n_short×3
```

## 六、经验教训

1. **"推断"要显式标成推断。** 我在 §十 写了推断却没标记，很容易被后来的人
   （包括我自己）当成实测。**能出口的读数就该出口，不能出口的就要标"未测"。**
2. **「0 升级」这种结果必须能拆分原因。** 单个 0 无法区分「没东西可升」与
   「有但被挡住」—— 而这两种情况的下一步动作完全相反。
3. **加读数要设计成"纯增量"**：多收一个可选 `trace`，不动返回值 —— 这样
   "不传就逐字不变"是可以被判据证明的，而不是靠嘴说。
