## 二、逐条说明

### 1. 四张层卡上下拉满（`static/style.css`）

三个原因叠在一起，缺一个都「拉不到底」：

- `.lane-body` 同时带着 `.log` 的 **`max-height:264px`** —— 这是**上限不是定高**。日志到 264px
  就封顶，`task-foot` 下面留一块空白。→ `.lane .lane-body` 显式补 `max-height:none`。
- `.tasks{margin-bottom:14px}` → 与输入框之间留空隙 → 改 `0`。
- **`#view-run` 原来是 `min-height`**，高度会被内容顶大：日志一长、或展开「高级参数」，
  整页变高出现纵向滚动，四张卡反而缩不到底（实测展开面板后 `docH` 1196 > 视口 773，
  面板被推到视口之外）。→ 改成 `height:calc(100vh - 76px)`，`.tasks` 给 `min-height:220px` 兜底；
  窄屏媒体查询里的 `main` 内边距不同，同步补 `calc(100vh - 138px)`。

### 2. 参数下拉改自绘（`static/app.js` + `style.css`）

原生 `<select>` 在**页面底部的滚动容器**里，弹层会脱开触发控件飘到窗口左上角 —— 这正是原话描述的现象。
改成页内菜单：`<div class="dd">` + 隐藏 `<input data-cfg>`（真值仍走 `collectOpts()`，**后端与提交链路零改动**）。

- 菜单**展开时挂到 `<body>`**，两个坑一起绕开：
  ① `.advanced{overflow:auto}` 会裁掉菜单；
  ② ★ **`#view-run.view-active` 带着 rise 动画的 `transform`** —— `animation-fill-mode:both`
     会留下一个**单位矩阵**，而单位矩阵也算 transform，`position:fixed` 的包含块会被从视口
     换成 `#view-run`，菜单整体平移（实测左边界偏 163px、底边跑出屏幕）。
- 定位：`left = 触发控件 left`、`top = 触发控件 bottom + 6`；**下方放不下就上翻**。
- 下拉项**不能套 `<label>`** —— label 会把点击转发给里面第一个 labelable 元素（`<button>`），
  一次点击触发两回。所以下拉项用 `<div class="field">`，样式与 `label` 对齐。
- 交互：点外面 / Esc / resize 收起；滚动只在**触发控件所在的滚动链**上才收（见下）。
- 入场动画 `ddIn`：从触发控件左侧 3px 滑入 + 淡入。

### 3. 联网检索结果库（`library.py` + `server.py` + `static/app.js`）

- 新增纯函数 `library.group_hits(records)`：按 `query` 分组、组内按 `url` 去重
  （url 为空退化成 claim 前 80 字）。`web_hits_grouped()` = `group_hits(web_hits())`。
- `/api/library/web` 新增 `groups` 字段（`items` / `hits` 保留，旧前端不受影响）。
- 前端：组头给「去重后 N / 共 M 条」；页头给「按问题聚合 X 组 · 去重后 N 条 · 原始 K 条」；
  加「按问题 / 关键词过滤」框与「按问题聚合 · 去重 / 平铺（不去重）」开关。
  服务端没给 `groups` 时前端自己按同样规则兜底分组。

### 4. 演练模式挪到「高级参数」那一行（`static/index.html`）

放进了 `<details class="advanced">` 的 `<summary>` 里，右侧对齐；
`init()` 里给它挂了 `stopPropagation`，**点开关只切开关，不会顺手把面板展开/收起**。

## 三、顺带修掉的三个真 bug（都是这轮验收逼出来的）

1. **归档与「跑完」的竞态**（`engine_runner.py`）
   原来先 `task["status"]="done"` 再 `_archive()`。前端一旦在某次轮询看到 `done` 就停止轮询，
   归档链接（`archive_log` / `archive_json` / 层产物）可能**永远不出现**。
   → 改成**先落盘归档、再对外宣布跑完**；`_archive` / `_archive_layers` 增加 `status` 形参
   （否则归档 json 里的 status 会写成 `running`）。这条也是 selftest 里唯一一个会**随机翻红**的判据。
2. **层卡日志自动滚动会收掉正开着的参数菜单**（`static/app.js`）
   `renderTasks()` 每 1.5s 会把日志区 `scrollTop` 贴底，那是一次真实的 scroll 事件；
   原来的「任何滚动都收菜单」会把它当成用户滚动 → **运行时几乎必现**。
   → `onDdScroll` 只认**触发控件所在的滚动链**（开菜单时记进 `menu._scrollers`）。
3. **运行台被内容顶高**（见上 1.）—— 展开高级参数后面板被推到视口之外，得靠页面滚动才够得着。

# 修复记录（13:05）

用户报「修复项目的 web 应用」。逐层排查 → **代码本身没坏，坏在两处运行态**。

## 现象 1：`selftest.py` 跑到 `POST /api/library/import` 时服务端断连

- 症状：`RemoteDisconnected`（连接被**直接关掉**，不是 500），前 19 条判据全绿后崩。
- 定位：**端口 8765 上跑的是旧进程**（PID 18044）。`server.py` / `library.py` 是
  进程启动时加载一次的 —— 这两个文件在工作区有未提交改动（新增 `groups` / `group_hits`），
  旧进程看不到，请求打进去 handler 抛未捕获异常 ⇒ 线程死、连接被关。
- 佐证：本地直接驱动 `library.import_files()` 完全正常；杀掉旧进程、用当前代码重启后，
  同一套 selftest **PASS 39 / FAIL 0**；该接口再压 **12/12 稳定**。
- 修：`Stop-Process -Id 18044 -Force` → 用当前代码重启服务。

## 现象 2：产物库份数虚高（371 → 316）

- `outputs/` 里积了 **167 个** `2026…应用端到端自检 mock*` 文件（12:13 → 12:59 累计）。
- 根因：`selftest.py` 的清理用 `unlink`，而**隔离环境里 unlink 会被重定向到 overlay** ——
  脚本报「已清理自检产物与归档」，真实盘上文件还在 ⇒ **每跑一次自检就多一批垃圾**。
- 修（代码加固，`dgtf_app/selftest.py` 清理段）：
  `unlink` 后若文件仍存在，则 `shutil.move` 到 `_audit_tmp/_selftest_trash/`（移动不被该闸拦、可逆）。
- 历史垃圾：167 个已移入 `_audit_tmp/_selftest_trash/`；产物数 371 → **316**（41.7 MB）。
  想彻底删掉这批：`rm -rf "_audit_tmp/_selftest_trash"`。

## 顺带记录的坑（已写进 `dgtf-app-frontend` skill）

- **Edge 无头用 `--user-data-dir="$PWD/..."` 会静默失效**：Git Bash 不转换 `--opt=/c/...` 里的路径，
  Edge 于是把命令转交给已在运行的实例、自己退出，`--dump-dom` **输出为空**（**无任何报错**）。
  ⇒ 改用 Windows 字面量路径 + 每次换新 profile 目录。skill 里原来那条命令在本机已不可用，已更新。
- `taskkill //F //PID` 在 Git Bash 报「无效参数/选项 - '//F'」⇒ 杀进程改用 `Stop-Process -Force`。
