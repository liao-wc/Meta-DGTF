## 二、P1：研究层结构化 actions —— ✅ 通过（本版重点）

**目标**：让研究层**直接产出结构化行动清单**，而不是事后拿词法规则去文本里捞。

**做了什么**

1. `_he` 的 schema 加 `decidable_product.actions[]`（六字段：verb / object /
   owner_role / deadline_hint / acceptance / fallback）+ 约束段（全部必填、
   不许写「相关部门」、不许写「尽早」…）。
2. ★ `dec_norm` 白名单加 `actions` —— **不加就是静默吞字段**（模型产了、
   归一化时被丢掉，产物里什么都看不见）。新函数 `_norm_schema_actions` 立据。
3. `_extract_actions` 改成「**schema 优先 + 词法兜底**」：原词法实现改名
   `_extract_actions_lexical`（**正文一字未动**），兜底结果带 `_source` 标签。
4. `action_incomplete` 的语义从「文本里没抽到行动」改成「模型没按 schema 产出」；
   新增 `action_fields_missing`（字段缺项），并把它**同时放进 `_V122_HARD_FLAGS`**。

**实测（三题真跑）**

| 题 | action 条数 | rubric（各项 1 分，满 3） |
|---|---|---|
| 老城区内涝 | 5 | 2 |
| 中小制造 | 6 | 2 |
| 社区医院 | 4 | 2 |
| **平均** | **5.0**（全 ≥3） | **2.00** |

`action_incomplete` 从**改前 4/4 份全触发** → **改后 0/3**。
动词白名单仍 **19 条**（没扩 —— 扩它是「把判据拟合到数据」）。

**★ 这里抓到一条真 bug（读真跑 packed 才看见）**：硬约束 flag 写进了
`view.errors`，却从 `quality_flags` 里消失 —— 19 行之后有一段
`_keep_selfcheck_flags(view, _quality_check(...))` 会**整体重算** `quality_flags`，

## 三、P2：triage 挂结构标签 —— P2a ❌ 未通过 → P2b 补齐 → **合并通过**

### P2a（触发条件）

**做了什么**：新增 `_TRIAGE_STRUCTURAL_PREFIXES = ("[外]",)`、
`_is_triage_candidate`（结构标签前缀 **∪** 语义关键词）、
`_is_never_downgrade`（真·自指 / 自证 / 本体论 / 无共同参照系 → **不许降级**）；
`_anchor_crosscheck` 的 triage 循环先过 `_is_never_downgrade` 再判候选。
旧词表 `_TRIAGE_KEYS` **一字未删**（加性）。

**结果**：机制判据 **15 项全绿**（`[外]` 结构标签 14/14 命中、三条负对照不降级），
但**三题真跑 triage = [0, 0, 0]** → 效果判据未达标 → **P2a 判未通过**。

**根因（定量）**：触发条件已修通，卡在下游 `_similar(aspect, anchor.claim, 0.6)`：

```
14 条 und 侧面 vs 3 条锚点的最高词重叠率：max 0.167 / 中位 0.000 / ≥0.6 的 0 条
```

**为什么必然为 0**：`undecidable_aspects` 说的是「**缺什么材料**」，而锚点 `claim`
说的是「**是什么事实**」（标准条文、指南要求）—— 两类文本的关键词几乎不相交。
不是相似度算错了，是**匹配对象选错了**。

### P2b（换匹配对象）

**做法**：不动阈值（`0.6`）、不动触发条件，只**换匹配对象** ——
给锚点快照加 `answers`（「我能回答哪些侧面」），新增两条匹配函数：

```python
_hit_by_answers(aspect, answers)   # 用 _overlap_coef（分母 min）+ _UNTRACED_OVERLAP(=0.6)
_hit_by_claim(aspect, claim)       # 老路径：_similar(aspect, claim, 0.6) —— 一字不动
hit = (由 answers 命中) or (由 claim 命中)，且必须 tier ≤ tier_floor
```

`_load_anchors` 加 `answers` 键（**不加仍是静默吞字段**）；`_anchor_crosscheck`
的 `_hit` 改双路径；另加 `answers` 全缺时的留痕键 `answers_all_missing`。

**实测**：三题真跑 triage = **[1, 0, 0]** → 主判据达标。
命中项：老城区内涝的 `[外] 未指定具体老城区，无法判定重建与局部改造加海绵措施孰优`
↔ 锚点 **a2**（tier 1）。

★ 值得单说：P2a 同一题那条侧面原文是
`[外] 无法得出「重建」还是「局部改造+海绵」的唯一最优解`，P2b 这次产出的措辞
**不一样**却仍被 a2 命中 —— 命中的是**语义轴**，不是某串写死的字。

**顺带查清两件事**（都写进了报告）：

1. `_overlap_coef` **是对称函数**（分母取 min，与方向无关）→ 任务书要求的
   「反向也查一次」与正向**等价**，不给新命中（冗余，留待下一版处理）。
2. triage **只出建议清单**，**没有任何写 `decidability_log` 的路径**
   （`apply_decidability_change` 在 crosscheck 内只出现在注释里、`append` 出现 0 次）
   → 「triage 引起的 und→partial」**结构上恒为 0**。所以把 P2.4.b 降为观察项是对的。

### ⇒ P2 整体重判

| 维度 | P2a | P2b | 整体 |
|---|---|---|---|
| 触发条件（`[外]` 结构标签） | ✅ 14/14 | 一行未删 | ✅ |
| 匹配对象（answers 路径） | ❌ 卡在 claim 文本 | ✅ 命中 1 条 | ✅ |
| 效果判据 triage ≥1 | ❌ [0,0,0] | ✅ [1,0,0] | ✅ |

**P2 重判为「通过（P2a + P2b 合并）」**。`--phase p2` 的 15/2 是 **P2a 单档的
历史记录**，不改写；整体判据由 `--phase p2b` 承担，并在 `phase_p2` 输出里加了

## 五、P4：一致率 ON/OFF 对照 —— ✅ 判据通过 / **结论：无结论**

**这节是本版最该被记住的地方。**

**跑法**：同题同配置（route 1 / rounds 1:4），ON 与 OFF 各 3 次。

**★ 先说一件事：任务书指定的口径在 OFF 臂不可用。**

任务书的口径是产物 md 里这一行：

```
**三态多票**：high N / medium N / low N（共 N 条）　一致率 X%
```

那一行读的是每条子问题的 `stability` 字段 —— 而 **`stability` 只有多票路径
（ON）才写**。OFF 走单票路径，子问题里**连 `stability` 这个键都没有**，
于是引擎照 `(0+0)/n` 印出：

```
OFF  **三态多票**：high 0 / medium 0 / low 0（共 5 条）　一致率 0%　⚠️ unstable（＜50%）
```

**那是「没算」，不是「算出来是 0」。** 初看是「ON 100% vs OFF 0%，多票更好 +100%」，
但那个 0% 是**非读数**。照抄口径就会得出一个**建立在不存在读数上的结论**。

（这个假渲染是 v1.22.0 阶段 2 就有的，不是本档引入；P4 只是第一次让它**显形**。
本档不改它 —— 改头部渲染 = 改产物格式，不在 P4 授权内。）

**改用两臂都可得的口径 `tri_state = [agree, total]`**：

| 臂 | 三次读数 | 平均 | 组内极差 |
|---|---|---|---|
| ON | 80% / 80% / 80% | **80.0%** | **0.0%** |
| OFF | 50% / 80% / 60% | **63.3%** | **30.0%** |

组间差 **+16.7%** → 落在「≥ +10% → 多票更好」这一档；
但 **OFF 组内极差 30.0% ≥ 组间差 16.7%** →
按 **P4.4 自己的两向规则**：**无结论**。

即：3 次重复里有 1 次 50%、1 次 80% —— 在这个散布水平下，
「ON 比 OFF 高 16.7%」和「掷骰子」暂时分不开。要真出结论，得先把 OFF 的组内极差
压下去（增加重复次数 / 固定采样温度），本档只跑 3 次（任务书要求），如实报无结论。

★ P4.1 要求的「运行时开关」**在引擎里早已存在**
（`_action_on(config, "tri_multi_vote")` + `DEFAULT_CONFIG.actions.tri_multi_vote = True`）
→ 本档**没改引擎**，`rc2` 与 `rc1b` **逐字节相同**。

汇总脚本 `_v1221_p4_agg.py` 出**两份** summary（`summary` = 任务书口径 +
`md_metric.usable` 可用性标注；`fair` = 两臂都可得的口径），验收里加了 `P4.2.c`
要求报告必须写明「md 口径在 OFF 臂不可用」——不许把 0% 当测量值。

## 六、P5：auto 取向回填 —— ✅ 通过

**目标**：`plan_orientation` 的真实判定结果写进产物头部；「auto 判成 boundary
却按 decision 渲染」这种错配**可查**。

**★ 任务书前提不成立。** 任务书写「`auto_plan` 已经带 `orientation` 字段，
把它带出来即可」—— 实测：

| 路径 | 谁在用 | 返回里有没有 `orientation` |
|---|---|---|
| 两次调用（`plan_orientation` + `plan_resources`） | **无任何内部调用点**（外部 API 用） | 有 |
| **一次调用**（`llm` 非空） | **`run()` 的自动调度走的就是它** | **没有** |

也就是说 `_auto_plan_used` 在真实路径上**永远拿不到取向**，头部那行一行都印不出来。

**修法**：在**同一次调用**的 prompt 里把取向一起要出来（schema 加
`"orientation":"decision|boundary"`），三处 `return`（失败早退 / 低置信早退 /
正常）都带出去。**成本不变** —— 冒烟里用打桩断言 `len(calls) == 1` 钉住这一点。

**产物头部新增两行**：

```
**取向判定（plan_orientation）**：boundary（…理由…）
⚠️ **取向错配**：plan_orientation 判为 `boundary`，但 orientation 未指定（按 decision 渲染）…
```

**真跑**：`p5_auto`（不传 rounds，触发 auto 调度）→ 「取向判定」与「取向错配」
**双双命中**；`p5_boundary`（显式传 boundary）→ **无**错配告警（负对照）。

★ 顺带看到一个事实：**取向判定本身有噪声** —— 同一道题两次 auto 跑，
一次判 boundary、一次判 decision。P5 的价值恰恰是让这件事**可见**；
要下「稳不稳」的结论需要同条件 ≥3 次重复（本档只跑了 2 次，不下结论）。

## 七、P6：tier 缺省时的显式提示 —— ✅ 通过

**目标**：若**全部**锚点都没显式声明 tier（缺省 3 > `tier_floor` 2），产物加一行警告 ——
否则引用表一条都收不到，而产物看起来「对照过了」。

**★ 任务书骨架有真 bug**：

```python
_n_explicit = sum(1 for a in out if "tier" in a and a["tier"] is not None)
```

`out` 里每条锚点都**已经被补过** `tier`（缺省 3）→ `"tier" in a` 恒真、
`a["tier"] is not None` 也恒真 → 计数恒等于总数 → `== 0` **永不成立** →
**警告永远不触发**。正解：在**补默认值之前的原始条目**上数（`_n_explicit_tier`），
并加了一条冒烟断言（`P6.1.c`）把「在原始条目上数」这件事本身钉住。

**实测**：

| 跑 | 锚点快照 | 「锚点 tier 警告」 |
|---|---|---|
| `p6_notier` | 2 条，都没 tier | **命中** |
| `p6_tier` | 2 条，其中 1 条 `tier=1` | 未命中（负对照） |

警告文案：`全部 2 条锚点未显式声明 tier（缺省 3 > tier_floor 2），引用表将收不到任何锚点`。

★ **不阻断**：`tier` 没写不等于灾难，只等于「对照会空转」。把它升级成致命错误
是把可读的提示变成没必要的失败 —— 本项目红线是「不许静默」，不是「不许继续」。
★ 红线保留：无 tier 的锚点**仍不进引用表**（冒烟里有这条断言）。

| 有产出（rubric 2） | 15 | 正常 |
| 有产出但 rubric 低（1） | 2 | actions 只有 2 条（< 3；`action_incomplete` 已留痕） |
| **没有可产的动作**（0） | 2 | 6 条子问题**全 undecidable、答出 0 条** → 确实没有行动可产 |
| **模型没按 schema 产出**（0） | 1 | `answered > 0` 但 `actions == 0` |

★ 关键区分：**「0 分」不等于「功能坏了」**。3 道 0 分题里 2 道是「研究层这一跑
没找到可判定的侧面」，1 道是「模型没按 schema 交」。两类都被 P1 的硬约束**留痕**了
（`quality_flags` 里的 `action_incomplete` + `errors` 里那句
「decision 取向 actions 段不足：schema 产出 0 条（< 3）」）——**产出不足要说出来，
不是伪造出来**，这正是 P1 想要的行为。

★ 另一处是**结构性上限**：rubric 第三项「不做什么」在 **20/20 题上全为 0**
（`_not_do` 为空）→ rubric 的数学上限本来就只有 **2/3**。要打到 2/3 平均，
得**每一道题**都产出 ≥3 条带回退的行动（实测 15/20 做到了）。
把第三项也做出来是 P1 明确留的「下一格」（见第十节第 6 条）。

★ 因此**没有**再做一轮「加圈数」的补测：主流缺口（`_not_do` 恒空）是**已知的设计缺口**，
不是圈数不够造成的 —— 加圈数不会让 `_not_do` 从空变满。

### ⚠️ F.1 期间出厂 `dgtf_config.yaml` 被外部手改（已查明并恢复）

F.1 跑完后冒烟报了配置红：出厂 yaml 里 `external_anchor` 三项与默认不同且**未登记** ——
`enabled: true`（默认 false）、`as_evidence: "gate"`（默认 "off"）、`triage: true`（默认 false）。

**查明过程与结论**：

- 该 yaml 的 mtime 落在 F.1 期间；但把工作区**所有** `*.py` 扫了一遍，
  **没有任何脚本**写它（唯一命中写动作的 `_audit_eval_quality.py` 本会话没跑过）；
- `triage: true` 这个字面串**只存在于这个 yaml**，不在任何脚本/示例里；
- `enabled: true` 配 `path: ""` 是**自相矛盾**：必然走
  「外部锚点加载失败：enabled=True 但没有给 path」——实测 F.1 的 20 题里
  **10 题的产物带着这条假告警**，`_bench_v1221_full.log` 里也有。

⇒ 判为**事故性外部手改**（没人会想要「一半产物报一条必然失败的锚点告警」）。
处置：备份为 `_bak_dgtf_config.pre_anchor_revert.yaml`，把三项**恢复成默认值**
（`false / "off" / false`），并核对 `load_config` 生效值 == `DEFAULT_CONFIG`。
之后冒烟回绿：`[配置] 能解析；键已列全（129 项，豁免 0 项）；手调 48 项全部已登记`。

★ 两件事值得记下来：
① **这条红项正是配置检查该拦的东西** —— 出厂文件与默认悄悄分叉，而没有任何东西
看得见（v1.22.0 那轮的「配置文件同步」就是为了治这个病）；
② **F.1 的产物里那 10 条锚点告警是噪声，不是缺陷**：锚点加载失败 → 无锚点 →
对照退化为「无锚点」路径，对判定/一致率/rubric 都无影响（十道题的读数与另十道同分布）。

## 十、遗留与下一版候选

1. **P4 的 OFF 臂需要一个真正的量**。现在 OFF 不写 `stability`，头部那行的
   「一致率 0% ⚠️ unstable」是**假告警**。三选一：
   ① 单票路径也写 `stability`（单票的「稳定」可定义为「与拆解原标签一致」→ high）；
   ② 头部在 `stability` 键缺失时**不印那一行**，改印「（多票未开启，本行不适用）」；
   ③ 统一成一条口径两条路径都写。★ 本版不动（改头部 = 改产物格式，改写入 = 改行为）。
2. **OFF 组内极差 30%** → 谈「多票是否更好」需要更多重复（同条件 ≥3 是下限）。
3. **`_hit_by_answers` 的反向分支冗余**（`_overlap_coef` 对称）。建议删；
   或改成「对 `answers` 也做同义改写」这种真能改变结果的做法。
4. **`answers` 的 min 分母 + 0.6 对短 answer 偏松**：2 个词的 answer 只要被长
   aspect 包住就是 1.000。本版按任务书复用既有常量、未新造阈值；下一版若接 W 系列
   **自动生成 answers**，需要给 answer 加最短长度/最小信息量约束。
5. **`answers` 目前手填**。下一版接 W 系列联网后，可让检索侧在拿到 web 结果时
   一并产出 answers 再落盘（不额外增加调用）。
6. **P1 的下一格**：给 schema 也加「不做什么」段（或改 `_extract_not_do`），
   把 rubric 从 2/3 推到 3/3 —— 三题的 rubric 都缺在第三项「不做什么」。
7. **`_all_settle_streak`**：进 `pending_fix`；要给负对照，先得把它从 `_run_layer`
   里抽成可调用宿主（属重构，本版不做）。
8. **`auto_plan` 的两条路仍不统一**（v1.21.71 F8 登记过的双实现）：两次调用那条
   返回 `_orientation_reason`，一次调用那条只返回 `orientation`，所以头部括号里
   常常是空的。下一版可把 reason 一并带出。本版**只加不合并**。
9. **tier 缺省值 3 > 出厂 `tier_floor` 2** → 任何不写 tier 的快照都「载入了但
   进不了引用表」。本版只把它变成可读警告；是否改缺省值属「改行为」，留给下一版。
10. **部分缺省仍静默**：P6 只在「**全部**缺省」时告警；3 条里 1 条没写 tier
    目前完全无声。下一版可补「部分缺省也计数提示」。
11. **F.1 的 rubric 缺口可以精确定位到两处**（不是笼统的「效果不好」）：
    ① 第三项「不做什么」在 20/20 题上全空（`_not_do`）→ 结构性上限 2/3；
    ② 3/20 题产出 0 条行动（2 题研究层没找到可判定侧面、1 题模型没按 schema 交）
    → 前者只能靠「多给几圈 + 换更容易判定的题」缓解，后者靠 prompt 再收紧。
    这两处都不是「改动引擎」能立刻解决的，也不该靠放宽 `min_actions` 去凑
    （见第八节第 2 条：那是把尺子改短）。
13. **出厂 yaml 的分叉要一直看得见**：本轮 F.1 期间 `dgtf_config.yaml` 被外部手改
    （`external_anchor` 三项 `enabled/true`、`as_evidence/gate`、`triage/true`，
    未登记），已查明非本轮脚本所写、判定为事故并恢复默认（见第九节末尾）。
    下一版可考虑：让这类「出厂文件被改」不仅冒烟判红，**也在产物头部留一行**
    （现在只在冒烟里可见）。
12. **降档跑会削弱 P1 的效果**：本轮 F.1 用的是 economy + `0:2,1:2,both:2,all:3`。
    要比「P1 的真实效果」，应在**原始档**（balanced + `0:5,1:5,both:5,all:6`）
    上量一次 —— 本轮原始档的单题证据只有阶段 1 的 3 题（`bench/runs/p1v2`）。
