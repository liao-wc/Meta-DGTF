## 二、审计：问题不是"风格"，是"会失败"

完整版见 `_审计_v12364_全维度.md`；机器可读结果在 `audits/static_audit_v12364.json`。
扫描 26 个活跃文件，分级 **15 critical / 118 major / 164 minor**。其中能一句话说清的根因有四类：

### 2.1 GBK 编码面（14 条 critical）

Windows 下 stdout 被重定向到管道时，Python 用 locale（cp936）。本项目第一条 print 就带 ✓/✗：

```
UnicodeEncodeError: 'gbk' codec can't encode character '\u2713'
```

实测两处**真实失败**：

1. `_run_gate.py` 在命令**成功之后**打印日志摘要时崩 ⇒ 退出码 1 ⇒ 把成功报成失败；
2. `bench/bench_calibrate.py` 打印「✓ 导出」时崩 ⇒ 三态校准导出不可用，
   冒烟 v1.22 阶段2 因此必红。

修法：所有会打印非 ASCII 的入口在模块加载期把 stdout/stderr 切到 UTF-8；
`_force_utf8_streams()` 同时给子进程 `setdefault` `PYTHONUTF8=1` / `PYTHONIOENCODING=utf-8`。
默认 GBK 下复验：包装器 EXIT=0、校准导出 EXIT=0（见 §五）。

### 2.2 EML 记忆库耐久性（真缺陷）

| 缺陷 | 后果 | 修法 |
|---|---|---|
| `_eml_finish` 新增行时裸 `open("w")`；`eml_rewrite_jsonl` 同样先截断 | 崩溃/断电 ⇒ 半截 jsonl；坏行又被跳过 ⇒ **静默丢证据** | tmp + `os.replace`；新增 `allow_grow` 只增校验 |
| 锁的 `__enter__()` 返回值没人看 | 并发真跑时可能**无锁读-改-写** | 拿不到锁 ⇒ `lock_timeout` 并跳过写库 |
| 陈旧锁只看 mtime | 长跑持锁 > 900s 被第二个进程抢走；释放还会误删别人的锁 | pid:token、回收前问活进程、只删自己的锁、`monotonic` 计时 |
| 坏行"跳过但计数"名不副实 | 读的人只看到条目变少 | `eml_read_jsonl(stats=…)` + logger.warning |

### 2.3 LLM 重试（真缺陷）

原实现把所有异常一视同仁：参数错/鉴权错（400/401）也重试 3 次，白烧钱；
`sleep(backoff ** attempt)` 无抖动，并行分层同拍重试。
修法：4xx（除 408/409/429）不重试；抖动 `[0.5,1.0]×backoff`；尊重 `Retry-After`（≤60s）；统一 `_tries`。

### 2.4 文档漂移（真缺陷）

`README.md` 写「当前 V1.23.61 / 26819 行 / 冒烟 263」，审计时实际已是
V1.23.63 / 26857 行 / 264；`smoke_test.py` 的审计回退路径还指向旧版 `元DGTF-V1.23.3.py`（文件存在，但不是当前版）。
本轮已把 README 同步到 64，并把回退改回 `SRC`。

> 其余 115 条 `except Exception` 不全是缺陷：守卫型（读不到不影响主流程）是合理的；
> 数据路径型（`_load_bandit`/`_save_bandit`/`eml_append_jsonl`）才是残余风险，

## 三、前沿内核：四条，都能被负对照打红

### F1 · e-process（任意停时检验）

- **学科**：博弈论统计 / 序贯分析（Ramdas, Grünwald, Vovk & Shafer, 2023）。
- **为什么**：本项目每圈都看读数再决定停不停 = optional stopping；
  固定样本区间在"边跑边看"下假阳率会暴涨。
- **做法**：对 H0: p ≤ p0，财富过程

  `K_t(λ) = Π_s (1 + λ(X_s − p0))`，`λ ∈ (0, 1/p0)`，

  对 λ 取均匀混合仍是非负鞅；Ville 不等式 ⇒ `P(∃t: K_t ≥ 1/α) ≤ α`。
  实现用 log-space 求和（长序列不溢出），判定 `evalue ≥ 1/α`。
- **判据**：800 次 140 步"边跑边看"仿真，假阳率 **0.031 ≤ 0.05**；
  功效：p=0.7 时中位 **37 圈** vs stitched Hoeffding **54 圈**。
- **接线**：`stop.anytime_mode=evalue`（默认 `hoeffding`，零行为差）。

### F2 · 保形预测（分布无关的弃权）

- **学科**：统计学习 / 分布无关推断（Vovk et al. 2005；Angelopoulos & Bates 2023）。
- **做法**：有限样本修正分位数

  `q = s_{(⌈(n+1)(1−α)⌉)}`，预测集 = `{y : score(y) ≤ q}`。

- **判据**：n=199、α=0.1 时实测覆盖率 **0.940 ≥ 0.9**；空校准集返回 +inf（保守全弃权）。
- **意义**：给"悬置"一个**有覆盖率保证**的阈值，而不是手调 0.33。

### F3 · BOCPD（贝叶斯在线变点）

- **学科**：贝叶斯推断 / 信号处理（Adams & MacKay 2007）。
- **做法**：NIG 共轭 + run-length 后验递推；用"最近 3 步内有变点的后验质量"判起点
  （不用 P(r=0)：它会被 r=1 分流，量级只有 hazard）。
- **判据**：5σ 均值漂移在 **0..7 步内检出**；平稳序列误报 **0**。
- **真实数据**：逐圈序列中位仅 4 圈（不冒充功效）；跨跑 log10(tokens) 24 点检出 1 个变点。

### F4 · Dung 抽象论证 + 负担排序

- **学科**：形式论证理论 / 法哲学 / 认识论（Dung 1995；Besnard & Hunter 2001）。
- **做法**：把 playbook 条目当论证；同 (kind, cond) 但动作不同 ⇒ 互相攻击；
  grounded 扩展（唯一、怀疑论）+ 负担 `b(a)=1+Σ 1/b(x)` 排序。
- **红线对齐**：**只标不删**；grounded 与负担都并列 ⇒ 全部 `undecided`，
  **不强行对齐**（红线 3「未对齐是合法状态」）。
- **判据**：二元环不硬选；三元链 grounded={A,C}；真实库 11 条论证 / 2 条攻击边，
  冲突对 L0002/L0005 判为 `undecided`；注入一条同条件不同动作 ⇒ 攻击边 >0（负对照有效）。
- **接线**：`playbook.argumentation.enabled=false`（默认关）。

## 七、经验教训

1. **"命令成功"不等于"门禁成功"**：退出码会被包装器自己的编码错误改写。
   先修观测面，再谈判据。
2. **只增不删要有物理保证**：断言行数不变，但写盘仍是裸 truncate ⇒ 断言挡不住崩溃。
   原子写 + 只增校验必须同时存在。
3. **锁的失败方向要选对**：拿不到锁时"继续写"比"这次不写"危险得多；
   状态不完整可续，库写坏不可逆。
4. **统计判据要报负对照**：e-process 的 I 类错误、BOCPD 的平稳误报、
   保形的覆盖率，三者都必须有"本该不发生"的那一列。
5. **并列不是缺陷**：Dung 二元环判不出赢家是语义事实，不是 bug；
   硬选一个反而违反项目红线。
