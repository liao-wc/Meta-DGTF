## 二、R1 后半：自省诊断 → 动作回写

### 2.1 问题：诊断与动作之间是断的

自省结论原先只落在**逐层明细**里（`views.*.self_check`）。真跑实证
（v1.23.9 产物 packed）里明明写着：

```
views.all.self_check.unsaid_is_escape = true
views.all.self_check.unsaid_where    = "第五步标出撞不动的地方该继续推回答槽与主语槽的对齐，却用未生收尾"
views.all.quality_flags              = ["unsaid_overused(8)"]
```

但读**落地层**的人看不到这些 —— 诊断被关在附录明细里，没有变成任何动作。

### 2.2 改法：高置信诊断提升为落地层的可执行动作

新增纯函数 `_append_self_check_writeback(res, body)`，把两类高置信信号
提升为落地层里的一条动作：

```
> **自省回写**（诊断 → 动作）：本次 2 条高置信诊断被提升为动作 ——
> - [all] ⚠ **判为逃避**：第五步标出撞不动的地方该继续推…却用未生收尾
>   ⇒ 动作：回到该层「撞不动的地方」继续推，别用「未生」收尾。
> - [all] ⚠ **质量线索 `unsaid_overused(8)`**
>   ⇒ 动作：先核这条线索对应的机制是否真跑到，再决定采不采信结论。
```

- 触发信号：`self_check.unsaid_is_escape=True`、`quality_flags` 里的
  `xxx_overused(n)` / `action_incomplete` / `not_do_missing`；
- **没有高置信信号时不渲染**（不制造动作）—— 由探针与判据两向钉住；
- 顺序固定：**形态声明（模板）→ 自省回写（动作）**，判据钉住不许反。

## 三、R10 后半：事实题默认接入外部校验

### 3.1 问题：挂账原文是「把『本次未校验』从设计边界升级为一次显式选择」

v1.23.10 做了留痕（产物里写明「未接入外部校验 + `--web on`」），但**默认还是没接**。

### 3.2 改法：`--web auto` 时事实型询问自动视同 `on`

新增纯函数 `_web_auto_for_facts(question)`：判据同 `_has_decision_context` ——
无决策语境（事实型）→ `True`。在 `main()` 里接到 `_apply_runtime` 之前：

```python
_web = args.web
if _web == "auto" and _web_auto_for_facts(" ".join(args.question)):
    _web = "on"
    print("   · 事实型询问 + --web auto ⇒ 自动接入外部校验（要关：--web off）")
```

★ **这是本版唯一改变默认行为的改动**，已在 `dgtf_config.yaml` 升级段里
用「★ 对你的影响」明写：想保持旧行为请显式 `--web off`。

## 六、经验教训

1. ★★ **「诊断已经在产物里」≠「诊断已经起作用」。**
   `unsaid_is_escape=true` 这种高置信结论一直躺在 `views.*.self_check` 里，
   却从没变成任何动作。**判断一个机制有没有生效，要看它有没有改变交付物，
   不是看它的结论有没有被算出来。**
2. ★ **把「未做」写进报告的价值，在于它下一轮能直接当清单用。**
   v1.23.10 §五 的「R1 只做了形态声明这一半 / R10 只做留痕与指路」两句，
   两份报告隔几小时就变成了可执行的两条改动 —— 记账不是仪式。
