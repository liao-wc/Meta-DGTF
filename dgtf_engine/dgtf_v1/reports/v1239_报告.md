## 二、改了什么

### 2.1 问题：一个日期问题被渲染成一份「发文流程」

v1.23.7 的真跑产物（`outputs/20261009_093317_新中国的成立时间是什么时候.md`）里，
落地层的「行动清单」写着：

```
- **A1**：核查 9月21、29、30日与10月1日当日的原始文书表述
  - 负责人：党史研究室编研岗
  - 时限：定稿会前2个工作日
  - 验收：出具四节点原文摘录，逐条注出处并签字
  - 回退：原文不可得时只保留10月1日一条，并标注来源缺失
```

这个岗、这个会、这个签发人**都不存在**。根因不在模型 —— 它只是按 decision 模板的
字段结构（`owner_role` / `deadline_hint` / `acceptance` / `fallback`）填了该填的位置。
根因在**分流**：`orientation=auto` 无条件走 decision 模板。

### 2.2 改法：给分流加「题面有没有决策语境」这一维

```python
def render_landing(res: dict) -> str:
    cfg = res.get("_config") or {}
    orientation = str(res.get("orientation") or "auto").strip().lower()
    if orientation == "boundary" or not _action_on(cfg, "landing_decision"):
        return _render_landing_boundary(res)          # 老短路 1、2
    if orientation == "auto" and not _has_decision_context(
            str(res.get("question") or "")):
        return _render_landing_boundary(res)          # ★ v1.23.9 新增
    return _render_landing_decision(res)
```

`_has_decision_context(question)` 是纯函数，命中任一决策语汇（「该不该 / 要不要 /
怎么选 / 方案 / 取舍 / 利弊 / 落地 / 规划 / 风险 / 预算 / 决策 …」）→ `True`。

三条边界，都由探针钉住：

- **不覆盖显式选择**：`--orientation decision` 时即使题面无决策语境，仍走 decision；
- **题面取不到就保守**：空题面、缺 `question` 键 → 走 boundary（不知道题面时不套决策模板）；
- **词表只增不减**：加词只会让更多题回到 decision（= v1.23.8 及以前的行为），
  不会静默把本来走 decision 的题踢出去。

## 三、为什么只做这一条

R1–R10 里，**只有 R2 的收益与「允许真跑」这个条件直接相关**：它的效果是
「产物用哪套模板」，必须**落盘**才看得见，离线最多验到「分流函数返回哪条分支」。

其余几条的排除理由（逐条写在 §五）：
R8 是纯渲染层、可离线验，但会推翻附录「以本段为准」的自我声明，需先改声明；
R1 / R9 是机制级且与 v1.23.4 的 runtime 优先级链耦合；R10 需要联网真打。

★ 本版**只改一处分流**，是为了让一次真跑就能把它验干净 —— 改动面越小，
真跑结论越干净。

## 六、经验教训

1. ★★ **形态错配的根因常在「分流」，不在「模型」。**
   行动清单里那些编出来的岗位，是模型按字段结构填出来的**正确行为** ——
   真正错的是「这道题不该走这套模板」。**先问"谁选的模板"，再问"模型写得对不对"。**

2. ★ **改默认行为要连"不许覆盖用户显式选择"一起断言。**
   `auto` 看题面是本次唯一的行为变更；如果顺手把显式 `--orientation decision`
   也一起改了，用户会发现"我明明指定了却被换掉"。M4 变异体专门钉住这条边界。

3. ★ **"取不到输入"必须有自己的档，不能落到默认分支。**
   缺 `question` 键时若沿用旧逻辑（走 decision），等于**在不知道题面时套决策模板**。
   本版让空题面/缺键都走 boundary，并由探针的两例钉住。

4. ★ **词表类判据要写清「只增不减」的单调方向。**
   这样后人加词时能立刻判断：这只会让行为回到旧版，不会制造新的静默变更。

5. ★★ **改了默认语义，就要连「描述它的文案」一起改。**
   本版把 `auto` 的分流语义改了，但产物里「**取向**：auto（未指定时按 decision）」
   还写着旧话 —— 真跑产物第 19 行与它下面的落地层模板**自相矛盾**。
   这条是**真跑**暴露的（离线探针只量「返回哪套模板」，量不到文案）。
   **通则：语义改动要顺带 grep 一遍它的说明文案（产物行 / 终端提示 / `--help`）。**

6. ★ **「档位名」不等于「实际规模」。**
   用 `--profile economy` 想省成本，但它只改 **token 裁剪**、不改**圈数上限** ——
   实跑反而比 `quality` 那次贵一倍（188 次 / 141.8 万 tokens vs 72 次 / 63.9 万）。
   **用任何「省钱开关」之前，先核它改的是哪个维度、那个维度是不是你要压的。**

7. ★ **清版次标记要逐行扫，不能只看块首。**
   `[v1236]` 判据查的是「**块内任一行**出现版本号」：第一轮清了 `★ v1.23.9：`，
   第二行里的「回到 v1.23.8 及以前」仍被判为批注，**又红一次**（行 14154）。
