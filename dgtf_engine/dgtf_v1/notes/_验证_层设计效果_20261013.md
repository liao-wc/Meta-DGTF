## 二、真正仍成立的问题（逐条：根因 + 影响面）

### P1 · 不可判定「结构覆盖率」口径内部矛盾（值近恒 0）

**现象**：7 份产物里 6 份 `结构覆盖率 0.00`（`已对上 0/3`），仅 1 份 0.60。

**根因（口径层）**：`update_undecidable`（L3776–3792）
```
struct_cov = |{und_aspects 被 structural_amps 命中(overlap≥0.3)}| / |und_aspects|
```
而喂模型的提示词（L5735–5736）明确要求：
> `structural_amps：从 ing 输出里**独立**提炼…**不得直接复述**下方 und_aspects 的原话`

⇒ **一个要求「别和 und_aspects 一致」，另一个用「和 und_aspects 一致的比例」打分。**
两侧口径反着来，读数自然趋 0（`aligned_amps` 那一路因定义为「对齐」而恒 ~100%）。

**影响面（改它要动的地方，别漏）**：
1. 计算：`update_undecidable` L3766–3799（`struct_cov` / `hit_aspects` / `_append_trace`）；
2. 提示词：L5735–5736、L5755、L5793、L5943（`structural_amps` 的定义与 JSON schema）；
3. 渲染：`_und_channel_line` L8300–8333、`_pool_shape` 喂模型的 L9208–9225、md 头部 L781；
4. 判据：`smoke_test.py` `check_v12317_und_coverage_trace` L1248–1268（有 `已对上 6/10` 之类锚点，改口径要同步）；
5. **历史语料**：`outputs/*.packed.json` 里已存的 `struct_coverage_history` 含义会变；
6. 冻结的 `sha` / 校准队列（若引用了该读数）。

**处置选项（需你定）**：
- (a) 改**口径**：把 `struct_cov` 改成「structural_amps 对 und_aspects 的**独立**程度」或直接删除该读数（承认它不构成覆盖率）；
- (b) 改**提示词**：取消「不得复述」约束，让 structural_amps 与 und_aspects 有对齐义务（但这会削弱「独立提炼」的设计意图）；
- (c) 保留读数但**改名 + 标注口径**（`独立度` 而非 `覆盖率`），避免被当成分数排名。
> 我倾向 (a)/(c)：**「独立」与「覆盖」本就互斥，不该共用一个分母。**

### P2 · 停止与圈数上限的匹配（停圈==上限 / 小 cap 直接截断）

**现象**：
- 05:06：修行/研究 cap=4，判据触发但**恰在第 4 圈** ⇒ `实际停圈 == 上限`；
- `20261010_023209`：cap=**1**，四层 1 圈跑完必然「体力耗尽」截断 3 层。

**根因**：这不是判据 bug，是**判据触发点与 cap 的相位关系**——
判据要求 `idle ≥ r_idle_limit` 且 `layer_no ≥ soft_max`，而 cap 由 auto 从历史 p50 给（4/5/6）。
当 auto 给的 cap 偏小（含用户显式 `--rounds 1`）时，判据没有机会跑。

**影响面**：auto 圈数策略（`_AUTO_ROUNDS_BASE`/种子 p50）、停止阈值 auto 项、
产物「停止 / 实际停圈」两行、`_AUTO_STOP_MIN_N` 门槛。**改一处要连带改 auto 的样本与产物渲染。**

### P3 · 清单「后补」已可观测，但未处置

**现象**：`candidates_backfilled(sc:5)`、`unsaid_overused(3)` 高频出现。

**性质**：引擎已把「候选后补 / 『此处未生』超阈值」做成**质量线索**（这是 v1.23.10+ 的成果），
但**只标记不处置**。是否要压回（阈值、或改去重器）需要单独定。

## 三、属「有意设计」的项（不是 bug，但需你确认是否要改设计）

### D1 · 条件 1 对修行层（0）生效
- 这是 v1.23.17 的**有意改动**，且 `smoke_test.py` 有守卫在**要求**它对四层都生效（L1177–1181）。
- 与「修行层不追求收敛」这条设计红线**确实冲突**。
- **要处理就得改设计 + 同步改判据**（把守卫从「四层通用」改成「0 层豁免 + negative control」），
  不是修 bug。**且修行层的复述半句在真跑里常常「未计算」**（`_upstream_texts` 为空时不算，
  L4531–4552；产物两层的自省都写「未计算」）⇒ 实际上常只剩「自省点名」半句可能触发。
- **需你决策**：恢复 0 层豁免，还是正式承认修行层也可早停（改红线文档）。

### D2 · 「这一次我是谁」= 各层 view 拼接
- `accumulate_self`（L3580）按设计把每层 `view.manifest` 拼进 self 通道，
  `keep = self_layers(4)`。产物 L806 就是它。
- 上一轮报告把它当成「复述守卫失效」——**归因错了**：复述守卫（`_detect_ing_rephrase`）
  量的是**层内跨圈复述**，不是这个跨节渲染。
- 但 v1.23.7 审计的 R6 认为该节**零新增信息**。它与「自省是另一个视角」的红线是否冲突，
  是设计判断。CHANGELOG 里**没有**采纳 R6 的记录。
- **需你决策**：是否要给 self 通道加一层「合成」（而不只是拼接）。
