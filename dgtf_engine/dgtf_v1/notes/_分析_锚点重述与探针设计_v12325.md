## 一、锚点重述

### 1.1 touched 证据链：健康 + 判据存在但零触发

| 读数 | 值 |
|---|---|
| 观测点（层×产物） | 14 |
| touched 总条数 | 50 |
| touched 为空的层 | **0 / 14** |
| anchor 字数 | 15 ~ 70（均值约 47） |
| anchor 含指示代词（它/这/那/此） | 8 / 14 |

提示词里写的是：
> `★ touched 是重述真的发生了的证据。如果 touched 空着，说明这次只是在换说法。`

实测 **从未空过**。这有两种解释，**必须分开说**：
- **好的解释**：重述确实每次都在做（与 §2.1「探针不复述」互证，倾向这个）；
- **要警惕的解释**：模型学会了「永远填几条 touched 满足格式」，字段变成**必填项**而非**证据位**。

**判据缺口**：这条提示词**没有对应的机器判据**（`smoke_test.py` 里搜不到
「touched 为空 ⇒ 报警」的检查）。也就是说，**它是一条只写在提示词里的红线**。

> 参见 v1.23.25 的经验：`polarity` 也是「100% 填充 ⇒ 零判别力」。同一个病，
> 当时靠「测填充率」抓出来。**touched 需要一个填充率/多样性的判据**，而不是只靠提示词。

### 1.2 touched × untouched 互相踩：12/14 —— 但先别信

用 `_overlap_coef >= 0.3` 判「touched 项与 untouched 项重合」，14 层里 **12 层有踩**，
最多的一层 7 对。表面结论会是「重述自相矛盾（同一方面既说已触及又说未触及）」。

**但逐例拆解后，绝大多数是尺子误报。** 看三例：

| 对 | overlap | 真语义 | 判定 |
|---|---|---|---|
| touched「指向历史事实」× untouched「需区分"新中国成立"与"中央人民政府成立"…」 | 0.50 | 「已触及：它是历史事实」vs「未触及：两个"成立"定义的区别」—— **方向相反** | ❌ 误报 |
| touched「AI时代已被指向具体接触面」× untouched「AI时代具体社会形态尚未发生」 | 0.60 | 共享「AI时代」这个**名词**，断言相反 | ❌ 误报 |
| touched「来源本身被追问」× untouched「来源指形成还是命名」 | 0.33 | 共享「来源」，一个是「被追问了」，一个是「分形成/命名两路」 | ❌ 误报 |

**共同形态**：`touched = 「X 是/已被 A」`，`untouched = 「X 是/还没 B」`。
两者共享主语 X，但断言相反 —— **这正是「触及」与「未触及」该有的样子**，
而不是错误。

### 1.3 根因：`_overlap_coef` 对短句系统性高估（真问题）

```
_overlap_coef(a, b) = |kw(a) ∩ kw(b)| / min(|kw(a)|, |kw(b)|)
```

touched / untouched 的短语**很短**（2-3 个关键词，如「指向历史事实」→ `{指向, 历史事实}`）。
于是：

| 例 | A 关键词数 | B 关键词数 | 交集 | coefficient |
|---|---|---|---|---|
| 「指向历史事实」vs 长句 | 2 | 13 | `{指向}` | **0.500** |
| 「AI时代已被指向具体接触面」vs「AI时代具体社会形态尚未发生」 | 5 | 6 | `{AI, 具体, 时代}` | **0.600** |
| 「来源本身被追问」vs「来源指形成还是命名」 | 3 | 4 | `{来源}` | **0.333** |

**分母取 `min(|A|,|B|)` ⇒ 短句的分母极小 ⇒ 共享 1 个词就被除满。**
对长文本（句子 vs 句子）这个尺子是稳的（v1.23.25 里 `und_aspects` 与
`structural_amps` 的对照 4/5 份 max ≤ 0.17 就是长文本），但对**短语**它会稳定高估。

★ **这条比「锚点重述有问题」重要得多** —— 因为 `_overlap_coef` 是**全局**用的尺子，
`structural_amps` / `und_aspects` / 本版新增的「结构覆盖率」全用它。
**短期影响**：只在「短语 vs 短语」的比对里失真（touched/untouched 恰是这种）。
**要查的**：还有哪些地方在拿**短句**互比 —— 那些地方的读数都偏高。

## 二、探针

### 2.1 探针没有在复述 ✅

| 读数 | 值 |
|---|---|
| 探针总数 | 37（14 层，均 2.6 条，符合「1-3 个」） |
| 探针 question 与 residue（本圈 amps+threads）相似 **≥0.6** | **0 / 34** |
| 最大相似度 | 0.46（多数 ≤0.36） |

提示词要求「探针必须推进，不能重复上面已有的内容」—— **这条被遵守了**。
（对比 v1.23.25 里 `ing` 复述率会到 50%+，探针这一侧干净得多。）

### 2.2 `expected_gain`：门槛冒充评分 🔴

```
门槛（代码 L6567）：if ... or gain < min_gain: continue      # min_gain 默认 0.3
```

37 条实测分布：

```
gain=0.50 : ######### (9)
gain=0.55 : ###### (6)
gain=0.60 : ########## (10)
gain=0.64~0.68 : #### (4)
gain=0.70 : ###### (6)
gain=0.72~0.75 : ## (2)
          min=0.50  max=0.75  均值=0.597
```

**如果它是「增益评分」**，应该看到低分（如实说 0.2「这条只是确认」）与高分（0.9「这条能破局」）的两端。
**实测两端全空，95% 挤在 [0.5,0.7]** —— 模型学到的是「**填中间稳过 0.3 门槛**」。

**这与 v1.23.25 刚修掉的 `polarity` 100% 填充是同一类病**：字段有形式、无信息。
差别在于 `polarity` 是**代码填充**（所以好修），`expected_gain` 是**模型自报的数值**（更难）。

> ★ 而且注意：`gain` 与 `select_probe_focus` 的**选取无关** ——
> 后者用 `_amp_weighted_score` / 关键词重合 / 新鲜度三步 take（L3619-3661），
> **从不读 `expected_gain`**。所以这个字段在整条链上**只起门槛作用**。

### 2.3 「推不动就返回空」：从未触发 ⚠️

| 读数 | 值 |
|---|---|
| 空探针的层 | **0 / 14** |
| 代码分支 | `if not residue and not subs_text and not open_def: return []`（L6461） |

提示词写「推不动就让 probes 返回空数组——**宁可空，不要凑数**」，
**实测一次都没空**。两种可能：① 材料确实每次都有东西可推（14 层都这样，可能性低）；
② **模型倾向于凑满 1-3 条**（`probe_return_empty` 是个会被记的 flag ⇒ 模型避开它）。

★ **这里有一个方向性问题**：`_quality_check` 把「有 &/线头但 probes 空」记为
`probe_return_empty`（L7463-7468）。也就是说，**代码在惩罚「空探针」**，
而**提示词在鼓励「宁可空」**。**两者方向相反** —— 这正是「方向错的断言比没断言更危险」的实例：
- 提示词：「推不动就空着」；
- 判据：空着 ⇒ flag ⇒ 可能进 quality_verdict ⇒ 影响停止判定。

于是模型**理性地选择凑数**。这也解释了 §2.2 的 `gain` 全填中间值。

### 2.4 `covers` 兑现率：45%（上界）

| 读数 | 值 |
|---|---|
| covers 声明总数 | 73 |
| 「该 untouched 项在产物里被后续 amortized 命中」 | 33 |
| **兑现率** | **45%（33/73）** |

**★ 这个数必须报为上界，有两个向上污染：**
1. 我用的是**末态** `view.amps/threads`（跨圈合并后），不是「**下一圈**」的增量 ⇒ 命中率偏高；
2. 尺子对短语高估（§1.3）⇒ overlap≥0.3 更容易满足 ⇒ 命中率偏高。

**所以真实的「探针指哪打哪」率 **≤45%**。** 有跨度（不是 0 也不是 1），说明
covers 确实在起作用，但**大约一半的声明没有落到产物上**。

## 三、红线核查：判据守住了吗

### 3.1 `probe_no_target_covered`：只拦形式，拦不住乱指 🔴

`_quality_check` 的判据（L7470-7500）核心逻辑：

```python
m = re.match(r"^T?(\d+)$", c)
if m:
    idx = int(m.group(1)) - 1
    if 0 <= idx < len(untouched_items):
        has_touch = True        # ★ 只要编号在范围内就通过
        break
```

**负对照实测**（直接驱动 `_quality_check`）：

| 用例 | 结果 |
|---|---|
| **A 完全乱指**（`covers:["T1"]`，语义与 T1 毫无关系） | **不报** ❌ |
| B 空 covers | 报 `probe_no_target_covered` ✓ |
| C 越界 `T99` | 报 ✓ |
| D 显式不碰 `[]` | 报 ✓ |
| E 指到有效项 `T2` | 不报 ✓ |

**判据的真实强度 = 「编号是否在 [1, N] 内」**，与「那条未触及项是否真被碰」无关。
模型只要**随便填一个范围内的编号**就能通过 —— **`covers` 因此退化为形式填写**。

这与 §2.4 的 45% 兑现率**互相印证**：如果 covers 有真实约束力，兑现率不该只有 45%。

### 3.2 `link`：红线缺判据 🔴

提示词（L7057 / L6475）：
> 「探针必须能把探索带回原始问题」「每个探针必须给出 link（怎么带回去）」

代码（L6567）：
```python
if not q or len(q) < 6 or not link or gain < min_gain: continue
```
**只查 `not link`（非空）** —— 不查 link 是否真的和 anchor/原始问题有关系。
`link` 字段**没有任何语义判据**，且（见 §2.2）`select_probe_focus` 也不读它。

**结论**：这是本项目最看重的一条红线（「必须指向原始问题」），
**目前只靠提示词 + 一个非空检查**。按项目的纪律（「判据落在行为上」），**这是缺判据的**。

## 四、建议（按「判据驱动」的优先级）

### P1 · 修 `_overlap_coef` 在短句上的高估（影响面最大）
它不是只影响锚点 —— 它是**全局尺子**。至少：
- 阈值按**长度分层**（短句用更高阈值，或改用 `_similar` 的字符级相似做二次确认）；
- 或给短句比对加**最小关键词数**（`min(|A|,|B|) >= 3` 才算），否则返回 0。
**先量**：全仓库搜「拿短句互比 `_overlap_coef`」的点，报清单再动。

### P2 · `expected_gain` 要么改成真评分，要么删掉门槛语义
现在它「有形式无信息」且 `select_probe_focus` 不读它。
- **方案 A（推荐先做）**：加判据 —— 若某层的 gain **全落在 [0.45,0.75]** 则记 flag
  （证明它是敷衍区）；
- **方案 B**：把 `gain` 从前 3 条里**排序取用**（进了 select 才叫评分），否则它只是装饰。

### P3 · `probe_no_target_covered` 升级为语义判据
现在的检查只判「编号在范围内」。应加：**该 untouched 项与探针 question 的语义关联**
（哪怕用 `_similar ≥ 0.3` 这种弱关联），否则**乱指与真指无法区分**（§3.1 负对照已证）。

### P4 · 解决「空探针」的方向矛盾
提示词说「宁可空」，判据 `probe_return_empty` 却在罚空。
**二者必须统一**。要么去掉 flag，要么把提示词改成「尽量给出，但要真推得动」。
**当前状态是：模型在两种相反信号下选择了凑数**（§2.3）。

### P5 · `link` 加判据
最低限度：`link` 与 `anchor` 的关键词重合 ≥ 某阈值，否则记 flag。
（否则「必须指向原始问题」是纯提示词，无机器保证。）

## 五、方法与局限（如实写）

**方法**
- 数据：`outputs/*.packed.json` 最近 8 份（2026-10-09 ~ 10-13），14 个层×产物观测点；
- 尺子：引擎本体 `_similar` / `_overlap_coef` / `_sim_ratio`（不是自造）；
- 判据强度：**用负对照直接驱动 `_quality_check`**（A~E 五例），不靠读代码猜。

**局限（必须知道）**
1. **8 份产物、14 个观测点** —— 样本小，且集中在近期（v1.23.1x~v1.23.25 期间跑出来的）。
   口径一致，但**不能外推到全部 306 份**。
2. `covers` 兑现率用**末态**算 ⇒ **报上界**。
3. `_overlap_coef` 的短句高估**同时污染**了我自己的读数（§1.2 的「12/14 踩」就是被它污染的）
   ⇒ 所以我**逐例拆解**而不是直接采信 12/14。
4. `expected_gain` 的「门槛 vs 评分」判断来自**分布形态 + 代码门（L6567）**，
   不是来自「问模型为什么这么填」—— 那是另一个实验（真跑 + 干预）。
5. 锚点重述的 touched **没有跨圈追踪**（packed 只存末态），所以
   「第 N 圈的 touched 是否在第 N+1 圈被兑现」**这份数据回答不了** —— 需要逐圈留痕或真跑。

**未做**
- 真跑（干预 `expected_gain` 提示词，看分布是否张开）；
- `_overlap_coef` 在**全仓库**的使用点盘点（P1 的「先量」）；
- 「touched 空率」的历史趋势（要 `_archive/` 里的旧产物）。
