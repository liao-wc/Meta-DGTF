## 1. 定位 P9：真跑脚本的「第二份全开清单」

**读代码**：引擎 `_ALL_ON_ITEMS` 写的是 `("api.thinking.default", "enabled", …)`，
而 `_run_full_v12333.py` 第 101 行是 `_set("api.thinking", True, "思考档")` ——
**脚本把整段 mapping 覆盖成了 bool**。

**根因定性**：不是「写错一个值」，是**同一语义在两处定义**（引擎一份、脚本一份）。
凡两处定义必漂移。修法必须是**消掉一份**，而不是把两份改一致。

**修①（脚本）**：删掉 `_set(...)` 手写清单，改为
```python
cfg = mod.load_config(...)          # 引擎已在最外层应用 all_on
if not cfg.get("all_on"):
    cfg, _ao = mod._apply_all_on(dict(cfg, all_on=True))   # 仍走引擎函数
for p, v, w in mod._ALL_ON_ITEMS:   # 只**回读**实际生效值并留痕
    ...
```
**修②（引擎，防御）**：`LLM.__init__` 加形状守卫。★ 第一版把守卫写在
`self.thinking_default = _th.get(...)` **之后** ⇒ 第一处 `.get` 照样先炸（实测复现）。
挪到**紧贴取值之后、首个 `.get` 之前**才生效。

**验证**：
- 干净基线：`load_config(出厂)` → `all_on=True`，`api.thinking` 是 dict，10 项全开逐项 ✓。
- 形状守卫两向：`thinking=True / "on" / 123` ⇒ 不崩（降级+告警）；合法 dict ⇒ 字段不被吞。
- 补冒烟判据（形状守卫两向）+ 变异体 **M25**（拆守卫 ⇒ 判红）。

## 3. 定位 P10：`run()` 从不盖 run_id ⇒ EML 从不学习真实跑

**追查**：全引擎 grep `packed["id"] =` ⇒ **只有我这一轮新加的一处**。也就是说
**修复前，CLI 与 app 真跑从未写过 episode**（库内 5 条全是测试/种子写的）。

**根因**：`run_id` 原本到 `save_result` 才以**文件名**形式出现，而 episode 是在
`run()` 内 `_eml_finish` 就写的 ⇒ 永远拿到空串 ⇒ 撞「无 id 一律不写库」闸
（该闸本意是**拦测试**，却连真跑一起拦了）。

**修（三处，时序是关键）**：
1. `run(..., run_id="")` 显式收 id；在 `_eml_finish` **之前**盖 `packed["id"]`；
2. CLI `main()` 传 `run_id=datetime.now().strftime(...)`；
3. 交互 `_interactive_run()` 同上。
不给 id ⇒ 仍匿名跳过 ⇒ **测试隔离不破**。

**验证**：PROBE2 复跑 ⇒ episodes **5 → 6**，新条目 `run_id=PROBE2_...`、
`duty={"0":0.0,"1":0.0}`、`used_ids=[L0001]`（跨跑学习生效）。
补判据（⑦ 记账）+ 变异体 **M31**。

## 5. 新增机制：AutoTune（走向「确定最优模式/层数/圈数」）

用户要求「自动设计测试与真跑，让元DGTF 自我学习迭代，确定最优模式/层数/圈数/运行时
动态调整」。已有 EML（micro/macro 反思）+ bandit（圈数三档）之外，新增**跨跑离线调优器**：

- `autotune_score`：episode → 读数向量（质量三级回落；缺 ⇒ `None` **不是 0**）。
- `autotune_dominates` / `autotune_pareto`：多目标（质量↑/成本↓）帕累托前沿，
  **不做加权标量化**（给成本拍假币汇率 = 凭空打分）。
- `autotune_sh_rounds`：Successive-Halving 档位表（预算受限粗筛）。
- `autotune_rank` / `autotune_recommend`：分层集与模式、推**建议默认**
  （层集 = 同质量 τ 内取成本最低 = 帕累托膝盖；圈数 = 未截断中位 + 截断层 +1）。
- `autotune_run`：读 episode → 出建议 → **只写 `dgtf_autotune.json`**（建议与执行分开）。

驱动 `_autotune_v12333.py`：`report`（零 API）/ `sweep`（跑设计空间 → 累积 episode → 出建议）。

**验证**：合成数据推 `route=['0','1']`（砍 both/all）、圈数截断层 +1；空/无质量 ⇒
`ok=False` 不瞎猜；补判据 + 变异体 **M26~M30**。

★ **M27 第一次假绿**：夹具里「最高质量」恰好 = 「膝盖」⇒ 变异体（恒取质量第一行）
不产生差异。**改夹具为「最高质量 = 最贵」** 后才判红 —— 典型假绿，幸由变异体自身逮到。

### 7.1 中途：用户允许 3 并发 ⇒ 先解决「并发正确性」

看到第一条真跑数据（`P1_Q1`：`duty={0:0.0, 1:0.0}`、391k tok）后，用户指示
「可以 3 并发跑」。**并发前必须先解决正确性问题**：

- `playbook.jsonl` 的升级/遗忘/macro 是**整表重写**（读-改-写），不是原子 append；
- `bandit.json` 也是读-改-写；
- 两进程同时改 ⇒ 互相覆盖（丢条目 / 写坏半行）。

**修**：新增 `eml_lock`（`O_CREAT|O_EXCL` 跨进程自旋锁 + **陈旧锁回收**），
用于 `_eml_finish` 写库段（`finally` 释放，异常不漏放）与 `_save_bandit`
（短超时，拿不到就跳过 —— bandit 是**状态不是账本**）。
`sweep` 改 `ThreadPoolExecutor(max_workers=3)` + **幂等跳过**已完成项
（`run_id` 前缀正则匹配，★ 不能按 `_2` 切：`P1_2L` 里也有 `_2`）。

**验证**：4 线程抢锁 ⇒ 并发进入数恒 1；退出后锁文件清除；把时间戳拨回 5000 秒
⇒ 陈旧锁被回收（崩了不永久死锁）。补判据 + 变异体 **M32**（去掉 `O_EXCL` ⇒ 判红）。

## 8. 通则（本轮沉淀）

1. **同一语义两处定义必漂移** —— 修法是**消掉一份**，不是「把两份改一致」。
2. **默认关的能力 = 判据基线；默认开的能力 = 真跑才暴露**：全开键逼出了 P9/P10
   两个**沉默失效**（一个炸、一个静默丢数据）。
3. **守卫要放在「第一次使用之前」** —— 形状守卫放晚一格就白加。
4. **`run()` 的记账时序**：id 必须在 `_eml_finish` **之前**盖 —— 晚盖 = 整跑白跑。
5. **夹具设计要保证「变异体能产生差异」** —— 否则假绿（M27）。
6. **区分「没有」与「是 0」** —— 质量缺读数回 `None` 而非 `0`，否则「没测」被当
   「测出来很差」，把好配置误淘汰。
