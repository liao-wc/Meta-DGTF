## A. 输出质量与字数（用户明确点名）

### A1 ★★ 产物正文存在**整段冗余**（`self_text` 二次渲染）
- 产物同时有两处渲染同一个东西：
  1. `## 附：逐层明细` → `### <层>` 下 `**view**：<manifest 全文>`；
  2. `## 这一次我是谁` → `[<层>] <manifest[:900]>`。
- 实测（`20261013_155915`）：`self_text = ["[修行层] " + manifest_0, "[研究层] " + manifest_1]`
  与 `views.*.manifest` **逐字同源**（`accumulate_self` 就是 `view.manifest[:chars]`）。
  ⇒ 后一处是**前一处的前 900 字截断拷贝**，纯重复。
- 规模：14 份 packed 里 `self_text` 合计 1206~9646 字符；最大一份占产物 ~6%，
  重复的**行**约占产物 15~35%（配合 `## 这一次我是谁` 标题与空行）。
- **关键事实**：`self.self_text` **不是任何 prompt 的输入** —— 引擎内部走
  `_self_snapshot_for(entry)` 读 `_self_text_by_entry`（分层累积），
  `self.self_text` 只被 `_pack_result` 打包 + `save_result` 渲染。
  ⇒ 它**只服务展示**，而展示的内容已在别处完整出现过。

### A2 产物行数量级
- 14 份 packed 对应的 md：676~1798 行 / 52~170 KB。
- 中位约 730 行；`self_text` 冗余段在最大的一份里占 ~250 行。
- 结论：**格式本身合理**（头部仪表 + 落地层 + 逐层明细 + 池），
  问题集中在 A1 的重复段。

## B. 模式设计（用户点名「各模式优势 / 能否合并单一最优」）

### B1 ★★ 九种并行模式中，**六种在近 80 份产物里从未被选中**
- 全量 309 份产物分布：严格串行 127 / A 87 / B 50 / G 20 / H 12 / F 5 / C 3 / E 3 / D 2。
- **最近 80 份**：严格串行 71 / B 6 / C 1 / **A、D、E、F、G、H 各 0**。
- 触发「自动决策」时 `mode` 项多为 `llm`（13 份 packed 里 6 份），
  而 LLM 决策结果几乎总是 `serial`（`_PARALLEL_CONF_MIN` 门槛 + 「拿不准 → serial」提示词）。
- ⇒ 模式选择器**花了一次 LLM 调用**，产出的却是「退回 serial」。
  9 种模式的表达能力实际只用到 serial / B / C。

### B2 模式的真实差异是**时序**，不是**结果质量**
- `_MODE_GRAPH` 里 D/E/F/G/H 都是「谁先起跑、谁等谁」的排班差异；
  底层 layer 执行体（`_run_layer` 与 `_b_*`）是同一套。
- 没有证据表明 D~H 比 serial 产出更好的**答案**（答案由层内 LLM 产出，
  与时序无关；时序只影响「下游读到上游的第几圈 view」）。

## C. 机制 / 接线（走真实入口查「能力是否落地」）

### C1 ★★ `touch_rate` **结构性恒 0**（口径错位，真 bug）
- `View.touch_rate`：`round_log` 非空就按圈数 `anchor_touched_n > 0`，
  否则退回 `1.0 if anchor_touched else 0.0`。
- 实测（`20261013_155915`，entry 1）：`anchor_touched` **3 条**、
  `aspect_units` **12 条**，而 `touch_rate = 0.0`。
- 根因：`round_log` **有 1 条**（truthy）⇒ 进逐圈分支；
  但该条**没有 `anchor_touched_n` 键**（keys = round/role/new_amps/…）
  ⇒ `.get(...,0)` 恒 0 ⇒ `0/1 = 0.0`。**兜底分支永远到不了**。
- 同类实例：`aspect_carry_rate` 走 `_carried_aspect_ids`（恒 None）
  → 回落 `_layer_und_channel`（空 dict）→ 0.0。**两处同名 bug**。
- 判别：这是「**有值但零信息量**」的第 4 种变体 —— **有正确源数据
  （anchor_touched=3），却因读错字段而报 0**。

### C2 `DEFAULT_CONFIG` 缩进破损（19279~19280 行）
- `api.thinking.stages` 里两行（`adjudicate_sub_tristate_multi` /
  `anchor_crosscheck`）缩进是 **4 空格**，兄弟键都是 **16 空格**。
- 语法合法（dict 不关心缩进）⇒ 任何判据都看不见；纯工程整洁问题。

### C3 `self_text` 合并函数的多余读点（与 A1 同源）
- `_merge_self_text()` 在 5 处被调用，但 `self.self_text` 无人消费。
